# FleetDoctrine — 3D 공간 명령·뷰포트·함대 자세 개선 명세

> **문서 유형:** 기존 `fleet_auto_battle_design_spec.md` v2.0에 대한 **변경·보강 명세**  
> **개정:** v2.1 / 2026-11-23  
> **사용 목적:** Codex 구현 및 회귀 검증 기준  
> **범위:** 전술 명령의 공간 입력, 격자 좌표, 함대·개별 함선의 자세, UI 가시성, 관련 CG 구현 책임  
> **우선순위:** 본 문서의 변경 조항은 해당 주제에 한하여 v2.0의 충돌하는 이전 설명보다 우선한다. 그 밖의 정책 2종+5종, 대형, 전투 루프와 무장 규칙은 유지한다.

## 0. 변경 관리 규칙

- **[확정]** 사용자가 제시한 기획 의도와 직접 수정한 사항.
- **[해석]** 해당 의도를 기술적으로 모순 없이 해석한 결과. 기능상 의미가 달라진다면 사용자 확인 필요.
- **[권장]** Codex가 구현을 진행할 수 있도록 제시한 기본 방식. 사용자의 확정사항은 아님.
- **[미결]** 사용자 판단, 프로토타입 검증 또는 추가 논의가 필요한 선택.
- **[임시값]** 테스트 전용 예시 수치. 반드시 설정값으로 관리.

**핵심 구분:** `명령 좌표의 이산화` ≠ `물체 위치의 양자화`; `대기 자세 수평 정렬` ≠ `전투 중 회전 금지`; `함대 기준 자세` ≠ `개별 함선의 선체 자세`.

## 1. 변경 목적과 범위

### 1.1. 목적 [확정]

1. 3D 목표점을 2D 화면에서 지정하기 쉽게 만든다.
2. 이동 명령의 좌표를 눈으로 추적·비교할 수 있는 **3D 격자 교차점**으로 통일한다.
3. 전투 중 3차원 자세 기동을 보존하면서, **이동 완료 후 대기하는 함대**는 읽기 쉬운 공통 수평 기준 자세로 복귀시킨다.
4. 처음부터 조작은 단순하게 유지하고 숙련도 차이는 위치, 진형, 고도, 무장 사각 등의 판단에서 생기도록 한다.

### 1.2. 변경하지 않는 사항 [확정]

- 실제 공간은 완전한 **X/Y/Z 3D**이다. Y를 층 또는 별개 전투 맵으로 축소하지 않는다.
- 이동 명령 `MOVE`, `PATROL`, 교전 대응 `OPPORTUNISTIC_FIRE`, `STANDOFF`, `BREAKTHROUGH`, `ENCIRCLE`, `POINT_DEFENSE`의 목적과 우선순위는 유지한다.
- 각 명령·대응에 대응하는 대형을 자동 적용한다. 독립적인 세 번째 `대형 선택` 주 명령을 만들지 않는다.
- 함선은 대형 슬롯을 따르고, 포탑은 독립 조준하며, 전방 고정식 무장은 실제 선체 방향과 무장별 사격각에 따른다.
- 자동 전투 시간 종료 뒤 준비 단계로 돌아올 때 실시간 시뮬레이션의 함선 위치, 자세, HP, 포탄 및 대형 전환 상태를 보존한다.

## 2. 공간 표현: 격자 교차점은 명령 좌표다

### 2.1. 3차원 격자 교차점 [확정]

플레이어가 지정하는 **목적지, 순찰 경유점, 거점 방어 위치**는 정수 격자 인덱스 `(ix, iy, iz)`가 나타내는 **교차점**으로 제한한다. 격자 칸의 중심이 아니라 **격자선이 만나는 지점**을 목표로 한다.

- **[권장]** 월드 업은 `+Y`, 수평 지도는 `XZ`이다. 격자 원점 `O=(ox,oy,oz)`, 간격 `h>0`인 경우:

  ```text
  worldPosition(grid) = O + (ix*h, iy*h, iz*h)
  nearestGridIndex(world) = round((world - O) / h)  // 축별
  ```

- **[권장]** 격자 간격은 월드 단위와 무장 사거리에 따라 하나의 `gridSpacing` 설정값으로 관리한다. 축마다 다른 간격은 나중에 필요성을 입증하면 도입한다.
- **[권장]** 명령 데이터에는 `Vec3` 부동소수점 좌표만 저장하기보다 **정수 인덱스 `GridPoint3`**를 보존한다. 렌더링/AI 실행 전에 월드 좌표로 변환한다.
- **[권장]** 전장 경계 밖의 교차점, 접근 불가능하다고 정의된 교차점은 선택할 수 없도록 표시한다. 어떤 점이 접근 가능한지는 전장 규칙에 따라 결정하며 현재 기획에서 확정되지 않았다.
- 음수 인덱스를 허용한다. 원점을 양수 공간의 한 귀퉁이로 강제하지 않는다.

### 2.2. 실제 시뮬레이션은 연속 공간 [해석/권장]

| 대상 | 격자에 스냅 | 이유 |
|---|---|---|
| 사용자 지정 `MOVE.destination` | **예** | 목적지 선택의 일관성 |
| 사용자 지정 `PATROL.waypoints` | **예** | 순찰 경로의 가독성 |
| 사용자 지정 `POINT_DEFENSE.defenseAnchor` | **예** | 고정 방어 거점 명확화 |
| 함대 기준점의 **실제 위치** | **아니오** | 유연하고 연속적인 이동 |
| 개별 함선 위치와 대형 슬롯 위치 | **아니오** | 슬롯 유지, 충돌 회피, 입체 대형 |
| 자율 교전 중 대치·관통·포위 목표 위치 | **아니오** | 적 상대 위치에 따른 연속적 전술 기동 |
| 포탄, 충돌 지점, 포탑 조준점 | **아니오** | 연속 공간상의 판정 |

**금지:** 목표점의 격자화만으로 함선을 매 틱 격자 교차점으로 순간이동시키거나, 상대 함대 위치를 격자 단위로 양자화하지 않는다. 격자를 **경로 탐색 셀이나 충돌 자료구조**와 혼동하지 않는다. 3D 공간 해싱을 나중에 도입하더라도 명령 격자와 자료구조 셀 크기는 별도로 결정한다.

### 2.3. 기존 명령과 데이터 호환 [권장]

- `MOVE.destination: Vec3` → `MOVE.destination: GridPoint3`.
- `PATROL.waypoints: Vec3[]` → `PATROL.waypoints: GridPoint3[]`.
- `POINT_DEFENSE.defenseAnchor?: Vec3` → `GridPoint3` (미지정 기본값 문제는 기존 명세를 따른다. 자동 도출된 실제 좌표를 강제로 사용자 입력 점인 것처럼 표시하지 않는다).
- 과거 저장 데이터가 있다면 임의 부동소수 좌표를 조용히 소실시키지 않는다. 마이그레이션 여부·절차를 명시하고, 격자 스냅이 일어날 때는 경고 또는 로그를 남긴다.
- 내부 AI 및 렌더 시스템은 `gridToWorld`를 통해 얻은 월드 좌표를 사용한다.

## 3. 단계별 3D 위치 입력 UI

### 3.1. 정규 입력 절차 [확정]

**위치 입력 모드 진입 → XZ 평면에서 X,Z 지정 → YZ 또는 XY 평면으로 자동 전환 → Y 지정 → 3D 목표점 등록.**

두 번째 화면이 `ZX`라면 첫 화면 `XZ`와 동일한 평면이므로 **Y를 선택할 수 없다**. 따라서 두 번째 화면은 반드시 **`YZ` 또는 `XY`**여야 한다.

**[권장 기본]** 두 번째 화면은 `YZ` 직교 뷰를 사용한다. `XY`로 대체하는 것도 의미상 동등하다. 사용자가 지정하지 않은 선택이므로 어느 쪽을 확정 규칙으로 간주하지 않는다.

### 3.2. 입력 상태 머신 [권장]

```text
NONE
  └─ [목적지 / 경유점 / 거점 지정 시작] → PICK_XZ
PICK_XZ
  ├─ XZ 교차점 클릭 → (ix, iz) 임시 고정 → PICK_Y
  └─ 취소 → NONE (기존 명령 유지)
PICK_Y
  ├─ YZ 또는 XY 뷰에서 높이 클릭 → iy 결정 → COMMIT
  ├─ 뒤로 → PICK_XZ
  └─ 취소 → NONE (기존 명령 유지)
COMMIT
  └─ (ix, iy, iz)를 대상 명령에 반영 → 기존 카메라/뷰 상태 복귀 → NONE
```

- **[확정]** 위치 선택 시작 시 화면의 **주 작업 영역**을 XZ 직교 화면으로 자동 변경한다. 수평 위치를 선택하면 높이를 고르는 직교 화면으로 자동 변경한다.
- **[권장]** 자동 전환 전의 자유 카메라 위치·회전·줌을 저장하고 완료/취소 후 복원한다. 뷰포트 보조 창 자체는 유지 가능하나, 주 작업 영역이 어느 평면을 편집하는지 분명해야 한다.
- **[권장]** 전투 실행 중에는 이 명령 편집 UI가 자동 발동하지 않는다. 사용자 입력은 관람·선택 용도로 유지한다.
- **[확정에 따른 해석]** 첫 단계에서 확정한 `ix, iz`는 두 번째 단계에서 변경되지 않는다. 두 번째 화면에서 마우스의 **수직 위치로 Y만 선택**한다. 다른 축의 움직임은 무시하거나 고정 축 안내선에 투영한다.
- **[권장]** 두 번째 클릭으로 곧바로 좌표를 확정한다. 별도 필수 확인 버튼을 늘리지 않는다. `ESC=취소`, `뒤로=첫 단계 복귀`를 지원한다.
- **[권장]** 선택한 교차점 하이라이트, 현재 인덱스 `(ix,iy,iz)`, 월드 좌표, 각 축 화살표, 기존 위치~목표 경로의 미리보기를 표시한다.
- 순찰은 경유점 하나마다 동일한 두 단계 입력을 재사용하고, 경유점 목록 및 순서를 별도로 관리한다.

### 3.3. 화면 좌표 → 격자 좌표 [권장 / W09 CG 구현 연결]

1. 입력이 발생한 **뷰포트 영역**을 식별한다(전체 창 좌표와 뷰포트 로컬 픽셀 좌표 구분).
2. 뷰포트 내부 픽셀을 NDC에 매핑한다.
3. 해당 뷰의 투영·뷰 행렬 역행렬로 월드 광선을 만들거나, 직교 카메라 화면 축을 직접 월드 축에 대응시킨다.
4. XZ 화면에서는 화면 점을 `Y = 임의의 기준 높이`인 가상 평면에 투영하고 X/Z만 읽어 **가장 가까운 격자 교차점**을 선택한다. Y 값은 이 단계에서 확정하지 않는다.
5. YZ 화면에서는 기존 Z 인덱스에 대응하는 세로 안내선을 그려 Y를 읽고 정수 높이로 스냅한다. X는 첫 단계 값으로 잠근다. XY 화면을 쓴다면 X 인덱스를 고정하고 Y만 읽는다.
6. 명령을 완전히 확정하기 전까지 **실제 시뮬레이션 명령 객체를 변경하지 않는다**. `draft` 상태로 표시한다.

### 3.4. 가시성과 오류 회복 [권장]

- 현재 모드 `수평 위치 선택 (XZ)` / `높이 선택 (YZ)`를 화면에 명시한다.
- 축 명칭과 눈금 표시를 고정해 카메라 전환 시 공간 인식이 뒤집히지 않도록 한다.
- 다른 고도에 있는 함대가 XZ 뷰에서 겹치면 선택 함대의 Y좌표와 선택된 층의 안내선을 표시한다.
- 확대/축소하더라도 그리드가 픽셀 격자로 바뀌지 않고 동일한 **월드 좌표 격자**로 유지되어야 한다.
- 마우스 위치가 격자 교차점 사이에 있을 때 가장 가까운 유효점을 예고한다.
- 뷰포트 리사이즈, 취소, 입력 중 함대 선택 변경에 의한 고아 `draft`가 남지 않도록 한다.

## 4. 함대 기준 자세와 개별 함선 자세

### 4.1. 용어 및 좌표 기준 [확정/권장]

| 용어 | 의미 |
|---|---|
| **함대 기준 자세** `fleetOrientation` | 이동·교전 정책이 정하는 대형의 방향. 로컬 슬롯→월드 슬롯 변환 기준 |
| **개별 함선 자세** `ship.rotation` | 슬롯을 점유한 함선의 실제 선체 방향. 무장 사격각 판정 기준 |
| **대기 수평 정렬** `idleLeveling` | 함대 기준 자세에서 Pitch=0, Roll=0에 해당하도록 XZ 평면을 기준으로 복귀시키는 동작 |
| **개별 조준 보정** `shipAimOffset` | 무장 운용을 위해 함선이 함대의 기본 방향에서 추가로 회전하는 동작 |

**[확정]** 함대 기준 자세와 개별 함선의 조준 자세는 별개의 상태다. 개별 함선이 사격을 위해 방향을 바꿨다는 이유만으로 전체 대형의 슬롯 방향까지 강제로 회전시키지 않는다.

### 4.2. 자세 제어의 핵심 불변식 [확정]

1. **전투 중에는 Pitch와 Roll에 인위적인 정책상 제한을 두지 않는다.** 상대 함대와 동일한 Y좌표에서 싸우는 경우에도 함선이 사격 화각을 얻기 위해 Pitch/Roll을 수행할 수 있다.
2. 다른 높이로 상승·하강하거나 다른 높이의 적과 교전하는 경우, 함대 기준 자세와 개별 함선 자세가 필요한 3D 방향을 자유롭게 취할 수 있다.
3. **이동을 완료하고 별도의 활성 교전을 수행하지 않는 대기 상태**가 되면, 함대 기준 자세를 XZ 평면에 평행한 **수평 기본 자세**로 되돌린다. 개별 함선도 이에 맞춰 기본 자세로 복귀한다.
4. 전투를 실행하는 동안 함대가 **순간적으로 정지했다는 이유만으로** 대기 수평 정렬을 발동하지 않는다. 교전 중 정지 사격, 거점 방어 중 활성 교전은 `ENGAGING`이다.
5. Yaw는 평면 안에서 자유롭게 유지할 수 있다. 수평 정렬은 **일률적인 고정 방위각**을 강제하는 것이 아니다.
6. 정렬은 **위치의 평면화가 아니다**. 함선은 다양한 Y좌표의 입체 슬롯을 그대로 사용한다.

**금지되는 구 해석:** '이동 중 Pitch/Roll은 항상 0', '같은 높이 교전이면 Pitch/Roll 불가', '정지 대치에서는 무조건 작은 yaw/pitch만 허용', '독립적인 큰 Roll은 무조건 불허'. 이러한 정책상 일괄 제한을 기존 v2.0에서 제거한다.

### 4.3. 상태와 규칙의 대응 [확정 의미 / 권장 상태 표현]

| 전술 행동 상태 | 기준 자세 | 개별 함선 자세 | 자동 수평 정렬 |
|---|---|---|---|
| `MOVING` (3D 목표로 진행) | 계획된 3D 진행 방향에 맞춰 조정 | 기본적으로 대형 추종; 필요시 실제 움직임에 맞게 회전 | 아니오 |
| `ENGAGING` (거리 유지·관통·포위 등) | 대응의 전술적 목표를 따름 | 사격 방향·무장 화각에 따른 3D 보정 가능 | 아니오 |
| `MOVING_AND_FIRING` (명령 유지 사격) | 기존 이동 경로·대형을 유지 | 사격을 위한 방향 보정 가능. 그러나 이동 목표를 변경하지 않음 | 아니오 |
| `POINT_DEFENDING_ACTIVE` (거점에서 활성 교전) | 방어 대형과 교전 방향을 따름 | 필요시 Pitch/Roll 포함 자유 조준 | 아니오 |
| `IDLE` (이동 완료, 활성 교전 없음) | 마지막 유효 Yaw를 사용해 수평 복귀 | 대형 방향에 기본 정렬 | **예** |

- **[권장]** `MOVEMENT`/`ENTERING`/`ACTIVE`/`EXITING` 등의 기존 교전 FSM과 자세용 `MOVING`/`ENGAGING`/`IDLE` 개념을 혼용하지 말고, 자세 판단에 필요한 파생 상태를 계산한다. **속도 0만으로 `IDLE`을 판정하지 않는다.**
- **[권장]** 관통 완료 후 원래 이동을 재개할 때는 진행 방향을 따르고, 목적지 도착·교전 종료 후에 대기 정렬을 실시한다.
- **[권장]** `POINT_DEFENSE`의 대상이 사라져도 방어 거점 이동은 완료한다는 기존 원칙을 보존한다. 거점에 머물러 있고 활성 교전이 없을 때만 대기 수평 정렬을 수행할 수 있다. 조우 정책의 해제 및 이동 임무 복귀는 기존 정책 FSM에 따른다.

### 4.4. 수평 복귀의 기하학 [권장]

기준 방향 `forward = rotate(qFleet, +Z)`를 XZ 평면에 정사영한다.

```text
horizontal = normalize((forward.x, 0, forward.z))
if length((forward.x, 0, forward.z)) < epsilon:
    horizontal = lastValidHorizontalForward  // 수직 진행 중 Yaw 소실 방지
qIdle = orientation(forward=horizontal, up=(0,1,0))
qFleet = rotateGradually(qFleet, qIdle, turnRate, dt)
```

- **[권장]** 회전 표현은 Quaternion을 사용해 Pitch가 ±90° 근처일 때 Euler 각도의 특이점을 회피한다. 회전 보간에도 각속도/가속도 제약을 적용한다.
- **[권장]** 이동·교전 중 불필요한 Roll 회전을 피하는 연속성 제어는 허용하지만, 실제 전술에 필요한 Roll을 금지하는 하드 클램프는 두지 않는다.
- **[권장]** `lastValidHorizontalForward`는 저장 가능한 유효 상태여야 한다. 미정이라면 `(0,0,1)`을 임시 기본값으로 사용하되 함대별 값으로 기록한다.
- **[중요]** 함대 기준 자세가 회전하면 `slotWorld = anchor + rotate(qFleet, slotLocal)`도 변한다. 그러므로 수평 복귀 중 **월드 슬롯 목표가 이동할 수 있다**. 함선은 가감속·충돌 회피를 거쳐 새 슬롯으로 이동하며, 즉각적 위치 보정/순간이동을 하지 않는다.
- **[권장]** 회전 종료 조건은 `rotationError < tolerance`와 필요하다면 슬롯 안정화 조건으로 정한다. 수평으로 돌리느라 임무 중심점 자체가 달라지지 않게 한다.

### 4.5. 무장 사격각과의 관계 [확정 의미 / 권장 처리]

- **[확정]** 함선이 조준을 위해 Pitch와 Roll을 사용하는 것은 **같은 고도에서의 교전에서도 가능**하다.
- **[확정]** 회전식 포탑은 장착 좌표계 기준으로 독립 조준하며, 고정식 무장은 실제 선체 방향으로 사격 가능 여부를 판정한다.
- **[권장]** `ship.rotation`은 함선의 실제 선체 방향이며, 함대 기준 방향은 그 기본값이다. 개별 보정은 슬롯의 위치를 변경하지 않는다.
- **[권장]** 선체의 3D 회전 허용과 무기의 사격각 무제한은 다르다. 무장별 실제 물리적 한계는 유지한다. 함선 회전의 응답 속도나 관성도 별도 제한할 수 있지만, **Pitch/Roll을 0으로 만드는 정책상 금지는 없다**.
- **[권장]** 로컬 +Z 방향으로 완전히 고정된 주포는 선체의 Roll만으로 전방 방향이 바뀌지 않는다. Roll은 비대칭 장착 무장·여러 무장 아크·편대 자세 보정에서 의미가 있을 수 있다. 사격 가능 여부는 **실제 변환된 무장 전방 벡터/아크**로 계산한다.
- **[미결]** `OPPORTUNISTIC_FIRE`에서 선체가 사격각 확보를 위해 어느 정도까지 이동 방향에서 벗어날 수 있는지의 구체적 **우선순위**. 다만 이동 경로·대형 슬롯을 바꾸거나 Pitch/Roll을 일률적으로 금지하는 방식으로 해결하지 않는다.

## 5. 기존 정책과 기능 연결

| 기존 전술 기능 | v2.1 적용 |
|---|---|
| 목적지 이동 `MOVE` | `GridPoint3`로 지정한 월드 교차점으로 연속 이동; 도착 후 활성 교전이 없으면 수평 정렬 |
| 경로 순찰 `PATROL` | 경유점은 모두 그리드 교차점; 경유점마다 **대기 상태로 확정하지 않고** 다음 점으로 이어서 이동 |
| 명령 유지 사격 `OPPORTUNISTIC_FIRE` | 이동 명령·대형 그대로. 전투 중 개별 함선의 자세 보정 가능하되 함대 기동 목표 변경 금지 |
| 거리 유지 교전 `STANDOFF` | 적과의 거리·무장 화각에 따라 함대·함선의 3D 회전 가능. 정지 사격도 `IDLE`이 아님 |
| 진형 관통 `BREAKTHROUGH` | 3D 관통 경로와 쐐기 대형의 회전 자유도 유지. 동일 적에게 무한 재관통 금지 |
| 분할 포위 `ENCIRCLE` | 다른 고도와 방향의 분견대 조작 유지. 분견대 방향은 각 그룹의 3D 전술 목표에 따라 결정 |
| 거점 방어 `POINT_DEFENSE` | 방어 좌표는 격자 교차점; 거점으로 가는 이동은 연속 공간. 활성 교전 없을 때 대기 수평 복귀 허용 |

**명확한 예외:** `MOVE`의 목적지 도달 중 적과의 `STANDOFF` 교전이 활성화됐다면, 현재 물리 속도가 0이더라도 대기 정렬 조건이 아니다. `PATROL`의 경유점 도착도 자동 대기 상태가 아니다.

## 6. 데이터 구조와 시스템 경계 — Codex 구현 가이드

다음 코드는 구조 **예시**이다. 엔진과 실제 레포지토리를 확인한 뒤 적용할 것. 확정 사용자 요구와 구현 선택을 구분한다.

```ts
type Vec3 = { x: number; y: number; z: number };
type GridPoint3 = { ix: number; iy: number; iz: number }; // 정수 인덱스

type CommandGrid = {
  origin: Vec3;
  spacing: number; // > 0, 월드 단위
  minIndex?: GridPoint3;
  maxIndex?: GridPoint3;
};

type MovementOrder =
  | { policy: 'MOVE'; destination: GridPoint3; travelSize: Vec3; arrived: boolean }
  | { policy: 'PATROL'; waypoints: GridPoint3[]; currentWaypointIndex: number; travelSize: Vec3 };

type EncounterOrder = {
  policy: EncounterPolicy;
  defenseAnchor?: GridPoint3; // 사용자 지정 거점만
  formationParams: FormationParameters;
};

type PositionDraft = {
  kind: 'MOVE_DESTINATION' | 'PATROL_WAYPOINT' | 'DEFENSE_ANCHOR';
  phase: 'PICK_XZ' | 'PICK_Y';
  ix?: number;
  iz?: number;
  iy?: number;
  previousCameraSnapshot: CameraSnapshot;
};

type FleetOrientationRuntime = {
  fleetOrientation: Quat;            // 함대 대형 기준의 실제 자세
  targetFleetOrientation: Quat;      // 이동/교전/대기 규칙이 산출한 목표
  lastValidHorizontalForward: Vec3; // 수직 방향 전환과 대기 복귀를 위한 yaw 기준
  postureIntent: 'MOVING' | 'ENGAGING' | 'IDLE';
};

// 기존 Ship.rotation과 실제 Ship.position은 월드 연속 값으로 유지한다.
// 기존 BattleState, FleetCommand, EncounterRuntime, Weapon, FormationKind는 보존한다.
```

| 시스템 | 새 책임 | 책임 밖의 일 |
|---|---|---|
| `CommandGrid` | 그리드 인덱스↔월드 좌표 변환, 경계 검증, 최근접 교차점 | 실제 함선 위치 스냅 |
| `PositionInputController` | XZ→YZ/XY 자동 화면 전환, 임시 좌표, 확정/취소 | 전투 중 함선 위치 직접 변경 |
| `ViewController` | 원근/직교 카메라 구성, 입력 뷰포트 좌표 변환, 기존 카메라 복귀 | 전술 지시 명령 자체 변경 |
| `FleetPostureController` | 이동·교전·대기 기준 자세 및 수평 복귀 목표 산출 | 개별 무장 발사 판정 |
| `FormationFollower` | 변화하는 함대 기준 자세로 실제 월드 슬롯 목표 계산 | 순간이동으로 슬롯 완성 |
| `ShipMotionController` | 개별 선체의 목표 자세와 슬롯 추종 | 임의로 전술 정책 변경 |
| `WeaponController` | 실제 선체·포탑 자세에 대한 무장 발사각 계산 | 무기 사격을 이유로 함대 명령 교체 |

**권장 실행 순서:** (1) 입력 `GridPoint3`를 실제 임무 월드 좌표로 변환 → (2) 기존 정책 FSM이 활성 목표를 결정 → (3) 자세 의도(`MOVING/ENGAGING/IDLE`)와 기준 회전 목표를 계산 → (4) 함대 기준·슬롯·개별 함선 이동 및 회전 갱신 → (5) 실제 방향 기반 무장 판정 → (6) 4개 뷰포트 렌더링. 입력 단계는 준비 상태에서만 명령 데이터를 커밋한다.

## 7. W08·W09·W10 강의 내용과 직접 연결되는 작업

- **W08 행렬/변환:** 함대 기준점과 회전으로 로컬 슬롯을 월드로 변환한다. 수평 복귀 전후 같은 `slotLocal`이 어떻게 재투영되는지 검증한다.
- **W09 뷰잉 파이프라인:** 원근 메인 카메라 + XZ/XY/YZ 직교 화면, 뷰포트별 픽셀→NDC→월드 변환 및 마우스 입력의 3D 위치 복원을 구현하거나 확장한다. 주 작업 화면의 XZ→YZ/XY 자동 변환은 게임의 공간 입력 목적에 직접 필요하다.
- **W10 공간 탐색:** 조우/사거리/충돌 후보 탐색에 필요한 경우 3D 공간 해싱·경계 구·BVH 등을 도입하되, **명령용 격자**와 **공간 탐색용 자료구조**를 동일시하지 않는다. 성능상 필요성과 직접 구현한 알고리즘을 별도로 입증한다.
- 엔진 내장 `Raycaster`, `lookAt`, 직교 카메라만 호출한 사실을 CG 기법의 직접 구현이라고 단정하지 않는다. 코드상 직접 구현/확장 책임과 테스트를 구분해 기록한다.

## 8. 수용 및 회귀 테스트

**테스트 참조 구분:** 이 절은 `보강 명세 G01~G18`로 표기한다. [v2.1 통합본](fleet_auto_battle_design_spec_v2_1.md)의 `통합본 G01~G14`는 독립 목록이며 동일 번호가 같은 사례를 뜻하지 않는다. 테스트 결과에는 문서명과 ID를 함께 기록한다.

| ID | 시나리오 | 기대 결과 |
|---|---|---|
| G01 | XZ 목표점 클릭 | X, Z만 정수 교차점으로 결정, Y는 아직 미확정 |
| G02 | YZ 높이 선택 | 앞서 정한 X, Z가 유지되고 Y만 정수 인덱스로 반영되어 좌표 완성 |
| G03 | XY 화면을 두 번째로 사용할 경우 | 앞서 정한 X, Z 유지, Y만 변경. `ZX`를 높이 선택 화면으로 사용하지 않음 |
| G04 | 입력 취소 또는 뒤로 가기 | 기존 명령 불변, 임시 표시/카메라 상태 정상 복구 |
| G05 | 음수 좌표, 경계 근처 클릭 | 정해진 스냅 규칙에 따라 교차점 선택, 범위 밖은 확정 방지 |
| G06 | `PATROL` 경유점 여러 개 추가 | 각 경유점을 같은 2단계 입력으로 등록, 경유점 순서 보존 |
| G07 | 서로 다른 두 격자점 사이로 이동 | 함대·함선 실제 위치는 연속적으로 변화; 중간 프레임에서 교차점으로 점프하지 않음 |
| G08 | 함대가 다른 높이로 상승/하강 | 3차원 회전을 허용하고 위치/진형 유지. 수직 진행 중 갑작스런 Yaw 반전 없음 |
| G09 | 같은 높이의 적과 활성 교전 중 함선 무장 화각 확보 | 필요시 Pitch/Roll 허용; '같은 높이'라는 이유로 강제 0 처리하지 않음 |
| G10 | 다른 높이의 적과 활성 교전 | 함대와 개별 함선의 3D 방향 변경 가능, 실제 무장 사각 준수 |
| G11 | 이동 완료, 활성 교전 없음 | 함대 기준 Pitch/Roll이 부드럽게 0으로 복귀, Yaw는 마지막 유효 방향 보존 |
| G12 | 거점 정지 교전 또는 대치 정지 사격 | 물리적 속도 0이어도 활성 교전 중 자동 수평 복귀가 발동하지 않음 |
| G13 | 대기 수평 복귀 중 슬롯 회전 | 함대 중심과 각 함선의 실제 3D 위치가 순간이동하지 않고 슬롯 위치로 부드럽게 추종 |
| G14 | 포위·돌파 중 Y 높이 차 발생 | 3차원 대형 전개 및 경로 유지; 강제 동일-Y 평면화 없음 |
| G15 | 동일 클릭 좌표에서 뷰포트 크기 변경 | 픽셀/뷰포트/NDC 변환을 반영하여 일관된 월드 교차점 선택 |
| G16 | 명령 유지 사격 중 표적 발견 | 이동 명령과 대형 기준점·슬롯이 적 추적 명령으로 바뀌지 않음. 자세 조준 예외는 별도 규칙 적용 |
| G17 | 카메라 자동 전환 후 완료/취소 | 종전 자유 카메라 상태가 복구되고 전투 관람 제어에 영향 없음 |
| G18 | 무기 마운트 방향의 Pitch/Roll 계산 | 실제 선체·장착 회전 및 무장 아크 기준으로 사격 가능 여부를 판단 |

## 9. 미결 사항과 권장 기본 선택

| 항목 | 상태 | 구현 시 권장 임시값 또는 원칙 |

## 10. Codex용 변경 지시 요약

1. 기존 v2.0의 정책 ID, 게임 루프, 입체 대형 및 사용성 원칙을 **보존**한다.
2. 목적지·경유점·사용자 지정 방어 거점을 **3D 격자 교차점의 정수 인덱스**로 모델링한다.
3. 명령 지점의 격자화와 개별 함선/대형/적/포탄의 연속적인 월드 좌표를 **구분**한다.
4. 목표 지정 시 `XZ`에서 X/Z를 지정한 뒤 `YZ` 또는 `XY`로 자동 전환하여 Y만 선택한다. 완료 또는 취소 시 종전 카메라를 복원한다.
5. 함대 기준 자세와 개별 함선 조준 자세를 분리한다. **교전 중 Pitch/Roll을 높이 차 유무와 무관하게 허용**한다.
6. 이동 완료 후 **활성 교전이 없는 대기 상태**에는 함대 방향을 XZ 평면 기준으로 부드럽게 정렬한다. Yaw는 유지 가능하다.
7. 함대 방향을 정렬할 때 **대형의 3D 슬롯과 실제 함선 위치를 평면화하거나 순간이동시키지 않는다**.
8. 기존 v2.0의 '정지 대치에서 작은 yaw/pitch만', '큰 Roll 금지' 등 **충돌하는 옛 규칙/테스트를 교체**한다.
9. 새로운 상태/격자/좌표 UI의 오류 사례를 `G01–G18`로 검증한다.
10. 미결정 수치와 대체 가능 구현 방식은 사용자 확정으로 표기하지 않는다.
