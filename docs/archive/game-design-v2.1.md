## 0. 문서 읽는 법과 우선순위

### 0.1. 확정 수준

- **[확정]**: 대화에서 사용자가 직접 정의하거나 명시적으로 수용한 방향. 기능을 생략·변경하려면 사용자와 다시 결정할 것.
- **[표준 명칭]**: 이 개정판이 UI·기획·코드 설명에 통일해서 쓰는 명칭. 이름 변경은 가능하지만 **정의와 동작을 함께 변경하지 말 것**.
- **[설계 권장]**: 구현을 가능하게 만들기 위해 제안한 구체적 알고리즘, 데이터 관계, 예외 처리. 게임 의도에 부합하면 대체 가능.
- **[임시값]**: 테스트용 숫자. 사실이나 사용자 확정값으로 기술하지 말고 한 곳에서 조정 가능하게 관리.
- **[미결]**: 별도 결정이나 테스트가 필요한 사항. 사용자와 확정한 것처럼 표시하지 말 것.

**충돌 해결 우선순위:** [확정] 의도 > 이 문서의 불변식과 정책 의미 > [설계 권장] 구현 > [임시값]. 오래된 명칭·예시가 충돌하면 **이 문서의 최신 명칭-정책 매핑표(4절)**를 따른다. **v2.1에서는 2절(격자), 10절(자세), 12.3절(2단계 입력)이 v2.0의 충돌하는 규칙을 대체한다.**

### 0.2. Codex 실행 지침

1. 구현 전 실제 Starter Pack, 저장소 구조, 기존 브랜치, 의존성 및 기술 트랙을 조사한다. 이 문서를 실제 코드가 이미 구현되었다는 증거로 사용하지 않는다.
2. 사용자가 요구하지 않은 상점·성장·멀티플레이·새 전술 정책·임의 스킬을 추가하지 않는다.
3. **정책(policy)**, **대형(formation)**, **함선/무장 행동**은 서로 다른 책임이다. 대형 선택을 별도의 세 번째 주 명령으로 노출하지 않는다.
4. 사용자의 조작 종류는 처음부터 끝까지 동일하게 유지한다. 숙련에 따라 **판단의 깊이**가 늘어야지 고급 조작이 해금되는 게임이 아니다.
5. 확정되지 않은 수치·알고리즘은 설정값으로 두고, 기본값을 적용한 사실과 한계를 README 또는 구현 노트에 기록한다.
6. **전투 한 판의 완결된 수직 슬라이스**를 우선 구축한다. 이후 정책을 단계적으로 추가한다. 기본 정책이 형식적으로만 존재하도록 더미 구현하지 않는다.
7. 게임에 꼭 필요한 CG 기술을 사용한다. 기법 시연만을 위한 인위적 기능은 추가하지 않는다. 단, 과제의 직접 구현/확장 조건은 별도로 검증한다.
8. **격자는 플레이어의 명령 목표에만 적용한다.** 실제 함선·포탄·대형 슬롯은 연속 3D 월드 좌표로 다룬다.
9. **대기 중 수평 정렬과 전투 중 자유 3D 자세를 혼동하지 않는다.** 같은 높이의 적과 싸울 때도 함선의 Pitch/Roll 조준 회전을 정책상 일률적으로 금지하지 않는다.

### 0.3. 변경 요약(v1 → v2 → v2.1)

- `이동 정책` → 플레이어 표시명 **이동 명령**, `조우 정책` → **교전 대응**.
- `진형/진법`을 문서와 UI에서는 **대형**으로 통일; 역사적 명칭은 참고 설명에만 사용.
- `이동용 장사진` → **이동 격자**: 3축 크기를 조절하는 입체 격자이며 면형도 허용.
- `이동/순찰` → **목적지 이동/경로 순찰**.
- `기회 사격/대치/돌파/포위/거점 방어` → **명령 유지 사격/거리 유지 교전/진형 관통/분할 포위/거점 방어**.
- **이동 명령 2종 + 교전 대응 5종**, 총 10개 정책 조합. 교전 대응의 대형은 대응별로 정해지며, 명령 유지 사격은 이동 격자를 그대로 사용.
- 조작은 고급/초급 모드로 나누지 않는다. 모든 플레이어가 같은 명령과 대형 조절 인터페이스를 쓴다.
- 교전 개시·종료, 관통 완료, 거점 기준, 분견대 붕괴, 무장 방향, 스냅샷 보존 등에 대한 구현 규칙과 검증 항목을 보강.

- **2026-11-23 v2.1:** 3D 격자 교차점에 명령 좌표 스냅, XZ→YZ/XY 자동 화면 전환을 통한 2단계 입력, 함대 기준 자세와 개별 선체 자세 분리, 이동 완료/비교전 대기 시의 XZ 수평 정렬, 교전 중 Pitch/Roll 허용, 데이터 모델·회귀 테스트 개정.

## 1. 제품 정의 및 목표 경험

### 1.1. 게임 한 문장 [확정]

플레이어가 **완전한 3차원 우주 전장**에서 보유 함선들을 여러 함대로 편성하고, 각 함대의 **이동 명령과 적 조우 시 교전 대응**을 지정하여, 함대가 이에 대응하는 **대형**을 유지·전환하며 일정 시간 자동으로 이동·교전하는 모습을 관찰한 뒤 전술을 수정하는 게임.

### 1.2. 핵심 재미 및 조작 원칙 [확정]

- 실시간으로 함선을 직접 조작하는 재미보다 **함대 운용 계획의 결과를 관찰하고 검증하는 재미**가 중심이다.
- 플레이어는 개별 함선의 실시간 위치나 포탑을 조종하지 않는다. **함대 편성, 명령, 3D 목표 지점, 대형 크기, 대형 내 함선 순서**를 전투 준비 단계에 설정한다.
- 함대는 조직적인 이동을 보이고, 함선은 진형 슬롯을 따르면서 자신의 무장으로 사격한다.
- 결과 차이는 임의의 진형 공격력 버프가 아니라 **무장 사거리·고정식 사격각·함선 배치·접근 방향·거리·차폐·이동/회전 제한**의 상호작용에서 나타나야 한다.
- 처음부터 같은 종류의 입력을 사용한다. 초보자는 직관적으로 선택하고, 숙련자는 **같은 선택에 더 많은 변수**를 고려한다. 초보/고급 설정 모드나 조작 해금은 핵심 설계가 아니다.
- 자동 전투 종료 후 기존 명령은 보존되며 수정하고 싶은 함대만 다시 설정할 수 있다.

### 1.3. 제외 범위 [확정/권장]

- **[확정]** 회피(Evade), 카이팅(Kite)은 독립 교전 대응으로 **제공하지 않는다**.
- **[확정]** 완전 3D 공간이며 수면/중력 기반 해전이 아니다.
- **[설계 권장]** 이번 과제에서는 성장, 자원, 장비 제작, 다수 캠페인, 멀티플레이, 복잡한 물리 충돌, 대량 신규 3D 에셋 제작은 제외.
- **[설계 권장]** 전면 대형의 자동 학익진화는 분할 포위와 역할이 중복되므로 초기 목표에 넣지 않는다. 국지적인 슬롯 미세 조정과 의도적인 4분할 포위는 별개이다.

## 2. 공간·좌표·방향 규약

### 2.1. 완전한 3D 전장과 명령용 격자 [확정]

- 함대의 실제 이동·교전, 함선 위치, 대형 슬롯, 포탄, 조우와 충돌은 **연속적인 X/Y/Z 3D 공간**에서 처리한다.
- 플레이어가 지정하는 **목적지, 순찰 경유점, 거점 방어 위치**는 **3차원 격자의 교차점**으로 지정한다. 이는 명령 입력의 이산화이며, 함선 위치의 격자 이동이나 단순한 높이별 2D 전장이 아니다.
- 명령 격자는 일반적인 3D 인덱스 `(ix,iy,iz)`로 나타낸다. 격자 *칸 중심*이 아니라 **격자선 교차점**이 유효한 목표 좌표다.
- 자동 교전의 대치·돌파·포위 목표 위치는 적의 움직임에 맞춰 **연속 좌표**로 생성한다. 적 함대의 움직임을 격자에 붙이거나 함선·슬롯을 양자화하지 않는다.
- 메인 원근 카메라와 XY/XZ/YZ 직교 카메라는 동일한 월드 데이터를 각자의 투영으로 표시한다.

### 2.2. 엔진 독립 좌표 기준 [설계 권장]

| 속성 | 규약 |
|---|---|
| 월드 업 | `+Y` |
| 수평 작전 평면 | `XZ` |
| 함선 로컬 전방/오른쪽/위 | `+Z` / `+X` / `+Y` |
| 이동 격자 로컬 폭/높이/깊이 | `X` / `Y` / `Z` |
| 위치 | 실제 함대·함선은 연속 `Vec3`, 사용자 목표는 정수 `GridPoint3` |
| 회전 | Quaternion 또는 동등한 3D 회전 표현 |
| 격자 간격 | `gridSpacing > 0` 설정값, 세계 크기와 무장 사거리에 맞춰 결정 `[미결]` |
| 단위 | 월드 임의 단위; 특정 현실 거리 단위로 단정하지 않음 |

- 격자 원점 `gridOrigin`과 간격 `h`에 대해 `gridToWorld(ix,iy,iz) = gridOrigin + (ix*h,iy*h,iz*h)`.
- 화면에서 선택한 점은 축마다 `round((world-gridOrigin)/h)`로 가장 가까운 **교차점**에 스냅한다. 경계/동률 처리 규칙은 코드에서 일관되게 결정한다. 음수 인덱스도 지원한다.
- 격자 간격과 공간 해싱의 셀 크기를 동일한 설정으로 묶지 않는다. 후자는 공간 탐색 알고리즘의 별도 구현 선택이다.

### 2.3. 이동·교전·대기의 방향 정책 [확정]

- **활성 이동 및 교전:** 이동/정렬/교전 목적에 필요한 3D 함대 회전을 허용한다. 서로 다른 Y를 향해 이동하거나 다른 고도의 상대와 교전할 때 Pitch/Roll을 금지하지 않는다.
- **같은 높이에서의 교전:** 개별 함선의 무장 화각 확보에 필요한 Pitch/Roll을 허용한다. 같은 Y좌표라는 이유만으로 Pitch/Roll을 0으로 고정하지 않는다.
- **이동 완료 후, 활성 교전이 없는 대기:** 함대의 기준 자세를 XZ 평면과 정렬하도록 Pitch/Roll을 0인 기본 수평 자세로 **부드럽게 복귀**시킨다. Yaw(수평 방향)는 자유롭게 유지한다. 개별 함선도 기본 방향으로 정렬한다.
- **교전 중 잠깐 정지한 상태는 대기가 아니다.** 정지 대치, 활성 거점 방어, 포위 대기 등은 전술 행동 상태로 판정하며 자동 수평 복귀를 강제하지 않는다.
- **함대 기준 자세**(3D 대형 슬롯의 회전)와 **개별 함선 자세**(선체/무장 화각)는 서로 다른 상태다. 개별 함선의 조준 회전만으로 대형 전체의 방향을 강제 변경하지 않는다.
- 입체 대형의 함선 Y 위치를 같은 높이로 강제 평면화하지 않는다. 수평 복귀는 **자세**에 관한 것이고 **위치**에 관한 규칙이 아니다.

### 2.4. 3D 격자 명령 좌표의 적용 범위 [확정/설계 권장]

| 대상 | 명령 격자 적용 | 실제 실행 |
|---|---|---|
| `MOVE.destination` | 적용 | 해당 교차점으로 연속 이동 |
| `PATROL.waypoints` | 적용 | 경유점 사이 연속 이동, 경유점 통과 후 다음 목표 |
| 사용자 지정 `POINT_DEFENSE.defenseAnchor` | 적용 | 거점으로 연속 이동 후 방어 |
| 함대의 현재 위치·속도 | 미적용 | 연속 3D 시뮬레이션 |
| 개별 함선·슬롯·포탄 | 미적용 | 연속 3D 시뮬레이션 |
| 자동 교전 대응의 대치·관통·포위 목표 | 미적용 | 적 상대 위치에 따라 연속 갱신 |

**[설계 권장]** 기존 저장 데이터의 임의 `Vec3` 명령점을 새 `GridPoint3`로 마이그레이션할 때 무언의 위치 변경을 일으키지 않는다. 자동 도출한 방어 거점도 사용자가 클릭한 격자 좌표로 허위 표시하지 않는다.

## 3. 게임 루프 및 주요 상태

### 3.1. 플레이 흐름 [확정]

```text
함대 편성
 └─ 보유 함선을 여러 함대에 배분하고 함대 내 정렬 순서를 결정
      ↓
전투 준비 (시간 정지)
 ├─ 적 위치 등 주어진 정보 확인
 ├─ 함대별 [이동 명령] + 해당 목표(목적지 또는 순찰 경유점)
 ├─ 함대별 [교전 대응] + 대응에 필요한 기준점(거점 방어 등)
 ├─ 각 명령에 대응하는 대형의 크기/형상 및 함선 순서 조절
 └─ 준비 완료
      ↓
일정 시간 자동 전투
 ├─ 명령에 따라 함대 이동·감지·대형 전환
 ├─ 개별 함선의 슬롯 추종 및 무장의 자율 공격
 ├─ 자유/함선 추적 카메라로 관람
 └─ 시간 종료 또는 승패 판정
      ├─ 적 전멸 → 승리
      ├─ 아군 전멸 → 패배 [설계 권장]
      └─ 시간 종료·적 생존 → 전투 준비 (살아남은 상태 그대로)
```

### 3.2. 전투 단계 전환의 불변식

1. **[확정]** 전투 실행은 제한 시간제이고, 적 전멸까지 준비와 자동 전투를 반복한다.
2. **[설계 권장]** 전투 준비는 전투 시뮬레이션의 완전한 일시정지다. 살아 있는 함선의 위치, 선체 회전, 체력, 현재 재장전, 진행 중인 발사체, 대형 전환 진행 상태, 적 상태를 보존한다.
3. **[설계 권장]** 매 준비 시작 시 함선을 초기 위치로 되돌리거나 순간이동시키지 않는다. 사용자가 지정하는 위치는 **이후 이동할 목표점**이다.
4. **[설계 권장]** 적군 또는 아군이 전멸하면 제한 시간 이전이라도 즉시 결과 화면으로 전환한다.
5. **[설계 권장]** 준비 중에는 이동·무장·포탄 업데이트와 AI 판단 시계를 멈추고, 재개 시 연속적으로 진행한다.
6. **[확정 의도]** 이전 명령과 배치는 다음 준비 단계에도 남는다. 사용자는 일부 함대만 재설정해도 다음 전투를 시작할 수 있어야 한다.
7. **[미결]** 정확한 전투 지속 시간, 패배 후 재시도, 장시간 교착 및 함대 편성의 전투 중 변경 허용 여부.

> **평소에는 이동 명령을 수행합니다. 적을 만나면 선택한 교전 대응을 우선 실행합니다. 단, '명령 유지 사격'은 이동을 멈추거나 바꾸지 않습니다.**

- `거리 유지 교전`은 **적과의 상대 거리**가 중심이고 `거점 방어`는 **월드상 지정 위치**가 중심이다.

## 5. 시스템 공통 불변식 및 충돌 해결

### 5.1. 필수 불변식

1. **교전 대응 > 이동 명령.** `OPPORTUNISTIC_FIRE`만 이동 명령을 끊지 않는 예외.
2. 교전 대응은 **정책 목표를 변경**하지, 함선 개개인이 무조건 적을 쫓게 만드는 것이 아니다.
3. 함선과 함대의 모든 목표/배치/충돌/사격은 실제 **3차원**에서 계산한다.
4. 함선의 **기본** 선체 방향은 대형 방향을 따른다. 다만 활성 교전 중 개별 함선이 무장 화각을 확보하기 위한 **Pitch/Roll 포함 3D 보정 회전**을 수행할 수 있고, 이는 대형의 슬롯 위치를 바꾸지 않는다. 전방 고정식 무장은 **실제 선체 자세**를 기준으로 사격각을 판정한다.
5. 진형(대형) 변경은 슬롯 목표의 변경일 뿐 **위치 순간이동이 아니다**.
6. 표적 배분은 다수 표적을 선호할 수 있으나 **항상 1:1을 강제하지 않는다**. 적 선두 등 집중 가치가 높은 표적은 집중 사격할 수 있다.
7. 함선의 현재 상태에 대한 진짜 데이터는 시뮬레이션이 단일 보유한다. 뷰포트/미리보기에서 별도의 권위 있는 상태를 만들지 않는다.
8. 조우 대응이 끝나면 저장된 기존 이동 임무로 복귀한다. 다만 `명령 유지 사격`은 복귀할 별도 이동 중단 자체가 없다.

### 5.2. 공통 우선순위(권장)

`전투 승패/생존 판정` > `현재 활성 교전 대응` > `기본 이동 명령` > `진형 슬롯 추종` > `국지 무장 조준`.

- 위는 **명령 결정 권한의 개념적 서열**이다. 충돌 회피 같은 안전 제한은 모든 이동에 걸리는 물리적 제약이지 추가 전술 명령이 아니다.
- 교전 대응이 활성이라도 각 무장은 가능하면 계속 사격할 수 있다. 포위나 돌파 중 '사격 금지'를 자동 적용하지 않는다.
- 고정식 무장의 조준 보정이 **함대 이동 명령·대형 기준점·정책 목표를 바꾸는 이유**가 되어서는 안 된다. 개별 함선의 조준 회전은 별도 제어로 취급하며, 활성 교전 중 Pitch/Roll을 무조건 금지하지 않는다.

## 6. 이동 명령 상세

### 6.1. 목적지 이동 (`MOVE`)

**입력:** `destination: GridPoint3` 1개(명령용 격자 교차점). 실행 시 `gridToWorld`로 변환한다.

**실행:**

1. 현재 함대 기준점에서 목적지까지 계획된 진행 방향을 얻는다.
2. 이동 격자 대형의 중심을 목적지로 이동시키고 함선들은 각자의 슬롯을 추종한다.
3. 진행 중인 3D 방향을 따라 대형 기준 자세를 조정한다. 함선은 기본 방향을 따르며 활성 사격 시 필요하면 독립 3D 조준 회전을 수행할 수 있다.
4. 함대 기준점이 `arrivalTolerance` 안에 있고 충분히 감속했으면 `ARRIVED`로 표시한다.
5. 도착 후 **다른 활성 교전이 없다면** 대기 자세로 전환하여 함대 기준 Pitch/Roll을 수평 복귀시키고, 마지막 유효 수평 Yaw를 유지한다. 새 명령을 자동 생성하지 않는다. 수평 복귀로 변한 슬롯 목표는 함선들이 연속 이동으로 추종한다.

**예외:** 이동 중 적극 교전 대응이 활성화되면 현재 `destination`과 도착 상태를 보존하고 대응이 종료될 때 임무를 재개한다. 이미 도착했다면 복귀 후 계속 대기한다.

### 6.2. 경로 순찰 (`PATROL`)

**입력:** `waypoints: GridPoint3[]`(격자 교차점)와 `currentWaypointIndex`. 각 경유점은 월드 좌표로 변환하여 이동한다.

**실행:**

1. 현재 인덱스의 경유점으로 목적지 이동과 같은 방식으로 이동한다.
2. 경유점에 도착하면 인덱스를 증가시키고 마지막 다음에는 첫 경유점으로 순환한다. **경유점 통과만으로 대기 수평 복귀를 시작하지 않는다.**
3. 조우 대응 중에는 인덱스를 보존하며, 복귀 시 기존 경유점을 이어서 수행한다.
4. 중간 경유점이 현재 위치와 동일하거나 너무 가까우면 무한 정지하지 않도록 즉시 다음 경유점으로 넘어간다.

**[설계 권장]** 최소 2개의 서로 다른 경유점이 있어야 `PATROL` 선택을 허용한다. 경로 수정 시에는 해당 함대의 현 위치에서 가장 적절한 시작 인덱스를 재설정하거나, 사용자가 지정한 첫 경유점부터 시작한다. 하나를 선택해 일관되게 사용한다.

## 7. 조우 감지, 실행 상태 및 복귀

### 7.1. '적을 만난다'의 정의

- **[확정된 역할]** 준비 단계에서 알고 있는 적의 위치와, **교전 대응이 실제로 발동하는 적 조우**는 구분한다.
- **[설계 권장]** 조우 조건을 `조우 대상 후보 거리 <= encounterEnterRange`로 정의한다. 거리 계산은 함대 중심 또는 각 함선과 상대 함대의 경계 구를 고려한다.
- `encounterExitRange > encounterEnterRange` 또는 종료 유예 시간을 사용해 경계에서 정책을 반복 전환하지 않도록 한다.
- 시야 공개/탐지 모델은 아직 미결이다. 초기 프로토타입에서는 전장 내 적 함대의 위치는 알려져 있고, `encounterEnterRange`가 교전 대응 개시 기준이라고 가정할 수 있다.
- `명령 유지 사격`은 조우 FSM을 진입·종료하지 않고 항상 이동 명령을 실행하면서 사격 가능한 적만 공격하는 **지속 오버레이**로 구현 가능하다.

### 7.2. 함대 행동 상태 [설계 권장]

```text
MOVEMENT
 ├─ 이동 명령 실행: MOVE 또는 PATROL + 이동 격자
 ├─ 교전 대응이 OPPORTUNISTIC_FIRE → 이동 지속 + 무장 후보만 갱신
 └─ 다른 교전 대응 & 유효 적 조우 → ENTER_ENCOUNTER

ENTER_ENCOUNTER
 ├─ 현재 이동 임무 보존(목표점/순찰 인덱스 등)
 ├─ 대상 적 함대 잠금(그룹 ID)
 ├─ 해당 교전 대형과 행동 목표 초기화
 └─ ENCOUNTER_ACTIVE

ENCOUNTER_ACTIVE
 ├─ 교전 대형 생성/전환 + 정책별 이동 목표 갱신
 ├─ 각 함선 슬롯 추종 및 가능 무장 사격
 ├─ 정책별 완료 조건 또는 적 조우 해제 확인
 └─ EXIT_ENCOUNTER

EXIT_ENCOUNTER
 ├─ 재관통 억제 등 교전 기록 업데이트
 ├─ 임시 교전 목표와 잠금 해제 또는 유예
 ├─ 이동 격자로 전환(순간이동 금지)
 └─ MOVEMENT, 원래 이동 임무 재개
```

**[설계 권장]** `FORMATION_TRANSITION`을 최상위 정책 상태로 만들지 말고 **대형 제어기의 내부 진행 상태**로 보관한다. 정책 전환 중에도 함대와 무장은 계속 작동할 수 있어야 한다.

**[v2.1]** 자세 제어를 위한 `MOVING / ENGAGING / IDLE`은 이 교전 FSM과 별개의 **파생 상태**로 계산한다. 함대 중심점의 현재 속도가 0이라는 이유만으로 `IDLE`이나 수평 복귀를 발동하지 않는다.

### 7.3. 적 함대 선택과 안정성 [설계 권장]

- `activeEnemyFleetId`는 **교전 대응의 대상 함대**를 뜻하며, 각 무장의 개별 표적 ID와 구분한다.
- 복수 적 함대가 접촉 범위 안에 있으면 거리, 전투 가능성, 위협, 해당 정책에 적합한 표적 가치로 하나를 선정한다. 초기 구현은 최근접 **적 함대** 선택으로 단순화 가능하다(최근접 단일 적 **함선** 집중과 다름).
- 매 프레임 적 함대를 다시 바꾸지 않는다. 변경 가능 조건(기존 대상 소멸/이탈, 더 중요한 적의 충분한 우세, 최소 유지 시간)을 정의한다.
- 같은 적이 진입/해제 거리를 반복 넘나들어도 쿨다운 또는 해제 유예를 두어 진형 전환이 튀지 않게 한다.
- 교전 대상 소멸 시 같은 틱에 다른 적을 즉시 새로 선정할지, 일단 이동 복귀 후 다음 틱에 조우할지는 **[미결]**. 임시로 한 번 `EXIT_ENCOUNTER` 처리 후 다음 틱에 재진입할 수 있다.

### 7.4. 정책별 완료 및 해제 [설계 권장]

| 교전 대응 | 완료/해제의 핵심 기준 | 복귀 후 처리 |
|---|---|---|
| 명령 유지 사격 | 별도 상태 없음. 사격 가능한 적이 없으면 발사 중단 | 계속 기존 이동 |
| 거리 유지 교전 | 대상 적 함대 소멸, 조우 해제 유예 충족 | 이동 격자 복귀 후 목적지/순찰 재개 |
| 진형 관통 | 대상 함대의 배치 영역을 실제 통과, 또는 대상 소멸 | 같은 적에 즉시 재관통하지 않음 |
| 분할 포위 | 대상 소멸, 조우 해제 유예 충족 | 분견대 해체 후 이동 격자로 재집결 |
| 거점 방어 | **거점에 도달했고**, 대상 소멸 또는 조우 해제 유예를 충족 | 구형 방어 대형에서 이동 격자로 복귀 |

- **주의:** `거점 방어`는 현재 기획에서 **교전 대응**이다. 아직 적을 조우하지 않았다면 상시 거점 수비 임무로 작동하지 않는다. 적이 없는 상태에서도 영구적으로 지켜야 하는 새로운 '상시 방어 명령'을 몰래 추가하지 않는다. 이 한계는 UX에서도 명확히 설명해야 한다.
- `진형 관통`은 교전 대상이 살아 있어도 성공할 수 있다. 관통 직후 같은 대상이 여전히 접촉 범위 안에 있다는 이유로 재시작하면 안 된다. `completedBreakthroughEnemyIds` 또는 `encounterEpoch` 기준 **재진입 금지 래치**를 유지하고, 충분히 이탈하거나 교전이 새로 시작되었을 때만 해제한다.
- `거점 방어`는 **조우로 한 번 발동하면 방어 거점까지 이동하는 임무를 우선 완료**한다 [설계 권장]. 이동 도중 적이 감지 범위를 벗어났다는 이유만으로 원래 이동 명령으로 되돌아가는 무한 전환을 방지한다. 거점 도달 후 적이 소멸했거나 접촉 해제 유예가 충족되면 기존 이동 명령으로 복귀할 수 있다. 이 규칙은 거점이 영구 사수 임무라는 뜻은 아니다.
- `분할 포위`와 `거점 방어`에서 적이 포기하고 멀어질 경우, 추적 범위·이탈 유예의 차이를 정책별 설정으로 둘 수 있다. 거점 방어의 **방어 위치 이탈 금지**는 무조건 지킨다.

### 7.5. 정책 전환 의사코드

```text
function updateFleetPolicy(fleet, world):
    if world.battleState != RUNNING or fleet.aliveShipCount == 0:
        return

    if fleet.encounterOrder.policy == OPPORTUNISTIC_FIRE:
        ensureMovementMode(fleet)
        updateMovementOrder(fleet)       # 계속 이동/순찰
        updateWeaponCandidates(fleet)   # 가능한 경우에만 사격
        return

    if fleet.mode == MOVEMENT:
        enemy = findEncounterEnemyFleet(fleet)
        if enemy != null and canStartEncounter(fleet, enemy):
            beginEncounter(fleet, enemy) # 이동 목표 보존, 대응 대형 설정
        else:
            updateMovementOrder(fleet)
            return

    if fleet.mode == ENCOUNTER:
        if encounterFinished(fleet):
            finishEncounter(fleet)      # 완료 기록, 이동 명령 복귀
        else:
            updateActiveEncounter(fleet) # 정책별 공간 목표 계산

    updateFormationTargetAndShipSlots(fleet)
    # 무장/표적/피해 갱신은 별도의 공통 시스템에서 수행
```

**구현 참고:** 진입/종료 처리가 같은 프레임에 반복되어 상태가 뒤집히지 않도록 하나의 업데이트에서 허용되는 최대 상태 전환 횟수와 이벤트 우선순위를 정한다. 이 의사코드는 구현 구조 설명이며 완성 코드가 아니다.

## 8. 교전 대응별 상세 행동 명세

### 8.1. 명령 유지 사격 (`OPPORTUNISTIC_FIRE`)

**플레이어가 기대하는 행동:** "가던 길을 계속 가면서 쏠 수 있는 적만 공격한다."

- **대형:** 이동 격자 그대로. 새로운 교전 대형 생성 없음.
- **기준 목표:** 이동 명령이 설정한 목적지/순찰 경유점.
- **수행:** 이동·속도·진형 방향·경로의 전술적 목표를 바꾸지 않는다. 그 순간 사거리/사격각/사선 조건을 만족하는 무장만 발사한다.
- **금지:** 공격을 이유로 **함대 기준 방향, 이동 경로, 목표 위치, 이동 대형을 변경**하거나 적을 추적·정지·우회하지 않는다. **개별 함선의 선체 조준 회전**은 함대 기준 자세와 분리하며, 무장 화각/이동 추종 우선순위를 지키는 한 허용 가능하다. 그 구체적인 우선순위는 10.5절의 `[미결]`을 따른다.
- **완료:** 별도 교전 완료 이벤트 없음. 사격 불가능하면 그냥 발사하지 않는다.
- **특성:** 목적지 도착 후 정지한 상태에서도 현재 자세로 사격 가능한 적에게는 사격할 수 있다. `MOVE`를 자동으로 대치 교전으로 승격하지 않는다.

### 8.2. 거리 유지 교전 (`STANDOFF`)

**플레이어가 기대하는 행동:** "적을 향해 전선을 세우고, 싸우기 좋은 거리에서 계속 싸운다."

- **대형:** 전면 대형(`FRONT_PLANE`), 진행/교전축의 법선이 적 함대 방향을 향하는 2D 입체 공간상의 격자 면.
- **기준 목표:** `activeEnemyFleet`의 월드 위치·상대 속도, 아군 무장들의 유효 교전 거리대.
- **수행:**
  1. 대상 적 함대를 선정하고 전면 대형으로 전개한다.
  2. 적까지 너무 멀면 접근, 너무 가까우면 필요한 만큼 이격한다.
  3. 적이 움직이면 함대 중심과 전면 대형의 방향을 함께 갱신한다.
  4. 유리한 거리대 안에서는 위치 변화를 줄이고 지속 사격한다.
  5. 함선들은 전면 대형의 슬롯을 유지하고 무장에 따라 표적을 배분받는다.
- **거리 목표:** 함대 무장별 사거리가 다를 수 있으므로 단순 `모든 함선 사거리의 평균`이 아니라 **현재 함대에서 유효하게 작동할 수 있는 화력 가중 거리대**를 선정하도록 권장한다. 초기에는 명시적인 `preferredRangeMin/Max`를 사용해도 된다.
- **제약:** 적이 무장의 실제 발사각 밖에 있을 때 무조건 발사하지 않는다. **활성 교전 중 함선은 필요하면 Pitch/Roll을 포함해 조준할 수 있으며**, 실제 선체·포탑의 회전 응답을 거쳐 사격각이 성립할 때만 발사한다. 함대의 전면 대형 슬롯은 유지한다.
- **범위 제외:** 아군 숫자가 많아졌다고 무조건 학익진/포위 상태로 자동 변화시키지 않는다. **분할 포위**라는 독립 대응과 역할을 구분한다.
- **종료:** 주 대상 소멸 또는 유효한 교전 접촉 종료.

### 8.3. 진형 관통 (`BREAKTHROUGH`)

**플레이어가 기대하는 행동:** "적 전열 속을 뚫고 지나가 반대편으로 빠져나간다."

- **대형:** 쐐기 대형(`WEDGE`), 전방 선두와 뒤쪽으로 확장되는 다층 쐐기.
- **기준 목표:** 적 함대의 **배치 영역을 가로지르는 경로** 및 그 바깥쪽 출구.
- **수행:**
  1. 대상 적 함대의 중심과 대략적인 3D 점유 영역(경계 구/박스 등)을 구한다.
  2. 현재 접근 방향에서 적 배치 영역의 내부를 통과하는 진입점과 반대편 출구점을 계산한다.
  3. 쐐기 대형으로 점진 전환하면서 진입한다. 정책적 기준은 **관통 경로 유지**다.
  4. 전진 및 실제 통과를 우선하고, 가능한 무장은 이동 중 사격한다.
  5. 함선의 충돌을 피하기 위해 소규모 편차는 허용하되 적 함대를 멀리 돌아가는 경로를 관통으로 판정하지 않는다.
  6. 적 함대의 후방 경계를 넘어 충분한 여유 거리까지 벗어나면 `BREAKTHROUGH_COMPLETE`.
- **검증 조건:** 계획 경로가 적 점유 영역과 교차했다는 것과, 실제 함대 궤적이 진입·통과·출구 조건을 충족했다는 것 **둘 다** 확인한다. 계획만 통과하고 실제로 우회하면 실패다.
- **적 함대가 이동할 때:** 대상 위치와 경로를 제한된 빈도로 갱신하고, 갑작스러운 경로 역전/왕복을 금지한다.
- **재발동 제약:** 같은 조우에 대해 완료 후 즉시 반복 관통하지 않는다.
- **종료:** 실제 관통 완료 또는 대상 소멸. 돌파의 성공은 적 전멸과 무관하다.

### 8.4. 분할 포위 (`ENCIRCLE`)

**플레이어가 기대하는 행동:** "함대가 네 방향으로 나뉘어 적을 둘러싸고 공격한다."

- **대형:** 4분할 포위 대형(`FOUR_GROUP_ENCIRCLEMENT`); **하나의 함대를 정확히 네 분견대**로 나눔 **[확정]**.
- **최소 조건 [설계 권장]:** 생존 함선이 4척 미만이면 선택 불가. 전투 중 4척 미만으로 줄면 남은 그룹으로 교전은 지속하되, 새 함선을 생성하거나 즉시 강제 재편성하지 않는다.
- **기준 목표:** 적 함대의 현재/예측 중심, 4개 분견대별 3D 목표 위치.
- **수행:**
  1. 함대 순서에 따라 4개 비어 있지 않은 분견대로 분배한다(초기 배분을 결정적으로 만들 것).
  2. 적 함대 중심을 기준으로 전후·좌우·상하를 다양하게 사용하는 4개 포위 목표점을 만든다.
  3. 네 분견대가 각자 목표점으로 이동하면서 분견대 내부 대형을 유지한다.
  4. 도달 후 포위 위치를 적의 이동에 맞춰 보정하고, 네 그룹은 **공동 화력 배분 정보**를 공유하며 사격한다.
  5. 적이 소멸하거나 접촉이 끝나면 분견대를 다시 한 함대의 이동 격자로 재집결시킨다.
- **[설계 권장] 목표점 생성:** 정규화된 정사면체 꼭짓점 방향 4개를 출발점으로 사용하고, 적 크기·사거리·현재 진입 방향에 맞춰 방향과 반경을 조정한다. 이것은 고정된 정사면체를 유지하라는 뜻이 아니다.
- **주의:** 포위는 반드시 하나의 함대에 포함된 **네 하위 그룹**이어야 한다. 서로 독립된 4개의 영구 함대로 분할하여 플레이어 편성 상태를 변경하지 않는다.
- **대형 내부 무장:** 분견대의 이동·포위 목표와 슬롯을 유지하면서 개별 함선은 무장 화각을 위한 3D 보정 회전을 수행할 수 있다. 고정식 무장이 실제 선체 방향에서 사격각을 확보하지 못했다면 발사하지 않는다. **동일 Y의 적을 상대해도 Pitch/Roll을 일률적으로 막지 않는다.**
- **종료:** 대상 소멸 또는 조우 관계 종료. 4개 그룹의 모든 함선이 지정점에 완벽히 도착해야만 공격을 시작한다는 조건은 두지 않는다.

### 8.5. 거점 방어 (`POINT_DEFENSE`)

**플레이어가 기대하는 행동:** "적을 쫓지 말고 정해 둔 곳에 모여 방어한다."

- **대형:** 구형 방어 대형(`SPHERE`), 방어 거점을 중심으로 구면 또는 다층 구형 배치. **구형**이라는 기하학적 의도는 확정; 표면/체적 방식은 [미결].
- **기준 목표:** 전술 준비에서 지정한 **방어 거점(`defenseAnchor`)**. 적의 현재 위치가 대형 중심을 바꿔서는 안 된다.
- **수행:**
  1. 적과 조우하면 기본 이동 명령을 중단한다.
  2. 방어 거점으로 이동하며 구형 방어 대형으로 전환한다.
  3. 거점 주변 슬롯을 유지하고 이탈한 함선은 해당 슬롯으로 복귀한다.
  4. 사거리·사격각·차폐 조건이 맞는 적은 공격한다.
  5. 적이 멀어져도 **추적하지 않는다**. 거점 위치와 진형 유지가 적 공격보다 우선한다.
- **지점 입력 [설계 권장]:** 플레이어가 별도 3D 방어 거점을 지정한다. 지정하지 않았다면 활성 목적지/현재 순찰 경유점을 사용하고, 그것마저 없으면 조우 시점의 함대 기준점을 사용한다. UI는 자동으로 결정된 거점을 표시한다.
- **구형 대형과 선체 방향:** 포탑이 자유 회전 가능한 함선과 전방 고정식 무장의 효율이 다를 수 있다. 구형 배치라고 해서 모든 함선이 자동으로 전방위 사격 가능한 것으로 취급하지 않는다.
- **대치와의 구분:** 대치는 **적의 움직임에 맞춰 상대 거리**를 유지한다. 거점 방어는 **고정 월드 좌표**를 유지한다.
- **명령 유지 사격과의 구분:** 명령 유지 사격은 **기존 이동 목표를 절대 바꾸지 않으며 이동 격자를 유지**한다. 거점 방어는 **기존 이동을 일시 중단하고 거점으로 모이며 구형 대형으로 바뀐다**.
- **종료:** 일단 조우로 발동했다면 거점 도달을 우선 완료한다. **거점 도달 이후** 대상 소멸 또는 조우 해제 유예 충족 시 원래 이동 명령으로 복귀 **[설계 권장]**. 적이 먼저 이탈해도 거점까지 가는 과정은 중단하지 않는다. 영구적인 거점 방어 명령은 이번 2종 이동 체계에 추가하지 않는다.

## 9. 대형의 기하학적 정의 및 전환

### 9.1. 공통 데이터와 변환 [확정된 개념]

- 함대는 `fleetAnchorPosition`, `fleetOrientation`(Quaternion), `formationKind`, `formationSlotOffsets`, `orderedShipIds`를 가진다.
- 함선 `i`의 목표 슬롯 위치:

```text
shipSlotWorldPosition[i] = fleetAnchorPosition
                            + rotate(fleetOrientation, slotOffsetLocal[i])
```

- 사용자가 바꾸는 **함선 순서**와 대형이 생성한 **슬롯 순서**를 대응시켜 실제 함선의 위치가 달라지게 한다.
- 진형 전환은 새 슬롯을 생성해 **목표 위치**로 설정하는 것이다. 순간이동·무제한 순간 회전으로 간주하지 않는다.
- **[v2.1]** 함대 기준 자세가 대기 수평 방향으로 변화할 때도 위 수식의 슬롯 월드 위치가 변화한다. 기존 함선의 현재 위치를 그대로 유지한 채 슬롯 목표를 다시 계산하며, 함선은 부드럽게 추종한다.
- 격침 시 사망 함선의 슬롯을 비워두는 것을 기본값으로 한다. 자동으로 나머지 함선 전원을 재번호 매기면 사용자의 배치 의도가 사라질 수 있다.
- 거리·체적·각도·회피에서 동일한 월드 기준 계산을 사용한다. 렌더링에 표시된 모델 위치를 AI가 별도의 권위 데이터로 재계산하지 않는다.

### 9.2. 이동 격자(`TRAVEL_GRID`) [확정된 조절 요구 + 설계 권장 정의]

**플레이어 조절:** 로컬 3축 X(좌우 폭), Y(상하 높이), Z(전후 깊이) 크기. 모든 이동 명령에 동일하게 적용한다.

- 기본 형태는 정렬된 3D 격자 슬롯. 한 축의 층수가 1이면 그 축으로는 **두께 없는 면/선 성분**이 될 수 있다.
- 3축 모두 두 개 이상의 슬롯 층을 가지면 **체적 격자**가 된다. 게임 내 이름은 '이동 격자'로 통일한다.
- 슬롯 배치와 축별 층수는 함선 수 및 크기에 따라 생성한다. 보이는 외곽 상자만 변경하고 실제 슬롯이 바뀌지 않는 슬라이더는 만들지 않는다.
- **단위 명세:** `travelSize: Vec3`는 축별 슬롯 중심의 최대 폭(Extent)이다. 각 축의 층수가 1이면 그 축의 슬롯 좌표는 0이며 해당 축 크기 슬라이더는 실제 배치에 영향을 주지 않을 수 있다. 이때 UI에 비활성/미적용 안내를 제공하거나 층수 재구성 규칙을 둔다.
- **[설계 권장]** 사용자 조절의 실효성을 높이려면 함선 수와 축 비율을 이용해 `nx * ny * nz >= aliveShips`인 층수 조합을 결정하고, 슬롯 수가 부족하지 않도록 한다. 결정적 결과·최소 함선 간격을 보장한다.
- `밀도`는 길이와 중복되는 조작이므로 **독립 기본 슬라이더로 제공하지 않는다 [개정 제안]**. 추후 '중심 집중도' 같은 별도 효과를 증명할 때 재도입할 수 있다. 이는 기존 초기 아이디어의 폐기가 아니라 현재 조작 원칙에 따른 범위 정리다.
- 대형 미리보기에서 선택된 함선이 어느 슬롯으로 이동할지 시각화한다.

### 9.3. 교전 대형의 원형 [형상 상세는 설계 권장]

| 대형 | 대응 정책 | 슬롯 생성 기하 | 플레이어가 같은 방식으로 조절할 크기 |
|---|---|---|---|
| 이동 격자 `TRAVEL_GRID` | 목적지 이동·경로 순찰·명령 유지 사격 | X/Y/Z 격자 | 좌우 폭·상하 높이·전후 깊이 |
| 전면 대형 `FRONT_PLANE` | 거리 유지 교전 | 적을 향하는 법선을 가진 XY 면 격자 | 좌우 폭·상하 높이, 필요시 전후 깊이 |
| 쐐기 대형 `WEDGE` | 진형 관통 | 선두가 +Z, 후방으로 퍼지는 다층 쐐기 | 전후 길이·후방 폭·후방 높이 |
| 4분할 포위 대형 `FOUR_GROUP_ENCIRCLEMENT` | 분할 포위 | 4개 분견대 중심 + 내부 소형 격자 | 포위 반경(공통), 그룹 내 간격/폭 |
| 구형 방어 대형 `SPHERE` | 거점 방어 | 거점을 중심으로 구면 또는 다층 구형 슬롯 | 방어 반경, 내부 밀집 정도는 선택 |

**개발 원칙:** 조작 방식 자체는 항상 드래그/슬라이더/핸들로 통일하되, '3축 길이'를 모든 원형에 억지로 일대일 대응하지 않는다. 예를 들어 구형은 반경이 의미 있고, 포위는 분견대 사이 거리가 의미 있다. 모든 대형에 허상 슬라이더를 추가하면 안 된다.

### 9.4. 전면 대형(`FRONT_PLANE`)

- 함선들이 로컬 X/Y 면에 놓이고 로컬 +Z가 적을 향한 면의 법선이 된다.
- **함대 전체가 실제 이동 중**이면 진행 방향을 따라 전환·이동하고, **대치 교전 위치에 도달**한 뒤 전면의 법선이 적을 향하도록 안정화한다.
- 위·아래·좌·우 모두 실제 3D 위치 차이이며 스크린 좌표의 단순 2D 아이콘 배열이 아니다.

### 9.5. 쐐기 대형(`WEDGE`)

- 선두 슬롯이 진행 방향인 +Z에 가장 앞서고, 뒤쪽 층으로 갈수록 X/Y 단면이 확장된다.
- 층별 함선 수가 적어 완전한 원뿔이 안 되더라도 일관된 슬롯 순서·선두·후방층 관계를 유지한다.
- 전체 함선이 관통 경로 방향에 따라 전진한다. 개별 선박이 적을 따라 쐐기 바깥으로 흩어지는 행동은 금지한다.

### 9.6. 4분할 포위 대형(`FOUR_GROUP_ENCIRCLEMENT`)

- `orderedShipIds`를 결정적 규칙으로 4그룹 분배하되 그룹 간 인원은 가능한 균등하게 한다.
- 분견대의 `anchor`가 독립적인 월드 목표를 가진다. 전체 함대의 함선 소유 정보와 하나의 상위 정책은 유지된다.
- 4개 포위 방향은 **3D로 분산**되어야 한다. 동일 XZ 평면의 4각형에만 고정하지 않는다.
- 그룹마다 이동 속도와 도착시간이 다르더라도 도달한 그룹은 우선 사격할 수 있다.

### 9.7. 구형 방어 대형(`SPHERE`)

- 기준점은 적 함대 중심이 아니라 `defenseAnchor`이다.
- **[설계 권장]** N개의 슬롯을 구 표면에 균일하게 분포시키는 규칙(예: Fibonacci sphere)을 이용한다. N이 극히 작을 때는 대칭적인 별도 배열을 사용할 수 있다.
- 무장 방향/선체 방향은 모든 함선이 일률적으로 전방위가 되는 식으로 덮어쓰지 않는다.

### 9.8. 대형 전환/복구 공통 원칙

1. 정책이 바뀌면 기존 함선의 실제 위치를 유지한 채 새 목표 슬롯을 계산한다.
2. 이동 거리·최대 속도·선회율·충돌 여유를 지키며 각 함선이 목표 슬롯으로 이동한다.
3. 조준할 적이 있다고 해서 슬롯 제어를 버리고 개별 추격하지 않는다.
4. 좁은 대형에서 넓은 대형으로 변하는 동안 서로 교차하는 경로가 생기면 최소한의 충돌 회피 또는 일시적인 우회 경로를 적용한다.
5. 전환 중에도 가능한 무장은 공격할 수 있다. 전환 완료를 모든 조우 정책의 공격 시작 조건으로 삼지 않는다.
6. 함선 격침으로 슬롯이 비면 우선 빈 상태로 유지한다. 전투 중 강제 전면 재배치를 기본으로 삼지 않는다.
7. 표적을 공격하기 유리한 위치를 찾기 위해 **슬롯 근방의 제한된 이동**은 향후 허용 가능하지만, 자동 학익형 변형이나 임의의 큰 진형 해체는 현재 요구가 아니다.

## 10. 함대/함선의 이동 및 자세 제어

### 10.1. 계층적 이동 [확정된 의도]

1. **함대 정책 제어기**가 이동/교전/대기 행동 목표를 결정한다.
2. **함대 자세 제어기**가 이동·교전 중 3D 목표 방향 또는 대기 수평 방향을 계산한다.
3. **대형 제어기**가 함대 기준 자세를 이용해 각 로컬 슬롯의 월드 목표를 산출한다.
4. **개별 함선 제어기**가 슬롯 추종과 실제 선체 자세를 결정한다. 교전 중에는 무장 화각 확보를 위한 Pitch/Roll 포함 보정이 가능하다.
5. **무장 제어기**가 실제 선체/포탑 자세와 무장 고유 사격각으로 공격 가능 여부를 판단한다.
6. **국지 충돌 처리**는 최소한의 우회·분리를 수행하되 함대 전술 목표를 독자적으로 폐기하지 않는다.

**[설계 권장]** 함대 기준점은 가상 지휘 위치로 취급하며, 물리적 실제 함선 집합의 중심과 강제로 동일시하지 않는다. 슬롯 추종 속도와 대형 회전 속도는 실제 함선의 가감속·선회율을 고려한다.

### 10.2. 자세를 구분하는 핵심 용어 [확정/설계 권장]

| 상태 값 | 책임 |
|---|---|
| `fleetOrientation` | 이동·교전 정책이 정하는 **함대 대형의 기준 자세**, 로컬 슬롯 변환용 |
| `ship.rotation` | 각 함선의 **실제 선체 자세**, 고정식 무장의 화각 판정용 |
| `targetFleetOrientation` | 전술 행동/수평 복귀가 요청한 함대의 목표 자세 |
| `shipAimOffset` | 함대 기본 방향에 상대적인 개별 함선의 조준 보정, 구현 표현은 선택 가능 |
| `postureIntent` | 속도만이 아니라 명령·교전 상태로 결정하는 `MOVING/ENGAGING/IDLE` |

### 10.3. 행동 상태별 자세 정책 [확정]

| 상태·상황 | 함대 기준 방향 | 개별 함선 방향 | 자동 수평 정렬 |
|---|---|---|---|
| 같은 높이에서 이동 | 계획된 3D 진행 방향 추종 | 기본적으로 대형 정렬, 활성 사격 시 보정 가능 | 없음 |
| 다른 Y로 상승·하강 | 3차원 경로·대형 제어에 맞춰 Pitch/Roll 가능 | 필요에 따라 3D 선회 가능 | 없음 |
| 같은 높이의 적과 **활성 교전** | 전술 목적에 따라 회전 | **사격 화각을 위한 Pitch/Roll 허용** | 없음 |
| 다른 높이의 적과 **활성 교전** | 상대 3D 위치에 따른 회전 | Pitch/Roll 포함 3D 조준 가능 | 없음 |
| 정지 대치 또는 활성 거점 방어 | 교전 행동의 일부 | 정지해도 무장 조준 회전 가능 | **없음** |
| 이동 완료 후 **활성 교전 없는 대기** | XZ 기준 Pitch/Roll 0으로 부드럽게 복귀 | 함대의 기본 수평 방향으로 정렬 | **있음** |

- **[확정]** 같은 높이끼리 싸운다는 이유로 Pitch/Roll을 금지하지 않는다. **정지 교전에서 작은 yaw/pitch만** 허용하거나 **개별 큰 Roll을 일률 금지**하던 v2.0 해석은 폐기한다.
- **[확정]** '회전 제한 없음'은 *전투 중 정책상 Pitch/Roll 금지 없음*을 뜻한다. 함선의 선회 속도, 관성, 무장별 고유 화각까지 무한하다는 뜻은 아니다.
- **[확정]** 대기 수평 정렬은 공간상 XZ 기준 **선체·대형의 자세**에 관한 것이다. Y가 다른 함선들을 같은 Y 좌표로 모으지 않는다.
- **[설계 권장]** `PATROL`의 중간 경유점 통과, 적과 교전 중 잠시 속도 0, 거점 방어 중 위협 상대가 남아 있는 정지는 `IDLE`로 간주하지 않는다.

### 10.4. 대기 수평 복귀 알고리즘 [설계 권장]

함대 기준 앞 벡터 `forward = rotate(fleetOrientation, (0,0,1))`의 XZ 성분을 정규화해 목표 수평 전방을 얻는다.

```text
flat = (forward.x, 0, forward.z)
if length(flat) > epsilon:
    targetForward = normalize(flat)
    lastValidHorizontalForward = targetForward
else:
    targetForward = lastValidHorizontalForward

targetFleetOrientation = orientation(forward=targetForward, up=(0,1,0))
fleetOrientation = rotateGradually(fleetOrientation, targetFleetOrientation, maxTurnRate, dt)
```

- Yaw의 절대값을 고정하지 않는다. 수직 이동으로 평면 투영이 거의 0일 때 이전 유효 Yaw를 보존한다.
- 즉시 `q = qTarget`으로 덮어쓰지 않고 연속적인 보간을 적용한다. 쿼터니언을 사용하면 Euler 특이점 회피에 도움이 된다.
- 함대 기준 자세가 바뀌면 `shipSlotWorldPosition = fleetAnchor + rotate(fleetOrientation, slotLocal)`가 변한다. **월드 슬롯은 움직일 수 있으므로 함선은 위치를 순간이동시키지 않고 새 목표를 추종한다.**
- 함대 중심점 자체를 수평 복귀를 이유로 별도 좌표로 옮기지 않는다.

### 10.5. 무장 조준과 방향 우선권 [확정/미결 구분]

- 개별 함선은 함대 기준 자세를 기본 방향으로 삼되, **활성 교전 중 필요한 3차원 화각 보정**을 할 수 있다. 회전 자체가 전술 명령/대형 슬롯을 변경하지 않는다.
- `TURRET`는 장착점과 선체 변환이 합성된 실제 아크 안에서 독립 회전한다.
- `FIXED_FORWARD`는 **현재 `ship.rotation`과 무장 장착 방향**을 적용한 실제 전방 벡터 및 허용 아크로 발사 가능 여부를 판단한다.
- **[설계 권장]** 함선 로컬 `+Z`를 전방으로 하는 정확히 축상 고정포라면 Roll만 수행해도 발사 전방 벡터는 바뀌지 않는다. Pitch/Yaw가 주요 조준 방향이 된다. Roll은 무장 아크·장착 편차 등에 영향을 줄 수 있다.
- **[미결]** `OPPORTUNISTIC_FIRE`에서 이동 중 각 함선의 조준 선체 방향이 대형 기준 방향과 얼마나 달라질 수 있는지의 운용 우선순위. **이미 확정된 것은 이동 경로와 이동 대형의 기준점·슬롯을 적 추적에 따라 변경하지 않는다는 점**이며, 일률적인 Pitch/Roll 금지는 해결책이 아니다.

## 11. 무장·표적 배분·피해

### 11.1. 무장 종류 [확정]

| 종류 | 사격 방향 | 선체 방향의 영향 |
|---|---|---|
| **회전식 포탑** `TURRET` | 장착점에서 독립 회전, 허용 각도 내 표적 추종 | 선체 회전과 함께 장착 좌표계가 이동하므로 조준을 재계산함 |
| **전방 고정식 무장** `FIXED_FORWARD` | 선체 로컬 전방 기준의 제한된 사격각 | 함선 정면이 표적과 어긋나면 공격 불가 |

- 전방 고정식 무장이 모든 방향으로 사격하도록 **자동 조준 각도를 무제한으로 늘리지 않는다**.
- 회전식 포탑도 장착 범위·고각·회전 속도를 무시하는 전방위 마법 포탑이 아니다. 각 무장별 제약을 데이터화한다.
- 발사체의 궤적은 무장 설정과 게임 콘셉트에 맞게 정한다. 특정 CG 수학 기법을 보여주기 위해 필연성 없는 궤적을 추가하지 않는다.

### 11.2. 공격 가능 판정 [설계 권장]

1. 자신과 대상이 모두 살아 있는가?
2. 대상이 적 팀인가?
3. 실제 3D 거리와 무장 사거리가 맞는가?
4. 현재 선체 자세와 포탑 회전 한계에서 조준 가능한가?
5. 필요하다면 함선/장애물에 의해 사선이 가려지는가?
6. 재장전·발사 간격·발사체 상태가 유효한가?

**사격 가능 후보 선정**과 **대형 이동 목표 결정**은 별도 단계로 유지한다.

### 11.3. 표적 배분의 핵심 목표 [확정]

- 함대의 모든 함선이 자동으로 최근접 **단일 적 함선**만 공격하는 현상을 피한다.
- 가능한 경우 여러 적에 화력이 분산되도록 하되, **항상 일대일 단사 배정을 강제하지 않는다**.
- 어린진 선두 등 전술적으로 가치가 높은 적에게 화력을 집중하는 것이 합리적일 수 있다.
- 표적 선택 때문에 함선이 독자적으로 대형을 해체하거나 이동 목표를 바꾸지 않는다.

### 11.4. 권장 배분 알고리즘: 유효 무장 후보 + 한계 효용

```text
주 교전 적 함대 선정(함대 수준)
    ↓
각 무장의 공격 가능 적 후보 집합 구축
    ↓
후보 기본 점수 계산
    S = 사격 효율 + 위협도 + 전술 가치
        - 기존 표적 변경 비용 - 과잉 화력 비용
    ↓
무장(또는 함선 주무장) 순회하며 한 후보 배정
    ↓
배정한 공격력을 해당 적의 예상 누적 화력에 반영
    ↓
다음 무장은 변경된 한계 효용을 사용
    ↓
다음 재평가 시점 또는 주요 사건까지 할당 유지
```

- **[설계 권장]** 과잉 화력 비용은 `적의 예상 잔여 체력` 대비 `이미 예약된 유효 피해량`이 높을수록 증가한다. 이미 충분히 공격받는 대상을 무조건 금지하지는 않는다.
- **[설계 권장]** 기존 표적 유지 보너스, 재배정 주기, 유효 사격 불가능 시 긴급 재배정으로 표적 떨림을 줄인다.
- 포위의 네 분견대는 표적 배분 정보를 공유한다. 4그룹 모두 같은 적 함선만 공격하도록 독립 최근접 선택만 사용하지 않는다.
- 3차원 사격각과 선체 방향이 맞지 않으면 전방 고정식 무장은 발사하지 않는다.
- **최초 완성 버전:** 실제 사격 가능성 + 점수 + 간단한 누적 피해 페널티. 이후 위협도·전술 가치·예상 명중·사선 차폐를 단계적 확장.

### 11.5. 격침과 전투 상태

- 체력이 0 이하가 되면 함선은 살아 있는 전투 단위에서 제외하며 이동·조준·사격을 중단한다.
- 진형 슬롯과 분견대 소속을 즉시 무작위 재배치하지 않는다. 빈 슬롯은 남겨둘 수 있다.
- 함선의 격침 연출/잔해 소멸의 화면 처리와 실제 전투 판정은 별도다. 화면에서 폭발이 끝나기 전에도 전투 AI에서는 이미 격침으로 처리할 수 있다.

## 12. 전투 준비 UX, 카메라 및 정보 전달

### 12.1. 조작 원칙 [확정]

**처음부터 조작을 단순하게 유지하고, 숙련될수록 같은 선택의 판단 요소가 늘어나게 한다.** 초보용/고급용 입력 모드 또는 추가 조작 해금은 요구하지 않는다.

플레이어가 사용하는 핵심 조작 종류:

1. **선택:** 함선/함대/명령/교전 대응 선택.
2. **3D 지점 지정:** 목적지, 순찰 경유점, 방어 거점 지정.
3. **대형 크기 변형:** 3축 핸들 또는 의미 있는 형상 크기 슬라이더 조정.
4. **함선 순서 변경:** 편성 목록에서 드래그로 순서를 바꾸고 슬롯 매핑을 갱신.
5. **관람:** 자유 카메라/함선 추적 카메라 전환, 보조 뷰포트 탐색.

- 조작은 적은 종류로 일관되게 유지하되, 관련 정보와 결과가 깊이를 만든다.
- 매 라운드 모든 항목을 다시 입력시키지 않는다. 이전 명령과 대형 파라미터를 그대로 유지한다.
- **[설계 권장]** 첫 실행 기본값은 `목적지 이동 + 명령 유지 사격`으로 두고, 목적지만 지정해도 전투를 시작할 수 있다. `순찰`, `거리 유지 교전`, `진형 관통`, `분할 포위`, `거점 방어`는 같은 UI 위치에서 변경한다.
- 대형은 대응 선택으로 **자동 선택**된다. 진형을 별도의 세 번째 독립 주 명령으로 선택하는 메뉴를 만들지 않는다.
- 대형 파라미터는 필요 없으면 손대지 않아도 되는 **유효한 기본값**을 가진다. 별도의 '고급 모드' 뒤에 숨기는 것을 목표로 하지 않는다.
- 선택하면 **예상 이동 경로, 현재/목표 슬롯, 교전 기준점**을 미리보기로 보여준다. 결과를 예측할 근거가 있어야 한다.

### 12.2. 전투 준비 패널 [설계 권장]

```text
[선택한 함대]  제1함대  |  생존 6/6  |  함선 목록 및 드래그 순서

[이동 명령]     (목적지 이동 / 경로 순찰)
  - 목적지 또는 경유점 편집
  - 이동 대형: 이동 격자 [크기 조절]

[적을 만나면?]  (명령 유지 사격 / 거리 유지 교전 /
                 진형 관통 / 분할 포위 / 거점 방어)
  - 현재 선택 설명을 한 문장으로 보여줌
  - 해당 대형 자동 적용, 의미 있는 크기 조절
  - 거점 방어라면 방어 거점 입력 표시
  - 분할 포위라면 4분견대 배치 미리보기

[전투 준비 완료]
```

**정책 설명은 정책명과 동일한 목표를 약속**해야 한다. 예: '진형 관통' → 적을 뚫고 통과, '거점 방어' → 지정 위치를 유지하며 추적 금지. UI 라벨과 실제 AI가 다르면 기획 실패로 간주한다.

### 12.3. 격자 기반 3D 목표 좌표 입력 — 자동 2단계 직교 뷰 [확정/설계 권장]

**[확정]** 목표 지점을 지정하는 조작을 시작하면 **주 작업 화면이 자동으로 XZ 직교 뷰**로 바뀐다. X/Z를 선택하면 **YZ 또는 XY 직교 뷰**로 자동 전환되어 **Y만 선택**한다. 두 단계 완료 시 하나의 3D 격자 교차점이 명령에 등록된다.

**주의:** `ZX`와 `XZ`는 같은 평면이므로 2단계 높이 입력 뷰로 사용할 수 없다. 2단계는 `YZ` 또는 `XY`여야 한다. **[설계 권장]** 초기 구현은 `YZ`를 기본으로 사용하고, 최종 선택은 `[미결]`로 둔다.

```text
[목적지/경유점/거점 지정]
  → PICK_XZ: XZ 직교 뷰 확대/전환 → 격자 교차점에서 (ix, iz) 임시 선택
  → PICK_Y:  YZ(또는 XY) 직교 뷰로 전환 → ix/iz 잠금, iy만 선택
  → COMMIT: (ix,iy,iz)를 명령에 반영 → 이전 자유 카메라/뷰 복귀

ESC/취소: 기존 명령을 유지한 채 임시 좌표 폐기 + 카메라 복귀
뒤로: PICK_Y → PICK_XZ (X/Z 다시 지정)
```

- **[확정]** 2단계에서 수평 좌표를 **다시 선택하지 않는다**. 마우스의 Y축 위치만 높이 교차점에 스냅하고 나머지 좌표는 이전 단계 값을 고정한다.
- **[권장]** 별도의 세 번째 필수 확인 클릭 없이 높이 선택으로 즉시 목표를 확정한다. 변경 전까지 실제 명령은 수정되지 않는 임시 입력(`draft`)을 사용한다.
- **[권장]** 화면에는 현재 입력 단계, 축 이름, 선택 격자점, `(ix,iy,iz)` 또는 실제 월드 좌표, 기존 위치→목표선, Y 선택용 고정축 보조선을 표시한다.
- **[권장]** 입력 완료·취소 시 기존 주 카메라 위치/회전/줌을 복원한다. 자동 전투 실행 중에는 전술 명령 수정으로 인한 뷰 전환을 발동하지 않는다.
- `MOVE.destination`, `PATROL.waypoints[]`, 사용자 지정 `POINT_DEFENSE.defenseAnchor`에 **동일한 조작**을 재사용한다.

**W09 CG 구현 연결 [권장]:** 입력한 창 픽셀을 뷰포트 로컬 좌표→NDC→역투영된 월드 광선으로 변환하고, XZ/XY/YZ 가상 평면과 교차하여 관련 축 좌표만 얻는다. 직교 화면이더라도 뷰포트 리사이즈·종횡비·줌을 고려해야 한다. 격자 교차점에 스냅한 월드 위치는 메인 원근 뷰와 모든 직교 뷰에 동기화해 표현한다.

- 메인 카메라 자유 이동/회전/줌, 함선 클릭 추적, XY/XZ/YZ 직교 관측 기능 자체는 **기존 기획과 동일하게 유지**한다.
- **[권장 선택지, 확정 아님]** 반복 입력 편의를 위해 '기존 높이 유지' 단축 조작을 둘 수 있다. 기본 2단계 좌표 지정 절차를 무단 대체하지 않는다.

### 12.4. 전투 관람 HUD [확정된 목적 / 설계 권장]

최소 정보:

- 현재 자동 전투의 **남은 시간**과 준비/실행/결과 상태.
- 아군 함대 및 개별 함선의 **잔여 체력/생존 여부**.
- 선택 함대의 **현재 이동 명령과 활성 교전 대응**, 진행 목표·교전 대상.
- 선택된 함선의 무장 발사 여부와 주요 발사 불가 원인(사거리/각도/차폐/재장전)을 개발용 또는 정보 UI에 표시 가능.

개발 검증용 표시(시연에서는 켜거나 끌 수 있게 하는 것을 권장):

- 함대 기준점/진행 방향/목표 좌표, 이동 경로.
- 실제 함선 위치와 대형 목표 슬롯 및 슬롯 오차.
- 공격 대상과 사격 가능 무장, 포위 분견대의 기준점.
- 진형 관통의 적 점유 영역·진입·출구·관통 판정 이벤트.

**[설계 권장]** 자동 전투 중 사용자의 입력은 관람 카메라/UI 선택에만 사용하고 전술 명령 편집은 준비 단계에서 수행한다.

### 13.1. UI 표시명과 내부 정책 ID 분리

type FormationKind =

const MOVEMENT_LABELS: Record<MovementPolicy, string> = {

## 15. 최소 구현 범위와 개발 단계

### 15.1. 전체 기획과 과제 범위를 구분

- **게임 기획 목표:** 이동 명령 2종, 교전 대응 5종, 정책별 대형, 시간제 전투 루프, 3D 관측, 최소한의 공동 표적 배분.
- **과제 필수:** 교수 강의자료의 3D 상호작용, CG 직접 구현/확장, 문제 정의, 원본 팩과의 변경 추적, 제출물·출처 충족.
- **이번 개발의 수직 슬라이스 [설계 권장]:** 3D 공간에서 두 함대가 지정 위치로 움직이고, 대형을 유지하면서 자동 공격하고, 일정 시간이 끝나면 준비 화면으로 돌아오는 하나의 완결된 실행 루프.

### 15.2. 구현 우선순위 [설계 권장]

| 순서 | 구현 내용 | 통과 조건 |
|---|---|---|
| 1 | Starter Pack 원본 보존, 실행 환경, 명령/전투 데이터 모델 | 원본 Git 첫 커밋과 정상 실행 확인 |
| 2 | 3D 함선 배치·함대 편성·이동 격자 | 함대가 3축 목표로 이동하고 슬롯과 순서가 반영 |
| 3 | 최소 무장·피해·격침, 시간제 전투 | 한 전투 구간 실행→준비 복귀→다음 구간 재개 |
| 4 | 목적지 이동·경로 순찰·명령 유지 사격 | 적 발견해도 이동 경로 변경 없음 검증 |
| 5 | 거리 유지 교전 + 전면 대형 | 조우 시 적극적 거리 조절과 대형 전환 확인 |
| 6 | 진형 관통 + 쐐기 대형 | 실제 적 배치 영역 관통/완료/재발동 억제 |
| 7 | 거점 방어 + 구형 방어 대형 | 거점 우선·비추적·구형 전개 확인 |
| 8 | 분할 포위 + 4분견대 | 3D 다방향 포위 및 복귀 확인 |
| 9 | 표적 배분 개선·카메라/뷰포트·UI 완성 | 준비/관람 전체 루프가 이해 가능 |
| 10 | 자동화 테스트·시연·보고서/출처 정리 | 과제 제출 형식 충족 |

**구현 팁:** 카메라·입력의 최소 기능과 전술을 검증할 UI는 2~4단계부터 병렬로 필요하다. '9단계까지 UI를 전혀 만들지 않는다'는 뜻이 아니다. **[v2.1]** 격자 좌표의 왕복 변환과 XZ→YZ 2단계 입력은 기본 MOVE 명령을 테스트하기 전에 작동해야 하며, 이동 완료 대기 정렬과 활성 교전 회전 보정도 자세 제어기 초기 설계에 포함한다.

### 15.3. MoSCoW 범위 [과제용 제안]

- **Must:** 원본 보존과 실행, 3D 함대 하나 이상 조작, 함대 자동 이동·기본 교전·승패·시간제 전투, 실제 CG 직접 구현/확장 1종 이상과 원리 설명, 사용 입력 반응 1종 이상, 필수 제출물.
- **Should:** 전체 이동 명령 2종, 명령 유지 사격과 거리 유지 교전, 정책 대응 대형, 함선 순서, 자유/추적 카메라와 3축 직교 뷰, 회전식/고정식 무장의 차이, 표적 분산.
- **Could:** 진형 관통·거점 방어·분할 포위의 정교화, 4분견대 동적 재배치, 성능 시각화, 상세 피격·격침 연출.
- **Won't:** 회피·카이팅 별도 정책, 멀티플레이, 성장/상점, 대규모 스테이지, 과제와 무관한 CG 기법 전시.

위 분류는 **실제 제출 일정에 따른 권장 범위**이다. 사용자가 추후 모든 5종 교전 대응의 완성을 이번 버전의 Must로 결정하면 우선순위와 작업 범위를 다시 조정해야 한다.

## 16. 인수 테스트 — 명칭, 전술 의미, 사용성 검증

`[필수 기획 의도]`는 합의된 규칙의 위반 여부를 검사한다. `[권장 UX]`는 구현 품질 검증을 위한 제안이다. 자동화 가능한 항목은 테스트 코드로 작성하고, 관찰성이 필요한 항목은 개발 HUD나 시연 영상으로 확인한다.

| ID | 구분 | 설정 및 상황 | 기대 동작 |
|---|---|---|---|
| T01 | 필수 기획 의도 | `MOVE + OPPORTUNISTIC_FIRE` | 목적지 이동 중 적 사거리 진입 시 이동 격자와 경로 유지, 공격 가능한 무장만 사격 |
| T02 | 필수 기획 의도 | `PATROL + OPPORTUNISTIC_FIRE` | 순찰 경유점 변경 규칙 유지, 적 추적/대형 전환 없음 |

**페르소나 초안:** 함대 전술의 판단과 관찰은 즐기지만 개별 함선의 연속적인 실시간 조작은 원하지 않는 PC 게임 이용자. 같은 명령 UI로 시작하여 무장 배치·사격각·상대 위치를 이해할수록 더 깊은 선택을 추구한다.

**정량적 검증 기준 초안(실측 전):**

1. 신규 사용자 3명 중 3명이 설명 없이 60초 내 함대 선택·목적지 설정·전투 시작 성공.
2. 같은 시작 조건에서 `OPPORTUNISTIC_FIRE`와 `STANDOFF`가 서로 다른 이동/교전 경로를 재현.
3. `BREAKTHROUGH`는 지정 적 배치 영역 진입·통과·출구를 디버그 로그/화면에서 검증.
4. `POINT_DEFENSE`는 지정 거점 유지, 적 추적 미발생을 확인.
5. 제한 시간 종료 시 상태를 유지한 다음 전투 준비로 복귀.
6. XZ에서 X/Z를 고르고 YZ 또는 XY에서 Y를 고르는 2단계 입력을 통해 **정확히 하나의 3D 격자 교차점**을 지정하며, 모든 직교 뷰에 일치.

실험을 실제 수행하기 전에는 성공 여부를 **예상**으로만 표기하고, 결과값을 지어내지 않는다.

## 18. 미결정 사항과 명시적 임시 선택

아래는 본 문서에서 **확정된 사실이 아니라 설계 결정을 기다리는 항목**이다. Codex는 확정된 것처럼 문서를 고치지 말고, 구현을 진행해야 할 때만 제시된 임시 접근을 사용하고 기록한다.

| 중요도 | 항목 | 현재 임시 처리 또는 판단 기준 |
|---|---|---|
| 높음 | 목표 지정 2단계 UI와 높이 평면 선택 | XZ→YZ(임시 기본; XY 가능), 기존 카메라 복원, X/Z 잠금, Y만 선택 |
| 높음 | 명령 격자 원점/간격/경계 | `GridPoint3` 인덱스 + `gridOrigin/gridSpacing`로 변환, 수치 미확정 |
| 높음 | 정책별 조우 시작/해제 범위 | 진입·해제 거리 분리, 유지시간 사용 |
| 높음 | 거점 방어의 방어 거점 미설정 처리 | 활성 이동 목표, 없으면 현재 위치를 자동 사용하며 UI 표시 |
| 높음 | 거점 방어의 '적이 없는 평시' 역할 | 현재는 교전 대응이므로 **조우할 때만 거점 이동 시작**; 상시 방어로 무단 승격 금지 |
| 높음 | 3축 이동 격자 슬롯 생성 및 층수 | 함선 수·축별 형상 비율로 결정, 최소 이격 보장 |

## 19. Codex가 혼동하면 안 되는 금지 사항

1. 3D 공간을 XY 또는 XZ 평면에 제한하지 않는다.
2. `진형/대형`을 이동 명령/교전 대응과 분리된 독립적인 세 번째 주 선택 축으로 만들지 않는다.
3. 이동 명령에 '사수'를 다시 넣지 않는다. 이동 명령은 **목적지 이동·경로 순찰** 두 가지다.
4. `OPPORTUNISTIC_FIRE`는 **명령 유지 사격**이다. 적을 보고 이동 목표/방향/대형을 변경하지 않는다.
5. `POINT_DEFENSE`는 **거점 방어**다. 적을 추적하지 않고 지정 3D 위치에 모여 구형으로 방어한다.
6. `STANDOFF`는 **거리 유지 교전**이다. 적과 유리한 사격 거리대를 추구하며 정면 화력을 유지한다.
7. `BREAKTHROUGH`는 **진형 관통**이다. 적의 실배치 영역을 실제 지나 반대편으로 나간다. 근접 후 정지 사격이나 먼 우회는 관통이 아니다.
8. `ENCIRCLE`는 **분할 포위**다. 하나의 함대가 네 분견대로 나뉘어 서로 다른 **3차원** 위치에서 공격한다.
9. 회피와 카이팅을 독립 정책으로 다시 추가하지 않는다. 거리 유지를 위한 제한적 후퇴는 `STANDOFF` 내부 기동일 수 있다.
10. 무장 조준을 위해 **함대의 이동 목표·대형 기준점·슬롯 배치**를 무단 변경하지 않는다. 다만 활성 교전 중 **개별 함선의 Pitch/Roll 조준 보정 자체는 허용**되며, 방향 제어와 무장 화각을 구분한다.
11. 전방 고정식 무장을 무제한 포탑처럼 다루지 않는다. 회전식 무장에도 실제 장착 방향/각도를 적용한다.
12. 함대 전체가 무조건 최근접 **단일 적 함선**만 쏘게 하지 않는다. 그렇다고 일대일 공격만 강제하지 않는다.
13. 3D 목표점을 평면 뷰 하나의 클릭만으로 임의 깊이까지 확정하지 않는다. **XZ에서 X/Z를 고른 후 YZ/XY에서 Y만 선택**한다.
14. 전투 준비로 돌아올 때 함선 위치·체력·비행 중인 발사체·상태를 원점으로 되돌리지 않는다.
15. 입체 격자를 '장사진'이라고만 부르며 체적과 면의 차이를 감추지 않는다. 플레이어 표시명은 **이동 격자**다.
16. 초보용/숙련자용 조작을 구분해 새로운 기능을 단계적으로 해금하지 않는다. **처음부터 조작 방식이 단순하고 동일**해야 한다.
17. 학익형 자동 포위를 대치 교전의 기본 강제 동작으로 추가하지 않는다. **분할 포위**의 독립 목적을 흐리지 않는다.
18. 게임에 필요하지 않은 CG 시연 기능이나 대규모 신규 콘텐츠를 추가하지 않는다.
19. 아직 정해지지 않은 세부 수치와 규칙을 사용자 확정사항으로 표기하지 않는다.
20. **사용자 지정 좌표만 격자 교차점으로 제한**한다. 함선/포탄/자동 교전 목표/대형 슬롯을 명령 격자에 강제 스냅하지 않는다.
21. 동일 Y좌표의 적과 교전한다는 이유로 함선 Pitch/Roll을 **정책상 일률 금지하지 않는다**.
22. **이동 완료 후 활성 교전이 없는 대기**에서는 함대 기준 Pitch/Roll을 XZ 평면 기준으로 **부드럽게 수평 복귀**시키되 Yaw를 고정 방향으로 강제하지 않는다.
23. **교전 중 순간적으로 멈춘 상태**를 단순히 속도 0이라는 이유로 대기 취급하지 않는다.
24. 수평 복귀 중 대형 슬롯의 목표 월드 좌표가 움직여도 개별 함선이 **순간이동하거나 동일 Y 평면으로 평탄화되지 않도록** 한다.
25. 목표 입력 중 화면이 XZ→YZ/XY로 전환되더라도 종전 자유 카메라를 잃어버리지 않도록 한다.
