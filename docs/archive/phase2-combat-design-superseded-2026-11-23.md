## 보존: 공통 4.2~4.3절

### 4.2 모델·포탑과 시뮬레이션 동기화

함선 자세, 무장 각도·목표·재장전 및 발사체는 시뮬레이션이 소유하고 모델 계층은 장착 기준과 화면 표현을 제공한다. 모든 무장은 공통 절차를 사용하며 모델별 회전 축·범위, 동기화 그룹, 포구 및 접합 예외를 데이터로 적용한다. 고정포도 발사 안전 검사를 거치되 회전식으로 취급하지 않는다.

매 고정 틱에 함선 이동을 확정하고 같은 시점의 모든 무장 이동 후보를 구한다. 각도 제한 후 이동 경로와 도착 자세의 자기 구조·다른 가동 부품 간섭을 함께 검사하고, 충돌 시 정해진 우선순위 또는 정지로 결과를 결정한다. 확정한 자세의 행렬을 갱신해 포구별 위치·방향을 얻고 자기 형상과 아군이 막는 사선을 검사한 뒤 발사한다. 발사 후 이동하는 탄과 선체도 충돌 판정 대상이다.

접합 허용은 확인된 **부품 쌍과 국소 영역**에만 적용한다. 모델, 계층·피벗·스케일, 판정 코드 및 승인 설정이 바뀌면 사전 결과를 무효화한다. 검사 불가·정밀도 부족은 안전으로 변환하지 않고 이동이나 발사를 보류하는 초기안을 둔다. 정상 중립 자세와 사격 가능 여부는 별개다.

기존 `RigSafety.moveBatch`는 후보 검사 중 실제 노드에 임시 자세를 적용하고 복구한다. 게임 통합 시 독립 검사 모델 또는 소유권이 명확한 임시 적용·복구 절차를 사용해 렌더와 다른 판정이 미확정 자세를 읽지 않게 한다. 세분 표본과 단순 형상은 누락이나 과차단이 가능하므로 정밀도·범위·미검증 사례를 기록한다.

### 4.3 시간과 단계 전환

- 임시 고정 간격 `1/60초`; 렌더링은 별도 주기로 시뮬레이션을 읽는다. 긴 프레임의 누적 시간 처리와 최대 틱 수를 명시해 탭 비활성화나 저속 환경에서 무제한 따라잡기를 막는다. 제한으로 버린 시간은 시뮬레이션 시간을 진행한 것으로 간주하지 않는다.
- 매 틱: 생존 확인 → 조우·정책 → 함대 목표 → 슬롯 → 선체 이동 → 표적 배분·동시 무장 안전 검사·조준 → 포구별 사선 검사·발사 → 투사체 이동·피해 → 승패·타이머. 동시 격침과 시간 종료가 겹치는 우선순위는 구현 시 결정적 규칙과 테스트로 기록한다.
- `PREPARATION → RUNNING`: 유효한 명령만 반영하고 현재 상태에서 재개. 시간은 새 구간의 임시 기본값 30초로 설정한다.
- `RUNNING → PREPARATION`: 양측 생존 상태에서 시간 종료 시 모든 전투 상태를 그대로 정지한다. UI가 목표를 편집한다고 실제 위치가 이동하지 않는다.
- `RUNNING → VICTORY/DEFEAT`: v2.2에서 현재 보유 점수가 목표에 도달한 경우를 우선 처리한다. 전멸 자체는 승리 조건이 아니다. 전장·예비 함선과 구매 가능성을 모두 고려한 재기 불능 패배 및 양측 동시 점수 달성 처리의 상세는 단계 2 설계와 후속 경제 단계에서 구분한다.
- 준비 단계에서 진행 중인 교전의 명령을 편집할 때의 재개 규칙은 **미결**이다. 초기 구현 제안: 수정하지 않은 함대는 런타임을 보존하고, 수정된 함대의 기존 교전 처리와 새 명령 적용 시점은 별도 명시·검증한다. 이를 핑계로 모든 함대의 런타임을 일괄 초기화하지 않는다.


## 보존: 구 2단계 상세 설계

### 단계 2 — v2.2 전장·기본 전투·득점 설계

**상태: 상세 설계 및 부분 구현.** 실제 구현·검증 결과는 코드와 [이슈 #1 성능 조사](../investigations/issue-001-combat-performance.md)를 확인한다. 단계 1의 격자 목표 지정·함대 이동을 출발점으로, 전장과 기본 전투를 고정 틱에 연결하고 실제 생존 함선의 구역 우위를 점수로 계산한다. 적 전멸 즉시 승리는 구현하지 않는다. 이 단계의 목적은 **9개 구역과 점수 목표를 포함한 기본 전투 구간**이다. 구매·예비 함선·증원 및 적 AI 경제는 별도 후속 단계이며 이들이 연결되기 전의 단계 2를 v2.2 완성 게임으로 부르지 않는다.

**선행 점검:** 단계 1의 좌표·편성·준비/이동 전환과 기존 카메라 조작을 회귀 검증한다. 현재 시제품에는 체력·발사체·득점과 A/B/E 편성이 존재한다. 각 축 ±60의 임시 경계와 초기 배치의 부피·비겹침·대칭 인수 조건은 별도로 검증해야 한다. `rigging-test/`의 형상 검사에는 접합 후보·열린 메시·각도 표본·다수 함선 성능의 미검증 범위가 남아 있으며 이를 게임 내 안전 인증으로 간주하지 않는다.

| 순서 | 구현 단위 | 단계별로 확인할 결과 |
|---|---|---|
| 2-A | 전장 구성·초기 배치 | 유한 대칭 직육면체, 서로 마주 보는 시작 면, 겹치지 않는 내부 시작 배치. 경계·방향·형상 크기는 중앙 설정 |
| 2-B | 9개 구역 구성·시각화 | 떨어진 3×3 3D AABB, 가운데 행 3개 ×2, 나머지 ×1, 각 구역 내부의 유효 명령 격자점 확인 |
| 2-C | 공통 무장·안전 기반 | 대표 함선의 모델 계약, 동시 포탑 이동 검사, 포구·자기 구조 및 아군 차폐 검사 |
| 2-D | 기본 전투 | 체력·생존, 자동 표적 배분·조준·발사·투사체·피해·격침 |
| 2-E | 득점·현재 점수 승리 | 실제 생존 함선 수 차이·상한·배율을 고정 시뮬레이션 시간에 적용, 양측 동시 계산, 목표 점수 판정 |
| 2-F | 준비/자동 전투 반복·통합 | 위치·속도·자세·체력·무장·발사체·명령·점수·득점 틱 잔여 시간 보존, 준비 중 정지 및 같은 상태에서 재개 |

2-A/B와 무장 데이터 설계는 병행할 수 있다. 2-D는 2-C의 안전 판정과 실제 함선 상태를, 2-E는 2-D의 생존·위치를 사용한다. 2-F는 결과를 임의 초기화하지 않는 전환과 전체 흐름을 검증한다. 대표 모델의 검수 범위를 명시하고 검증되지 않은 무장은 발사를 보류한다. 미완성 기능은 비활성화하거나 미구현으로 명시한다.

#### 2.1 전장과 구역 데이터

- 전장 AABB는 중심에 대칭인 유한 직육면체다. 초기 제안은 길이축 Z, 아군 `+Z` 면·적군 `-Z` 면이며 축의 절대 부호는 기획 확정이 아니다. 중심·반쪽 크기와 시작 면·스폰 영역은 설정에서 하나의 기준으로 계산한다.
- 정확히 9개의 서로 떨어진 3D AABB를 XZ 상 3열×3행으로 배치한다. 중앙 **행** 3개만 `2`, 양측 인접 행 6개는 `1`이다. 각 구역은 유한한 Y 범위를 갖고 영구 소유권은 갖지 않는다. 명령 격자 교차점·실제 함선 위치와 별도 데이터다.
- 설정 로드 시 양의 전장·구역 크기, 구역의 전장 내부 포함, 구역 간 양의 간격, 9개 고유 ID·3×3 배치·3개 배율, **각 구역 내부의 유효한 격자 교차점 존재**를 검증한다. 실패 시 경고만 출력하고 잘못된 전투를 시작하지 않는다.
- 구역 경계에 대표점이 닿았을 때의 포함 규칙은 **양 끝 포함**을 초기 제안으로 사용하고 일관되게 테스트한다. 구역 간 양의 간격이 있으므로 경계 포함으로 두 구역에 동시에 포함돼서는 안 된다. 정확한 오차 정책은 설정/구현 시 기록한다.
- 기존 임시 전장과 함대 위치를 v2.2 구성으로 바꿀 때 현재 조작 상태를 실행 중에 갑자기 이동시키지 않는다. 새로운 시험 시나리오를 시작할 때 초기 배치만 구성한다. 함선 중심이 아니라 모델 부피·대형 크기·다른 함선과의 겹침 및 전장 내부를 검사하고 불가능한 배치는 실패로 보고한다. **현재 단순 중심 클램프는 안전 스폰의 증거가 아니다.**
- 전장 외곽과 9개 구역을 메인 화면과 선택된 XY/YZ/XZ 미니맵에 동일한 월드 데이터로 표시한다. 중앙 배율은 색 외에 `×2`로 구분한다. 구역의 함선 수와 순간 득점률은 선택/호버 시 보여주되 구역 클릭으로 새 `CAPTURE` 명령이나 소유권을 만들지 않는다.

#### 2.2 상태 소유와 준비/전투 전환

- `BattleState`는 함대·함선·발사체·구역 설정, 각 진영 현재 점수, 득점 틱 누적 시간, 남은 전투 구간 시간과 실행 상태의 권위 있는 소유자다. 미니맵·HUD·이펙트는 그 상태를 읽는다. 사용자가 정한 이동·교전 명령과 실행 중 런타임은 분리한다.
- 각 `Ship`은 안정적 ID·팀·함대 및 기존 슬롯 연결, 생존·체력·월드 위치·속도·선체 회전, 무장 배열을 갖는다. 격침 시 `alive=false`로 전투·득점 후보에서 즉시 제외하며 기존 슬롯을 임의로 재번호하지 않는다. 파괴 연출 수명은 별도 표현이다.
- 각 `Weapon`은 ID·종류(`TURRET`/`FIXED_FORWARD`)·장착 기준·사거리·실제 각도/회전 속도·재장전·대상 ID·피해·발사체 설정을 소유한다. 고정식·회전식은 실제 마운트/선체 변환을 적용한다. 포구마다 발사 가능 여부가 다를 수 있다.
- 각 `Projectile`은 고유 ID·진영·소유 함선/무장·이전/현재 위치·속도·반경·피해·잔여 수명을 보유한다. 시뮬레이션 상태와 이펙트 객체를 분리한다. 발사 후 소유 함선이 격침돼도 이미 발사된 탄은 명시된 수명/명중 규칙에 따라 진행한다는 **초기 구현 제안**을 테스트한다.
- 제한 시간 종료로 준비에 돌아가면 위치·속도·자세·체력·대상·조준·재장전·발사체·대형/조우 상태·명령·점수·득점 누적 시간을 보존한다. 준비 중에는 고정 틱이 진행되지 않고 발사·명중·득점도 없다. 화면 전환과 카메라 조작은 전투 시간을 소비하지 않는다.
- 재개 시 남은 탄·무장과 현재 명령에서 이어진다. 현재 시제품은 수동 정지 후 남은 구간 시간을 보존하고, 시간이 끝난 뒤 재개할 때 새 구간을 시작한다. 상세 정책과 검증은 2.9절을 따른다. 준비 중 명령을 바꾼 함대의 기존 교전 런타임 적용 시점은 상위 문서의 미결 항목이므로 이 단계에서 무단 확정하지 않는다. 단계 2에서는 명령 유지 사격의 범위로 제한하고 다른 대응은 미구현 표시한다.

#### 2.3 무장·조준·발사 및 피해

1. `OPPORTUNISTIC_FIRE`는 이동 목표·진로·대형을 유지한다. 유효한 적이 없으면 공격하지 않고 이동하며, 사격을 이유로 함대 기준점이나 목표 슬롯을 변경하지 않는다.
2. 각 무장은 살아 있는 다른 진영 함선 중 실제 3D 거리와 자신의 장착·사격각, 유효 상태를 만족하는 후보를 찾는다. 초기 배분은 유효 후보 + 대상 유지 보정 + 이미 배정한 예상 피해의 간단한 페널티로 시작한다. 함대 전체가 무조건 같은 최근접 표적만 공격하거나 일대일을 강제하지 않는다. 단계 4에서 세부 전술 가중치를 확장한다.
3. 회전식 포탑은 리깅된 피벗·포신 및 모델별 축·범위·회전 속도에 따라 독립적으로 목표 방향을 추종한다. 실제 도달한 각도가 발사 허용 오차 안에 있을 때만 발사한다. 고정식은 실제 선체·장착 방향의 아크로 판정하며 포탑처럼 자유 회전시키지 않는다.
4. 같은 고도의 적이나 정지 상태라는 이유로 활성 사격의 선체 Pitch/Roll을 일률 금지하지 않는다. `OPPORTUNISTIC_FIRE` 중 선체 조준 보정과 이동 방향의 우선순위·허용 범위는 미결이다. 이 단계에서는 임시 처리와 한계를 명시하고 목표/대형을 바꾸지 않으며, 선체 자세 보정의 완성 또는 모든 사각 확보를 주장하지 않는다.
5. 고정 틱의 선체·포탑·포신 자세를 적용한 후 월드 행렬을 갱신해 **해당 포구의 위치와 로컬 +Z 발사 방향**을 구한다. 화면의 보간된 자세나 이전 렌더 프레임 값을 명중 기준으로 삼지 않는다. 모델별 노드 방향이 실제 포신과 일치하는지 대표 함선을 시각 검수한다.
6. 재장전 완료 후 포구별로 자기 구조와 현재 아군 차폐를 검사한다. 발사체 폭과 시작 내부 겹침을 고려하고 차단·검사 불능이면 사격을 보류한다. 미래의 아군 진로를 발사 시점에 완벽히 예측하는 것은 아니다. 발사 후에도 이전→현재 이동 구간과 대상의 같은 틱 이동을 고려하며 가장 이른 충돌을 결정적으로 처리한다. 회전 형상과 근사 충돌체의 오차는 별도 검증한다.
7. 무장 이동은 4.2절의 공통 검사와 모델별 제한을 사용한다. 기존 검사기는 재사용 후보이며 게임에 이미 연결됐다는 뜻이 아니다. 아군 차폐 시 사격 보류는 이 계획의 제안이다. 이미 발사된 탄의 아군 충돌 시 피해 여부와 최초 충돌 처리 등은 상위 기획의 미결 항목이므로 구현 전에 결정한다. 검증되지 않은 부위나 검사 불가를 안전 통과로 취급하지 않는다.

8. 피해 적용으로 HP가 0 이하가 된 함선은 즉시 득점 집계와 다음 공격 후보에서 제외한다. 동일 틱의 다수 명중과 사격 순서는 이벤트 순서/동시 처리 정책을 구현 전에 정해 결정적으로 시험한다. 화면상 피격 연출만으로 피해를 계산하지 않는다.

#### 2.4 고정 틱 순서·득점·결과

```text
입력된 준비 명령 적용 / 이전 상태
→ 함대·함선 이동과 대형 슬롯 추종
→ 동일 틱 상태에서 표적 배분·무장 후보 자세 산출
→ 동시 이동 안전 검사와 확정 → 포구별 차폐 검사·발사 후보
→ 기존 투사체 구간 검사 → 동시 피해·격침 및 새 탄 생성 확정
→ 살아 있는 실제 함선의 구역별 3D 포함 집계
→ 득점 틱이면 모든 구역·양측 득점 동시 계산 및 합산
→ 현재 점수 목표 판정 → 재기 가능성 판정(경제 연결 후) → 구간 타이머
→ 화면은 확정된 상태 읽기
```

`scoreTickSeconds`는 렌더 FPS가 아니라 고정 시뮬레이션 시간의 누적으로 판단한다. 부분 득점 주기는 준비 중 고정하고 다음 구간에 이어가도록 제안한다. 한 고정 틱에 여러 득점 틱이 생길 가능성은 허용 설정과 처리 순서를 명시하고 유효성 검사한다. 예를 들어 `scoreTickSeconds >= fixedDelta`로 제한하거나 각 틱을 누락 없이 처리하는 방법 중 구현 시 하나를 정해 시험한다.

각 구역에서 같은 시점의 살아 있는 실제 함선 대표점으로 `P`와 `E`를 집계한다. `d = clamp(P-E,-C,C)`에서 `player += b*w*max(d,0)`, `enemy += b*w*max(-d,0)`를 각 구역에 독립 적용해 양측 합계를 동시에 반영한다. 개별 진영 수를 상한으로 먼저 자르지 않는다. 임시 테스트 값은 `C=3`, `b=1`, `scoreTickSeconds=1초`를 사용할 수 있으며 확정 밸런스가 아니다. 구역 안의 함대 기준점이나 슬롯만으로 득점하지 않는다.

득점 적용 후 **현재 보유 점수**가 목표에 도달하면 결과를 확정한다. 양측 동시 달성은 높은 현재 점수 우선, 동점 무승부를 임시안으로 둔다. 목표 점수·틱 주기·우위 상한·기본 점수는 설정값이며, 값과 단위는 테스트 결과와 함께 기록한다. 상대 전멸 자체는 승리 조건이 아니다(Z16). 구형 T17은 적 전멸 즉시 승리가 아니라 최신 v2.2 결과로 대체한다.

**중간 단계 제약:** 구매·예비 함선·증원과 재기 가능성 데이터가 아직 없을 때는 임의로 구매 불가능하다고 간주해 패배/승리시키지 않는다. 득점 목표가 달성되지 않은 전멸 상황은 미완성 경제 기능으로 인해 종료 규칙이 완성되지 않았음을 개발 화면에 표시하고, 해당 동작을 최종 게임 규칙으로 보고하지 않는다. 단계 2에서 정식 전멸/교착 결과까지 완료하려면 다음 경제 단계의 실제 보유·구매 가능성 데이터와 함께 구현·검증해야 한다.

#### 2.5 초기 UI와 설정

- 기존 메인·미니맵·함대 관리 창을 유지한다. 구역 9개의 경계·배율, 선택 구역의 양측 생존 수와 현재 득점 방향/속도, 양측 현재 점수/목표 점수, 제한 시간과 함선 체력·생존을 상태에 맞게 표시한다. 미니맵 평면을 바꿔도 같은 실제 구역과 함선 데이터를 투영한다.
- 준비 단계에서 기존 3D 격자 지점 지정·편성·함선 순서와 간격 단계를 사용한다. 전투 중 관람·선택은 허용하되 전술 편집과 구매는 막는다. 점수·체력은 정보 표시이며 숫자를 입력하도록 요구하지 않는다.
- 구역 선택 후 내부 격자점 제안은 **선택적 단축 UX**다. 구현하지 않아도 기본 2단계 목표 입력은 유지한다. 제안한다면 후보가 구역 내부에 있음을 검증하고 자동으로 새 점령 정책을 만들지 않는다.
- 밸런스 미결값: 전장/구역 크기와 간격, 시작 함선 수, 구역 Y 높이, 무장별 사거리·각도·탄속·데미지·재장전, HP, 목표 점수. 고정 틱 `1/60초`, 전투 구간 `30초`는 현재 프로토타입 기준의 임시값이다. 실제 값은 설정과 표시·시험 기록을 통해 조정한다.

#### 2.7 상세 설계의 범위와 구현 전제

이 절부터 2.14절까지는 2단계 구현을 위한 **제안 계약**이다. 상위 기획의 확정 규칙과 구분하며 임시 수치·충돌 근사는 실제 FBX와 시험 결과로 조정한다. 2단계에서는 MOVE + 명령 유지 사격과 양측 같은 무장·득점 규칙을 연결한다. 구매·증원·재기 불능 패배와 다른 교전 대응은 만들지 않는다. 적은 사전에 설정된 목적지와 같은 이동·사격 규칙을 사용한다. 게임 규칙을 위장한 적 AI의 숨은 보정은 없다.

**구현 선행 조건:** 1단계 회귀와 대표 FBX의 축·포구·고정/가동 무장 및 접합 검수를 먼저 확인한다. 발사 안전이 검증되지 않은 포구는 차단하고 사유를 진단한다. 2단계 초기 장면은 대표 모델과 단순 실탄을 기준으로 하며 빔·유도탄·곡선 탄도, 여러 함종의 완전 검수는 범위 밖이다.

| TickSnapshot / events | 이전·현재 선체 자세, 무장 후보, 포구 자세, 발사·명중·피해와 차단 사유 | 한 고정 틱 내 임시 자료. 확정 결과만 UI·렌더에 노출하고 다음 틱에 재사용하지 않는다. |

거리는 월드 단위, 시간은 시뮬레이션 초, 각도는 모듈 경계에서 단위를 명시한다. 리깅 검사기의 각도 단위와 게임 내부 단위를 혼용하지 않는다. ID와 팀은 참조 시 검증하며 객체 배열에서의 인덱스를 영구 ID로 쓰지 않는다. 같은 FBX의 여러 인스턴스는 자세와 검사 상태를 공유하지 않는다.

**격침과 슬롯:** 현재 `slots(f)`는 `f.ships.length`로 전체 격자를 다시 만든다. 죽은 함선을 즉시 배열에서 빼면 생존 함선의 슬롯이 바뀐다. 2단계에서는 전투 중 편성 순서와 슬롯 식별자를 보존하고 죽은 함선 슬롯을 빈 상태로 취급한다. 이동·회피·표적·득점은 살아 있는 함선만 사용한다. 화면 목록에서 격침 표시와 슬롯 유지는 별개다. 준비 단계에서 사용자가 편성을 수정했을 때의 슬롯 재계산은 명시적 명령으로만 처리하고 회귀 시험한다.

#### 2.9 고정 틱·사건 순서와 준비 전환

다음은 구현·검증에 사용할 초기안이다. 순서를 바꾼다면 사격 동시성과 득점 결과를 함께 재검증한다.

1. RUNNING이 아니면 시뮬레이션을 실행하지 않는다. 시작 직전 유효 명령·설정을 확인하고 기존 명령과 탄, HP, 재장전, 점수 누적분을 보존한다.
2. 틱 시작의 생존 함선과 자세, 기존 탄 목록을 스냅샷으로 고정한다. 함대 기준점과 함선의 이동을 계산·확정하고 시작/끝 자세를 보관한다. 죽은 함선은 이동·회피 후보에서 제외한다.
3. 틱 시작에 살아 있던 무장의 쿨다운을 고정 dt만큼 줄인다. 끝 위치 기준으로 유효 적 후보를 만들고 표적을 배분한다. 선체의 함대 목표를 변경하지 않는다.
4. 각 함선의 모든 무장에 대해 회전 속도·각도와 동기화 제약을 적용한 후보를 함께 계산하고 자기 형상과 가동 부품의 이동 안전을 확인한다. 안전한 자세를 확정하고 월드 행렬을 갱신한다.
5. 확정한 포구별 사거리·조준 오차·쿨다운·사선·안전 상태를 검사해 발사 후보를 만든다. 이 후보는 틱 끝에 생성되며 **생성된 틱에는 이동하지 않는다**. 다중 포구의 발사 간격과 쿨다운 공유 여부는 무장 프로필에 명시한다.
6. 틱 시작에 이미 존재하던 탄만 시작→끝 구간으로 전진시킨다. 선체의 시작→끝 평행 이동을 반영한 상대 운동으로 충돌 시점을 구하고 가장 이른 충돌을 고른다. 충돌이 수명 만료 시점보다 늦으면 수명 만료가 우선한다. 선체 회전·포탑 움직임에 대한 형상 검사는 근사 범위와 누락 위험을 따로 기록한다.
7. 같은 틱의 명중은 틱 시작 생존 상태에 대해 결정하고, 정렬된 명중 이벤트의 피해를 대상별로 합산해 한 번에 적용한다. 따라서 같은 틱 다수 탄은 동시에 같은 함선에 명중할 수 있으며, 틱 중 격침된 공격자도 5번에서 확정한 사격을 수행한다는 동시 처리 임시안이다. 이때 생성된 탄은 소유자 사망과 무관하게 다음 틱부터 진행한다. 차단된 사격은 쿨다운을 소모하지 않는다.
8. HP·격침·탄 제거와 새 탄 생성을 확정한다. 득점 시각이면 확정 후 생존 함선의 위치를 집계해 양측 득점을 동시에 반영하고 현재 점수 승패를 확정한다. 점수 승리와 구간 종료가 같은 틱이면 승리가 우선이다. 이 단계에서는 재기 불능을 추측하지 않는다.
9. 결과가 없으면 구간 남은 시간을 줄이고 0이면 PREPARATION으로 전환한다. 결과가 있으면 결과 상태를 유지한다. 화면에는 확정 상태와 사건만 반영한다.

수명은 시작 시 양수이며 잔여 수명보다 긴 틱에는 그만큼만 이동한다. 다만 상대 선체도 **같은 시간 비율**까지만 보간해 판정한다. 충돌 동률은 충돌 시간 오차 정책을 정한 뒤 고정 우선순위(자기/아군 구조, 적 함선, 그 외)와 안정 ID로 결정한다. 수치 오차와 우선순위는 테스트 설정에 기록한다. 생존·피격의 동시 규칙은 단계 3 이후 변경 시 구매·승패 테스트까지 재확인한다.

현재 `start()`는 매번 30초를 재설정하고 일시정지 버튼은 즉시 준비로 전환한다. **구간 종료 후 재개**와 **수동 정지 후 재개**를 같은 동작으로 취급할지는 미결이다. 초기 제안은 수동 정지에서 남은 구간 시간을 보존하고 구간 종료 후에만 새 30초를 부여하는 것이다. 기존 UI 의미가 바뀌므로 구현 시 명시하고 테스트한다. 렌더 누적 시간은 준비 전환 때 비우되 점수 주기의 시뮬레이션 누적분은 보존한다.

#### 2.10 전장·구역의 계산 계약

- 전장과 9개 구역은 각각 유한 AABB다. 모든 축의 min < max, 구역 간 비접촉 및 전장 내부 포함을 검증한다. 시작 영역은 대칭 반대쪽 면의 안쪽으로 지정하고 함선 충돌체 전체가 전장 안에 있어야 한다. 대표 시나리오의 함선 수·배치와 좌표는 설정값이며 실패 시 전투 시작을 거부한다.
- 각 축의 구역 내부 격자점 검증은 `ceil((min-origin)/spacing) ≤ floor((max-origin)/spacing)`를 사용한다. 경계 포함과 부동소수점 허용 오차를 한 곳에 정의한다. 실제 격자점이 전장 내부인지도 검증한다.
- 명령 격자·득점 영역·충돌 후보 탐색 영역은 서로 다른 개념이다. 9개 구역 각각에 대해 살아 있고 전장에 배치된 함선 중심만 세며, Y 범위와 경계 규칙을 동일하게 적용한다. 격침 애니메이션의 잔해와 대기 중인 탄은 득점하지 않는다.
- 점수 주기는 `scoreTickProgress += dt` 후 주기마다 차감한다. 첫 구현에서는 `scoreTickSeconds`를 고정 dt의 양의 정수 배수로 제한해 주기를 틱 정수로 관리하는 안을 사용한다. 설정 불일치는 반올림하지 않고 오류로 표시한다. 향후 임의 주기 지원은 별도 검증한다.
- 각 구역의 동일 스냅샷에서 `d=clamp(P-E,-C,C)`, 각 진영 획득량은 `b×배율×max(±d,0)`이다. 모든 구역의 합을 계산한 후 양측 잔액을 동시에 갱신한다. 두 진영이 동시에 목표에 도달하면 높은 현재 점수, 동점 무승부는 v2.2의 권장 임시안이다.

#### 2.11 표적 배분·회전 및 발사 안전

1. 초기 기준 구현은 각 함대의 무장 사거리와 함선 충돌체 크기를 보수적으로 포함한 적 후보를 한 번 수집하고 안정 ID 순으로 정렬한다. 각 무장은 실제 3D 거리·살아 있음·팀·마운트 가능 각도 등으로 다시 필터한다. 함대 범위 계산이 어렵거나 누락 가능하면 전수 검색을 사용한다. 상위 N명만 자르거나 득점 구역을 검색 셀로 사용하지 않는다.
2. 후보 점수의 초기 예시는 유효 거리, 기존 표적 유지 보너스, 이미 다른 무장이 할당한 예상 피해에 대한 페널티다. 배정은 안정 무장 ID 순서로 수행하고 같으면 표적 ID로 결정한다. 배정된 목표가 실제 발사 가능하다는 뜻은 아니며, 차폐·정렬 실패가 생겨도 무장마다 검사한다. 가중치와 단위는 임시 설정으로 기록한다.
3. 축·각도는 모델 로컬 좌표로 변환해 계산한다. 고정식은 선체와 장착 방향으로만 사격하고 회전식은 속도 제한을 적용해 실제 도달 각도를 유지한다. 선체 조준 보정은 미결이므로 2단계에서 무장 때문에 함대 목적지나 대형을 바꾸지 않는다. 개별 선체 Pitch/Roll을 영구 금지하는 규칙도 신설하지 않는다.
4. 검사 결과는 `CLEAR / BLOCKED / UNKNOWN`과 사유·검사 틱으로 구분한다. 미검증 모델, 누락 노드, 해시 불일치, 정밀도 예산 초과, 무효 변환은 UNKNOWN으로 보고 이동/발사를 보류한다. 차단된 무장은 현재 자세를 보존하거나 검사기가 실제 확인한 연결된 안전 자세까지만 이동한다. 기존 `moveBatch`는 마지막 안전 표본으로 노드를 남기므로 단순 불리언 검사가 아니다.
5. 검사용 모델을 별도로 두는 방식을 우선 검토한다. 공유 노드를 쓴다면 한 틱의 유일한 쓰기 책임자가 후보 적용→검사→안전 자세 확정 또는 복구를 동기적으로 수행하며, 예외 발생 시에도 원상 복구해야 한다. 렌더나 다른 무장 판정이 중간 노드를 읽지 못하게 한다. 포구 월드 자세는 확정 직후에만 추출한다.
6. 포구가 자기 구조 내부이거나 자기 선체·가동 무장 또는 아군 충돌체가 목표까지의 사선을 막으면 발사 보류한다. 탄 반지름과 최초 출구를 포함한다. 아군이 적 뒤에 있을 때는 적까지의 경로로 차폐를 판단한다. 적 앞의 다른 적을 명중시키는 것은 투사체 최초 충돌 규칙을 따른다. 이미 발사한 탄의 아군 피해 여부는 미결이며 테스트용 임시 규칙을 명시한 뒤 구현한다.

**접합:** 포신과 포탑의 정상 삽입은 지정된 부품 쌍·국소 영역에서만 허용하고 같은 영역의 선체나 다른 포탑은 면제하지 않는다. 경순01·구축함01의 사용자 확인 중립 자세는 다른 각도나 다른 함선의 무관통 승인으로 확대하지 않는다. 표본 검사와 열린 메시 판정의 한계가 남으므로 CLEAR도 명시한 검사 범위 내 결과다.

#### 2.12 투사체·피해·효과 연결

- 초기 탄은 직선 이동하는 구형 투사체다. 시각 크기와 판정 반경을 같은 설정에서 가져오고, 첫 출구 검사 및 비행 중 충돌에 반영한다. 충돌체가 화면 메시의 정확한 외곽을 대표하지 않으므로 모델별 피격 형상과 오차를 검수한다.
- 선체의 초기 피격 형상은 모델 치수에 맞춘 구 또는 캡슐을 제안한다. 구형 기준 상대 선분 대 구 교차는 시작 겹침, 영속 정지, 접선, 양 끝점, 고속 통과를 처리한다. 캡슐이나 회전 몸체는 별도 구현과 검증을 요구한다. 단순 충돌체의 모든 공백을 메시로 보완했다고 가정하지 않는다.
- 탄별 가장 이른 충돌 대상이 자기 구조·아군이면 해당 충돌을 관통해 적에게 피해를 주지 않는다. 피해 여부는 미결; 첫 임시 테스트의 정책을 환경 설정과 결과에 명시한다. 적에게 명중하면 피해 이벤트를 만들고 탄은 한 번만 소비한다. 탄이 전장 밖인지 또는 사정거리·수명이 끝났는지는 충돌 순서와 동일 기준으로 검사한다.
- 이펙트는 확정된 발사·명중·격침 이벤트를 읽어 표시한다. 포구 화염·엔진 효과와 사운드 유무가 사격·피해·득점에 영향을 주지 않는다. 이벤트 소진과 화면 객체 제거는 시뮬레이션의 탄 생존 상태를 바꾸지 않는다.

파일 분리는 구현 시 결정한다. `rigging-test/`의 원본을 일방적으로 이동하거나 중복 개조하지 않으며 의존성·자산 경로·변경 중인 작업을 확인한다. 기존 검사기는 three.js 객체에 의존하므로 순수 계산 테스트와 실제 FBX 브라우저 검증을 구분한다. 외부 `three-mesh-bvh`는 라이브러리 기여로 표기한다.

#### 2.14 상세 검증 및 성능 기준

성능은 구현 전후에 동일한 함선 수·무장 수·발사체 수, 카메라·모델, 브라우저/기기와 실행 시간을 기록하고 고정 틱 평균·상위 지연, 렌더 프레임 및 후보/정밀 검사 수를 측정한다. 먼저 전수 검색 결과를 기준으로 삼고 공간 해시를 도입한다면 충돌·표적 후보 누락과 결과 차이를 비교한다. 수치 목표는 측정 환경과 예산을 정한 후 확정하며, 실측 없이 대규모 함대 성능을 약속하지 않는다. W08 변환 합성 및 W10 경계·교차 계산은 직접 작성 범위와 three.js 비교 결과를 분리해 기록한다.
