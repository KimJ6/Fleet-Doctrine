## UI 개선 반영 — 2026-11-24

이 절은 아래 단계 0의 과거 배치·목적지 입력 중 이동 제한보다 우선한다. 기존 게임 규칙과 준비/전투 전환은 유지한다.

- 하단 왼쪽 미니맵, 중앙 함대 탭·선택 함대 명령·높이별 편성, 오른쪽 전투 시작/준비 전환으로 구성한다. 이동·전술·목적지는 선택 함대에, 전투 버튼은 전체 전투에 적용한다. 함대 탭·전장·미니맵의 선택은 공유한다.
- 함선 카드는 로컬 슬롯 Y 내림차순으로 줄을 나누고 각 높이의 기존 슬롯 순서를 유지한다. 함선 간 드래그 또는 두 번 클릭은 두 슬롯을 교환한다. 함대 탭으로 드래그하거나 카드를 선택 후 탭을 클릭하면 함대 간 이동한다. 격침된 슬롯은 빈 슬롯으로 표시한다. 준비 단계에서만 편집하며 이동은 실제 선체를 순간이동시키지 않는다.
- 목적지 XZ→YZ 두 단계에서 WASD와 왼쪽 드래그는 화면 이동, 클릭은 선택, 휠은 확대·축소, Esc는 취소다. XZ의 이동 중심은 이전 단계로 돌아갈 때 복원한다. 중간 입력은 기존 명령을 바꾸지 않고 완료/취소 시 일반 카메라를 복원한다. 일반 카메라 줌 거리 4~160, 입력 줌 1.25~8은 가독성 확인용 임시값이다.
- 입력 중에는 함대 선택과 전투 시작을 잠근다. 보조 설명은 정보 버튼에 두고 상태·오류는 표시한다. 순찰과 미구현 전술은 선택 불가로 표기한다.
- Edge 헤드리스·실제 경순01 모델에서 높이 간 드래그/클릭 교환, 탭 간 이동, 입력 양 단계의 키보드 이동, 드래그와 클릭 구분, 줌 제한, 이전/취소 시 카메라·목적지 보존, 시작/정지 및 체력 갱신을 확인했다. 600px 폭에서 미니맵과 함대 패널 경계가 겹치지 않음을 확인했다. 전 범위 반응형·시각 검수, 다른 함종과 전체 플레이 회귀는 별도다.

## UI 조작 보완 — 2026-11-24

함대 탭의 +는 준비 중 선택 함대의 기준점과 명령을 참고한 **빈 편성 초안**을 하나 만든다. 다른 탭으로 이동해 함선을 드래그/선택 이동할 수 있도록 초안은 즉시 자동 삭제하지 않는다. 초안은 함선이 없으면 미니맵에 활성 함대로 그리지 않고, 배정된 예비 함선도 없는 빈 초안은 전투 시작 시 정리한다. 기존 함대의 마지막 생존 함선을 옮겨 비면 해당 함대를 즉시 제거하고 대상 함대를 선택한다. 삭제된 함대로 예정된 예비는 미배정 보유 상태로 되돌린다.

간격은 축별 좁게/보통/넓게 라디오형 버튼이며 미구현 이동·전술은 현재 정책의 읽기 표시다. 함선 구매·예비는 오른쪽 전투 시작 위 세로 메뉴로 이동했다. 미니맵과 하단 함대 창은 열린 상태에서 높이와 상·하단을 맞추고, 360/600/900/1280px 폭의 요소 경계·함선 영역·시작 버튼을 브라우저에서 확인했다. 줌은 일반 화면의 카메라-관찰점 거리와 입력 화면의 직교 줌 배율을 개발용으로 표시한다. 정규 및 입력 화면의 줌 값은 단위가 다르다.

브라우저에서 함대 추가→기존 함대의 네 척을 옮겨 마지막 함선 이동 시 원래 함대가 삭제되는 흐름, 간격 버튼, 구매 버튼 위치, 줌 표시 전환을 확인했다. 외부 모듈 로딩을 의도적으로 실패시킨 시험에서 오류 안내가 표시됨을 확인했다. 전체 입력·다른 화면/플랫폼의 시각 검수는 별도다.

## 1. 목표와 구현 전략

플레이어는 유한한 3차원 전장에서 함대를 지휘해 9개 득점 구역의 병력 우위를 확보하고, 현재 점수를 승리에 보유할지 함선 구매·증원에 사용할지 판단한다. 일정 시간 자동 전투 뒤 상태와 기존 명령을 유지하며 필요한 설정을 수정한다. 적 전멸만으로 승리하지 않는다.

**첫 목표는 실제로 반복 가능한 전투 구간 하나다.** 먼저 목적지 이동·이동 격자·명령 유지 사격·피해·격침과 준비 복귀를 연결한다. 이후 점수 경제와 양측 증원을 연결하고 순찰과 교전 대응을 하나씩 추가한다. UI와 검증용 표시는 해당 기능을 확인하는 데 필요한 시점에 함께 만든다.

전체 기획 목표는 이동 명령 2종과 교전 대응 5종이다. 아래의 수직 슬라이스는 일정상 우선순위이지 나머지 확정 기획의 삭제나 더미 정책으로의 대체를 의미하지 않는다. 완성되지 않은 기능은 UI에서 선택 불가 또는 미구현으로 표시한다.

## 2. 기획에서 유지할 불변식

1. 이동 명령은 **목적지 이동(MOVE)**, **경로 순찰(PATROL)** 두 가지다. 교전 대응은 **명령 유지 사격(OPPORTUNISTIC_FIRE)**, **거리 유지 교전(STANDOFF)**, **진형 관통(BREAKTHROUGH)**, **분할 포위(ENCIRCLE)**, **거점 방어(POINT_DEFENSE)** 다섯 가지다.
2. 대형은 선택한 이동 명령·교전 대응에 종속된다. 플레이어가 대형 크기와 함선 순서를 조절할 수 있지만 별도의 세 번째 주 명령으로 선택하지 않는다.
3. 명령 유지 사격은 이동 목표·경로·대형을 바꾸지 않는다. 다른 대응은 조우 시 이동 명령에 우선하며, 종료 후 보존한 임무로 복귀한다.
4. 사용자 지정 목적지·순찰 경유점·방어 거점은 명령용 3D 격자 **교차점**이다. 실제 함대·함선·슬롯·발사체 및 자동 전술 목표는 연속 X/Y/Z 공간에서 처리한다. 월드 +Y는 위, 함선 게임 로컬 +Z는 전방이다. FBX 원래 축과 크기는 모델 어댑터에서 변환한다.
5. 대형 전환은 목표 슬롯을 바꾸며 실제 함선은 이동·선회 제한을 따른다. 사격 때문에 개별 함선이 전술적 목표를 무단 변경하지 않는다.
6. 준비 단계는 시뮬레이션 정지다. 위치·회전·속도·체력·재장전·발사체·대형 전환·조우 진행과 기존 명령을 보존한다. 결과 및 승패 판정은 시뮬레이션이 소유한다.
7. 회전식 포탑과 전방 고정식 무장의 사격 범위를 구분한다. 표적 배분은 무조건 단일 표적 집중이나 강제 1:1을 요구하지 않는다.
8. 회피와 카이팅을 독립 교전 대응으로 추가하지 않는다. 전투 중 조작은 관람과 정보 확인을 우선하고 명령 변경은 준비 단계에서 수행한다.
9. 목표 입력 시작 시 XZ 직교 화면에서 X/Z를 선택하고, YZ 또는 XY 직교 화면에서 Y만 선택해 격자점을 확정한다. 확정 전에는 명령을 변경하지 않는다.
10. 함대 기준 자세와 개별 선체 조준 자세를 분리한다. 활성 교전 중 Pitch/Roll을 일률적으로 금지하지 않는다. 이동 완료 후 활성 교전이 없는 대기에는 기존 유효 수평 방향을 보존하며 자세를 부드럽게 수평 복귀시킨다.

## 3. 현재 기반과 전제

- `web/`은 three.js 기반 게임 프로토타입이다. 목적지의 2단계 격자 입력, 함대 편성·순서 및 단계형 간격, 카메라와 고정 틱 이동이 코드에 존재한다. 인수 조건의 통과 여부는 별도 확인해야 한다.
- 전투용 체력·무장·발사체·구역 득점·점수 경제는 완성 게임으로 연결되지 않았다. 기존 임시 전장과 초기 편성을 v2.2 대칭 배치로 검증된 것으로 취급하지 않는다.
- `rigging-test/`는 분리된 검사 도구다. 공통 제어·형상 검사와 분석 자료는 재사용 후보이나 열린 메시·표본 사이 간섭·추정 접합·다수 함선 비용에 한계가 있다. 특정 FBX의 중립 자세 확인을 모든 자세의 승인으로 확대하지 않는다.
- 10종 리깅 FBX는 저장소 외부 `../ship assets/rigged/`에 있다. 자산·라이선스와 실행 경로는 [프로젝트 안내](../../README.md)를 따른다.
- 아래 0~1단계의 상세 문구는 당시 설계 기록이다. 숫자 입력 등 과거 상태를 기술한 부분보다 현재 소스와 이 절의 현황이 우선하며, 브라우저 조작과 회귀 테스트 전 완전 통과로 간주하지 않는다.

### 3.1 2단계 선행 확인

기존 좌표 입력과 카메라 복원, 함대 순서·간격, 이동·도착, 준비 정지/재개를 회귀 확인한다. 기존 사용자 작업을 보존한다. 함선 근접 완화는 무충돌 보증이 아니며 새 전장 배치는 기존 실행 중 상태를 바꾸지 않고 새 시험 시나리오에서 시작한다.

## 4. 책임과 데이터 경계

아래는 논리적 모듈이며, 파일 단위는 구현 착수 시 변경 가능하다. 게임 데이터는 ID로 참조하고, 렌더링 객체는 게임 상태의 대체 원본이 되지 않는다.

|---|---|---|---|
| 전투 흐름 | 시작·시간 종료·격침 | 준비/실행/승리/패배, 타이머 | UI가 체력이나 승패를 직접 확정 |
| 편성·명령 | 함대/함선 선택, 준비 입력 | 소속, 순서, 격자 인덱스 기반 이동 명령, 교전 대응 | 임의 슬롯 재정렬 또는 독립 대형 명령 |
| 명령 격자·입력 | 격자 원점·간격, 직교 뷰의 클릭 | 정수 격자 인덱스, 월드 변환, 미확정 draft | 함선이나 대형 슬롯을 명령 격자에 강제 스냅 |
| 함대 자세 | 이동·교전·대기 의도, 현재 기준 자세 | 목표 자세와 마지막 유효 수평 방향 | 속도 0만으로 대기 판정, 선체 조준으로 슬롯 방향 변경 |
| 조우 제어 | 함대 상태, 적 후보 | 접촉·대상 잠금·정책 단계·복귀 | 개별 무장이 함대 목표를 덮어쓰기 |
| 대형·함대 이동 | 명령, 정책 단계, 대형 설정 | 기준점·자세 및 함선별 목표 슬롯 | 함선 실제 위치의 순간이동 |

| 무장·배분 | 함선·무장·유효 적 상태 | 무장별 표적, 조준, 재장전, 발사 이벤트 | 무장 사격을 위해 선체 진행 방향을 무제한 변경 |
| 공격·피해 | 발사 이벤트, 전투 상태 | 사선 결과, 함선의 피해·체력·격침 | 렌더링 이펙트의 존재를 명중 근거로 사용 |
| 에셋 어댑터 | 모델 식별자·시뮬레이션 자세 | FBX 계층, 축 보정, 피벗과 기준점 변환 | FBX 크기나 로컬 축을 게임 전체 규약으로 유출 |
| 카메라·준비 UI | 상태 읽기, 플레이어 입력 | 검증된 명령 변경 요청·표시 | 임의로 전투 상태를 직접 변조 |

### 4.1 데이터 소유권

- `BattleState`: 현재 단계·시뮬레이션 시간·남은 구간 시간·함대·함선·발사체. 상태 전환과 승패 판정의 단일 기준이다.
- `FleetCommand`: 사용자가 정한 이동 정책, 정수 `GridPoint3` 목적지/경유점, 교전 대응, 사용자 지정 격자 거점 및 대형 크기. `EncounterRuntime`은 현재 대상·활성 단계·정책별 진행 기록을 별도로 보유한다. 자동 도출 거점은 사용자 격자 입력과 구분한다.
- `CommandGrid`와 `PositionDraft`: 격자 원점·양의 간격, 별도로 정의된 유한 전장 경계, 그리고 XZ/Y 선택 중인 임시 인덱스와 카메라 복구 정보. `gridToWorld`로 명령을 연속 월드 목표로 변환하며 확정 전 명령을 변경하지 않는다.
- `Fleet`: 팀, 순서가 있는 함선 ID, 기준 위치·자세, 마지막 유효 수평 방향, 현재 대형과 목표 슬롯. 자세 의도는 이동·활성 교전·대기를 구분한다. 함선 격침 후 기본적으로 기존 슬롯은 비워 둔다.
- `Ship`: 소속·생존·위치·속도·회전·체력과 무장 상태. 게임 논리는 장식용 메시의 경계나 현재 화면 픽셀을 진실로 사용하지 않는다.
- `Weapon`: 유형·장착 기준·사거리·회전 제한·속도·재장전·대상·현재 조준 상태. 발사체 생성에 필요한 포구 변환은 다음 절의 동기화 규칙을 따른다.
- `AttackEvent` / `DamageEvent`: 발사·피해의 권위 사건과 수신 함선을 구분한다. 시각 탄은 별도 표시이며 착탄 시간 모델은 미결이다.

### 4.2 모델·무장과 시뮬레이션 동기화

함선·무장 및 포구의 권위 좌표와 상태는 시뮬레이션 데이터가 소유하고 화면 객체는 표시한다. 장착 좌표, 각도 제한, 후보 탐색과 모델 표시의 연결은 [2단계 상세 재설계](phase2-data-oriented-combat-design.md)를 따른다. 기존 UI·카메라와 리깅 자산은 어댑터를 통해 재사용한다.

### 4.3 시간과 단계 전환

준비 중 시뮬레이션은 정지하고 확정된 명령·상태를 보존한다. 고정 틱의 공간 인덱스·사선·피해·득점 순서 및 동시 사건 처리는 [2단계 상세 재설계](phase2-data-oriented-combat-design.md)의 시간 계약을 따른다. 발사 즉시 판정은 시제품 가정이며 실제 착탄 시간의 최종 규칙은 미결이다.

## 5. 구현 단계와 완료 기준

### 단계 0 — UI·카메라 설계와 게임 기반

**작업:** 아래 0단계 UI 설계로 화면 구성과 조작 흐름을 먼저 검토한다. 구현 시 게임 진입점을 리깅 테스트와 분리하고 게임 상태·고정 틱·렌더러와 카메라를 구성한다. 대표 함선의 FBX를 복제 배치하고 크기·중심·축을 정규화한다. 빠진 에셋·노드 오류를 알아볼 수 있게 표시한다. UI 설계와 자리 배치는 전체 전투 기능 구현을 뜻하지 않는다.

**검증:** 준비 상태에서 시간과 변환이 정지한다. 동일 함선 여러 개의 포탑 자세가 서로 독립적이다. 모델 보정 후 게임 로컬 +Z 전방과 포구 +Z가 의도한 방향인지 화면과 좌표로 확인한다. 로딩 성공과 외관 검수를 분리해 기록한다.

#### 0.1 화면 구성안

아래 배치는 **데스크톱 초기 시안**이다. 배치와 수치는 실제 화면 검증 후 조정하며, 아직 구현 완료나 최종 비주얼 확정을 뜻하지 않는다. 축약된 화면에서도 메인 전장과 명령 취소·확정의 접근성을 유지한다.

```text
┌──────────────────────────────────────────────────────────────────┐
│ [준비 / 전투 상태]        메인 3D 전장             [XY] [YZ] [XZ] │
│ ┌─ 함대 관리 ──────┐                              ┌─ 미니맵 ─────┐ │
│ │ 함대 목록 / 선택  │                              │ [XY][YZ][XZ] │ │
│ │ 편성 및 함선 순서 │          선택 함대           │    직교 뷰   │ │
│ │ 이동 명령·목표    │        / 목표·경로          │  축·선택 표시 │ │
│ │ 교전 대응·대형    │                              └──────────────┘ │
│ │ [준비 완료]       │                                               │
│ └──────────────────┘      조작 / 입력 단계 안내                     │
└──────────────────────────────────────────────────────────────────┘
```

| 영역 | 책임 | 0단계 설계 범위 |
|---|---|---|
| 메인 전장 | 자유 관람과 3D 상황 표시; 목표 입력 시 주 작업 뷰 | 카메라 조작, 축 방향 버튼, 선택 표시 및 입력 모드 전환의 상호작용 정의 |
| 미니맵 | 전장의 한 직교 평면과 공유 선택 상태 표시 | XY/YZ/XZ 중 하나 선택, 축·팀·선택 상태·목표 표시 원칙 |
| 함대 관리 창 | 선택 함대 편성·이동 명령·교전 대응·대형 관련 입력 | 목록과 상세 창의 구조, 단계별 편집 가능 상태·미구현 표시 |
| 상태 및 안내 | 준비/전투/결과, 시간, 현재 입력 단계와 오류 | 입력 흐름과 취소·복귀를 발견할 수 있게 표시 |

레이아웃은 함대 창·미니맵을 접거나 크기를 제한해 작은 화면에서 전장과 버튼이 겹치지 않도록 한다. 좁은 화면에서의 구체적 배치는 반응형 검증 후 결정한다. 한 캔버스 다중 뷰포트 또는 보조 캔버스는 렌더링 구현 선택이며 UI 규칙을 바꾸지 않는다.

#### 0.2 메인 카메라와 평면 방향 버튼

| 입력 | 관람 모드의 동작 |
|---|---|
| W/S, A/D | 카메라가 바라보는 전후 방향과 카메라 기준 좌우 이동 |
| R/F | 월드 +Y 상승 / -Y 하강 |
| 화면 드래그 | 관찰 중심을 기준으로 카메라 회전 |
| 스크롤 | 관찰 중심을 향한 줌인 / 줌아웃 |
| XY / YZ / XZ 버튼 | 해당 평면을 정면에서 보는 위치·방향으로 카메라를 이동; 이동 후 자유 이동과 회전 가능 |

- 축 버튼의 **초기 기준안**은 선택된 함대의 현재 기준점이며, 선택이 없으면 현재 관찰 중심이다. 현재 거리 또는 적절한 거리의 보존 방식과 전환 애니메이션은 시연 후 결정한다.
- 일반 관람의 평면 버튼은 카메라를 고정하는 모드가 아니다. 정렬 후 WASD·R/F·드래그·줌을 계속 사용할 수 있다. 원근 카메라의 정렬 시점으로 시작하는 것을 제안하며, 직교 투영 전환 여부는 별도 결정한다.
- `목표 위치 지정`은 관람 버튼과 별도다. 기획의 정규 절차대로 **주 작업 영역을 XZ 직교 뷰로 전환 → X/Z 임시 선택 → YZ 또는 XY 직교 뷰로 자동 전환 → Y만 선택·확정**한다. YZ는 임시 기본안이다. 완료·취소 시 이전 자유 카메라의 위치·방향·줌·관찰 중심을 복원한다.
- 목표 입력 중 카메라 버튼, 자유 카메라 조작, 함대 변경 및 전투 시작은 draft가 유실되거나 명령이 일부 적용되지 않도록 제어한다. 초기 제안은 목표 입력을 취소/완료하기 전에는 해당 전환을 비활성화하고 이유를 표시하는 것이다. UI 입력란·버튼에 포커스가 있을 때 카메라 단축키 충돌을 방지하고 키 해제·창 포커스 이탈을 처리한다.

#### 0.3 미니맵의 평면·좌표·선택

미니맵은 **한 번에 하나의 직교 뷰**를 표시하고 탭으로 XY·YZ·XZ를 전환한다. `ZX`와 `XZ`는 같은 평면이므로 UI 이름은 XZ로 통일한다. 아래 축 방향은 화면 반전을 방지하기 위한 초기안이며 모든 뷰에서 화살표와 글자로 표시한다.

| 탭 | 보이는 축: 화면 오른쪽 / 위 | 임시 관측 방향 | 보이지 않는 축 |
|---|---|---|---|
| XY | +X / +Y | +Z에서 원점을 향함 | Z |
| YZ | +Z / +Y | -X에서 원점을 향함 | X |
| XZ | +X / -Z | +Y에서 원점을 향함 | Y |

- 아군·적군·선택 함대는 색과 윤곽 등 색 외 수단으로 구분하고, 선택 함대의 목적지와 경로를 투영해 표시한다. 선택된 함대의 좌표와 현재 탭을 함께 표시하여 투영에서 사라지는 축을 확인할 수 있게 한다.
- 다른 깊이의 대상은 같은 화면 위치에 겹칠 수 있다. 겹침은 숨겨진 축이 같다는 뜻이 아니며, 목록을 통한 선택은 항상 가능해야 한다. 겹친 아이콘을 직접 고르는 방식은 후속 사용성 검토 대상으로 둔다.
- 미니맵 탭은 메인 평면 방향 버튼과 독립적이다. 미니맵에서 함대 선택은 가능하도록 제안하되, **한 번의 미니맵 클릭을 3D 목적지 확정으로 해석하지 않는다.** 명령 지점은 공통 2단계 입력을 사용한다.
- 기본 화면에서 세 평면을 동시에 표시할 것을 요구하지 않는다. 단, 세 투영은 모두 같은 월드·명령 데이터를 읽고 각 탭 전환 시 일관된 좌표를 표시한다. 동시에 세 보조 뷰를 보여줄지 여부는 별도 UX 선택이다.

#### 0.4 함대 관리 창과 표시 상태

```text
함대 목록: 아군 함대 선택 / 생존 수
선택 함대: 함선 목록 · 편성 · 순서
이동 명령: 목적지 이동 / 경로 순찰 · 목표 지점 지정
교전 대응: 명령 유지 사격 / 거리 유지 교전 / 진형 관통 / 분할 포위 / 거점 방어
대형 설정: 선택된 명령·대응에 종속된 크기와 함선 순서
전투 준비 완료 / 현재 상태 / 안내와 오류
```

- 함대 선택은 관리 창·메인 화면·미니맵이 같은 함대 ID를 공유한다. 편성은 중복 소속 없이 표현하고 순서 변경은 실제 슬롯 대응에 반영한다.
- **준비 단계:** 편성·명령·목표점·해당 대형의 크기와 순서를 편집한다. 목표 입력 draft는 완성 전 기존 명령을 변경하지 않는다.
- **자동 전투:** 함대 선택·관람·상태 확인은 가능하게 하고 전술 편집은 비활성화한다. 화면에는 선택 함대의 현재 명령과 활성 교전 대응, 생존/체력과 남은 시간을 표시한다.
- **결과:** 승패와 생존 상황을 확인한다. 시간 종료 후 준비로 복귀한 경우 기존 설정과 시뮬레이션 상태가 유지되며 선택한 함대만 수정할 수 있어야 한다.
- 대형은 독립적인 세 번째 주 명령이 아니라 이동 명령과 교전 대응에 연결된 설정이다. 미구현 기능은 비활성 또는 미구현 표시를 하고 실제 동작하는 정책처럼 보이게 하지 않는다. 디자인 시안의 문구와 임시 상태는 실제 게임 데이터와 구분한다.

#### 0.5 상호작용·상태 경계

1. 공유 상태의 최소 단위는 `selectedFleetId`, 관람 카메라 상태, 미니맵 평면, 준비/전투/결과, 목표 입력 draft다. 메인 뷰와 미니맵은 공통 시뮬레이션 위치를 읽으며 별도의 권위 있는 함대 위치를 만들지 않는다.
2. 관람 카메라와 미니맵 평면 선택은 전술 명령을 바꾸지 않는다. 미니맵 전환, 평면 버튼 이동, 카메라 이동 자체가 시뮬레이션을 진행·정지시키지 않는다.
3. 목표 입력은 준비 단계에서만 시작한다. `PICK_XZ`에서는 X/Z만, `PICK_Y`에서는 잠긴 X/Z와 새 Y를 draft로 관리한다. 확정 전 기존 명령은 유지하고 확정 후에만 선택 함대의 해당 명령을 갱신한다.
4. 뷰포트별 픽셀 위치를 실제 렌더 영역 기준으로 계산한다. 패널·버튼 클릭을 전장이나 미니맵 클릭으로 전달하지 않는다. 리사이즈 뒤에는 카메라 종횡비·투영·입력 좌표를 함께 갱신한다.
5. 카메라/미니맵 조작은 전투 상태와 독립적이며, 전투 단계 변경·함대 선택 변경·ESC·브라우저 포커스 상실에서 각 입력 상태를 명확히 정리한다. 구체적인 키 매핑과 전환 처리의 임시 선택은 구현 시 기록한다.

#### 0.6 검증 기준과 단계 경계

| 검증 ID | 조건 | 기대 결과 |
|---|---|---|
| UI-01 | WASD·R/F, 드래그·휠 사용 | 의도한 축으로 관람하고 패널 입력 중 키가 전장 이동과 충돌하지 않음 |

0단계는 위 화면과 상호작용의 **설계 및 사용성 확인**이 목적이다. UI 골격을 구현할 경우 UI-01~04·07 및 미구현 표시를 우선 검증한다. UI-05의 실제 격자 커밋과 UI-06의 실제 전투 상태는 각각 단계 1과 2에서 확인한다. 0단계 설계·와이어프레임만으로 구현 또는 테스트 통과를 보고하지 않는다.

### 단계 1 — v2.1 목표 입력과 목적지 이동 보완

**시작 조건:** 현재 이동 프로토타입과 별도 리깅 테스트를 보존한다. v2.2의 유한 직육면체 전장을 기준으로 격자 간격·원점·전장 경계 치수를 설정 가능한 임시값으로 둔다. 두 번째 높이 입력 화면은 YZ를 임시 기본으로 사용하되 XY도 기획상 가능하다. 기존 숫자 입력만으로 v2.1 정규 목표 입력을 대체하지 않는다.

| 순서 | 작업 | 구체적인 완료 기준 |
|---|---|---|
| 1-A | 명령 격자 데이터 | `GridPoint3`의 세 정수, 유한한 원점, 양의 간격과 v2.2 유한 직육면체 전장 경계를 정의한다. 인덱스→월드 및 월드→가장 가까운 교차점 변환을 한 곳에서 처리하고 음수·반올림 동률·경계 규칙을 일관되게 문서화한다. 명령 격자는 이동 대형 슬롯 격자와 별도다. |
| 1-B | 기존 목적지 처리 | 초기 함대 목표와 현재 `Vector3` 기반 명령을 인덱스로 전환한다. 기본 목표가 격자에 맞지 않으면 실제 적용될 좌표를 표시하고 임시 기본값을 기록한다. 기존 저장 명령이 발견되면 조용히 위치를 바꾸지 않으며 마이그레이션 여부를 별도 결정한다. |
| 1-C | 목표 선택 상태와 카메라 | 준비 단계에서 `NONE → PICK_XZ → PICK_Y → COMMIT` 흐름을 구현한다. 첫 클릭은 X/Z만 임시 선택하고 두 번째 화면에서 Y만 확정한다. 주 작업 화면이 XZ→YZ로 바뀌며 변경 전 명령은 그대로 유지된다. |
| 1-D | 입력 취소·오류 복구 | ESC/취소는 draft를 폐기하고 기존 명령과 원래 카메라를 보존한다. 뒤로 가기는 XZ를 다시 고를 수 있게 한다. 함대 변경·시작·화면 크기 변경 등 입력 중 상태 전환을 정의하고 고아 draft를 남기지 않는다. 입력 중 자유 카메라 키 조작과 패널 클릭을 충돌시키지 않는다. |
| 1-E | MOVE와 자세 | 확정된 인덱스에서 월드 목표를 생성하고 연속 공간에서 이동한다. 함대의 이동/교전/대기 자세 의도를 분리할 수 있게 설계한다. 비전투 도착 후 마지막 유효 XZ 방향을 보존하며 함대 기준 자세와 선체를 각속도 제한으로 수평 복귀시킨다. |
| 1-F | 슬롯·편성 검증 | 실제 위치를 고정 틱에서 유지하며 순서·소속·3축 대형 크기를 슬롯에 반영한다. 한 층인 축은 효과 없음이 보이게 하고, 활성 축의 최소 간격 미달은 확정 전에 설명한다. 간단한 근접 완화를 무충돌 보장으로 표현하지 않는다. |

**입력 검증:**

- 원점과 간격이 다른 경우에도 정수 인덱스가 정확히 월드 교차점으로 변환되고, 음수·절반 간격 동률·경계 안팎에서 정한 규칙이 재현된다. 격자 간격은 공간 탐색용 셀 크기와 공유하지 않는다.
- 첫 클릭 후 X/Z만 draft에 저장되고 Y와 실제 명령은 변하지 않는다. 높이 단계의 좌우 마우스 이동은 기존 X/Z를 바꾸지 않으며 클릭으로 Y만 확정한다. 단계 이동·취소·카메라 복구를 확인한다(통합본 G01~G04·G12; 보강 명세 G01~G05·G17).
- 뷰포트의 위치·크기·종횡비·확대 수준이 달라진 상태에서 동일 **월드 교차점에 대응하는 화면 위치**를 선택하면 같은 인덱스를 얻는다. 리사이즈 후 동일 픽셀에 서로 다른 월드 지점이 보이는 상황을 동일 좌표로 강제하지 않는다.
- 준비 중만 명령을 편집하고, 전투 실행/함대 전환/취소의 경계에서 반쯤 완성된 draft가 명령에 들어가지 않는다. 완료·취소 후 기존 자유 카메라를 복구하고 WASD·R/F 및 드래그·줌을 다시 사용할 수 있다.

**이동·자세 검증:**

- 목표는 교차점이지만 기준점·함선·슬롯의 중간 좌표는 연속이며, 위치 스냅 없이 높이가 다른 목적지로 이동한다(통합본 G05; 보강 명세 G07·G08).
- 이동 완료와 활성 교전 없음이 모두 성립할 때만 대기 정렬한다. 수평 복귀 중 함대 기준점은 유지하고 슬롯 목표는 회전하며 실제 함선은 연속 추종한다. 마지막 유효 Yaw와 서로 다른 함선 높이를 보존한다(통합본 G10·G11; 보강 명세 G11·G13).
- 수직에 가까운 상승·하강, 0에 가까운 XZ 투영 및 방향 전환에서 유효한 이전 수평 방향을 유지하고 급격한 회전 반전이 없는지 검증한다. 준비 상태의 위치·자세·시간은 변하지 않는다.
- 순서 변경이 실제 함선↔슬롯 대응을 바꾸고, 3축 크기 변경 시 해당 축의 실제 슬롯이 바뀐다(T14·T15). 소규모·불완전 편성과 다른 함대의 함선 이동에서 슬롯 수·간격·중복 소속을 확인한다.

**단계 1 완료 판정:** 위 입력과 이동·자세 항목을 모두 통과한 뒤 기본 MOVE가 v2.1 목표 입력을 사용한다고 보고한다. 현재의 숫자 입력 프로토타입이나 화면 로딩 성공만으로 이 단계를 완료 처리하지 않는다. 통합본 T21의 **모든 관측 뷰 동기화**는 단계 7에서 완성하며, 단계 1에서는 주 작업 뷰 전환과 명령·메인 화면 동기화를 선행 검증한다. 통합본 G07 중 *다른 높이의 적과 교전 및 무장 화각* 부분도 전투 구현 후 검증한다.

#### 1.1 설계 범위와 현재 상태

이 절은 단계 1의 **구현 전 상세 설계**다. 현재 `web/simulation.js`는 함대 목적지를 연속 `Vector3`로 저장하고 기준점을 목표 근처에서 바로 목표로 맞춘다. `web/main.js`는 단일 원근 카메라, 별도의 2D 미니맵과 숫자 입력을 사용한다. 아래 기능을 이미 구현하거나 검증했다는 뜻이 아니다.

- **이번 단계:** 명령 좌표의 격자 인덱스화, 목적지의 XZ→YZ 2단계 입력, 카메라 복원, MOVE 이동·대기 자세, 편성·이동 격자 연결 및 검증.
- **후속 단계:** 경유점과 방어 거점에 같은 입력기 재사용, 실교전의 자세 보정과 무장, 세 직교 관측 뷰의 완성. 입력기는 대상 명령에 종속되지 않게 설계하지만 미구현 정책을 선택 가능하게 만들지 않는다.
- 명령 격자, 함대의 이동 격자, 화면 픽셀, 미니맵 투영은 서로 다른 좌표·책임이다. 어느 하나의 변경이 다른 하나의 값을 암묵적으로 스냅하거나 저장하지 않는다.

#### 1.2 명령 격자와 데이터 계약

**초기 구현 제안 — 임시값:** 원점 `(0,0,0)`, 간격 `h=1`, 전체 축 공통. 현재 A `(10,8,8)`, B `(10,-5,22)`, E `(20,0,0)` 기본 목표가 모두 이 격자에 있어 좌표를 바꾸지 않고 인덱스로 표현할 수 있다. 게임 밸런스나 월드 규모가 확정됐다는 의미는 아니며 설정에서 조정한다. v2.2 전장은 **유한한 직육면체**이며 경계 밖 목표는 유효하지 않다. 전장 치수와 접근 불가능 영역은 미결이므로 기존 초기 배치와 목표를 포함하는 대칭 AABB의 임시 치수를 설정하고 표시한다. 실제 함선 부피·초기 스폰·득점 구역과의 일치 검증은 v2.2 전장 설계와 연결하며, 검증되지 않은 임시 배치를 확정 규칙으로 취급하지 않는다. 표현·수치 안정성 범위는 별도 제한과 오류로 명시한다.

```text
CommandGrid = { origin: Vec3, spacing: 양의 유한수 }
Battlefield = { min: Vec3, max: Vec3 } // 유한한 직육면체 경계; 정확한 치수 미결
GridPoint3  = { ix: 정수, iy: 정수, iz: 정수 }
world       = origin + spacing * (ix, iy, iz)
```

- `gridToWorld(point, grid)`는 유효한 인덱스를 새 월드 좌표로 변환한다. `worldToNearestGrid(world, grid)`는 축별 스냅 후 인덱스를 반환한다. 반올림 동률은 **0에서 멀어지는 방향**을 초기 규칙으로 제안한다. 예를 들어 ±0.5는 각각 ±1이다. 음수에서 언어 내장 `round`의 동률 방식에 무심코 의존하지 않는다.
- `GridPoint3`는 정수·유한값 및 안전 정수 범위를 검사한다. `origin`, `spacing`, 변환 결과도 유한해야 한다. 목표 교차점이 설정된 유한 전장 AABB 안에 있는지 검사한다. 전장 경계 면 포함 여부는 임시 규칙을 정하고 기록한다. 무효 클릭은 알리고 **기존 명령과 draft의 확정 축을 유지**한다. 범위를 임의로 잘라 다른 좌표로 확정하지 않는다.
- `FleetCommand.movement.destination`에 인덱스를 보관하고, 해당 명령의 월드 목표는 이 값과 `CommandGrid`에서 계산한다. 시뮬레이션 위치·속도·대형 슬롯은 계속 연속 좌표다. 임시 숫자 편집이 유지된다면 인덱스 또는 스냅될 월드 값을 명확히 표시하고 같은 검증·확정 경로를 사용해야 하며 정규 2단계 조작을 대체하지 않는다.
- 현재 소스는 메모리 내 기본값을 사용한다. 영속 저장 데이터의 존재는 확인되지 않았으므로 저장 데이터 이관 완료를 가정하지 않는다. 이후 연속 목적지 저장본을 발견하면 원본을 보존하고 스냅 결과를 사용자 또는 기록에 드러내는 이관 방식을 별도 설계한다. 격자 설정을 런타임에 바꿀 수 있게 된다면 같은 인덱스의 월드 좌표가 달라지는 영향을 명시하고 무음 변경을 금지한다.
- 현재 설정의 `spacing=4`는 **함선 최소 간격**이다. 새 `commandGridSpacing`과 이름·의미·설정 소유권을 분리한다.

#### 1.3 목표 입력과 카메라 상태

입력기 상태는 시뮬레이션 명령과 별도로 둔다. 단계 1은 목적지에만 연결하지만 대상 타입과 commit 경계는 후속 경유점·거점에 재사용할 수 있게 한다.

```text
PositionDraft = {
  targetKind: MOVE_DESTINATION, fleetId, phase: PICK_XZ | PICK_Y,
  ix?: integer, iz?: integer, hover?: GridPoint3 또는 부분 좌표,
  cameraSnapshot: { position, quaternion, zoom, orbitTarget, 관람 조작 상태 },
  commandBefore: 기존 명령 식별/검증용 값
}
```

| 상태·사건 | 동작 및 불변식 |
|---|---|
| `NONE → PICK_XZ` | 준비 단계에서 선택된 아군 함대 ID와 원근 관람 카메라 상태를 저장한다. 키 입력 상태를 비우고 주 화면을 XZ 직교 카메라로 교체한다. 기존 명령은 그대로다. |
| `PICK_XZ` 포인터 이동 / 클릭 | 유효 교차점을 임시 강조한다. 클릭 시 `ix, iz`만 draft에 저장하고 Y는 미확정으로 두어 `PICK_Y`로 전환한다. |
| `PICK_Y` 포인터 이동 / 클릭 | YZ 직교 카메라로 전환하고 이전 X/Z를 잠근다. 화면 높이에 대응하는 `iy`만 읽는다. 클릭 시 세 인덱스와 대상 함대·준비 상태를 다시 검증한 뒤 해당 명령을 **한 번** 커밋한다. |
| `PICK_Y → PICK_XZ` | 뒤로 버튼은 Y 임시값을 폐기하고 X/Z 재선택 화면으로 돌아간다. 기존 명령은 수정하지 않는다. |
| 취소 / ESC | 어느 단계에서든 draft를 폐기하고 명령을 유지한다. 전환 전 카메라와 컨트롤을 복원한다. |
| 완료 | 유효한 3D 인덱스 하나를 선택 함대의 목적지로 반영한 뒤 draft를 지우고 이전 카메라와 컨트롤을 복원한다. |

- 입력 중에는 카메라 방향 버튼·자유 카메라 키/드래그와 함대 변경·이동 시작을 일시 비활성화하고 사유와 취소/뒤로 방법을 표시하는 **초기 UI 선택**을 사용한다. 미니맵의 평면 변경은 허용할 수 있으나 함대 선택과 명령 확정으로 전파하지 않는다. 포커스·키 상태는 시작·종료 시 정리한다.
- UI 패널 또는 미니맵의 클릭은 주 화면 목표 클릭으로 전달하지 않는다. 클릭과 드래그의 구분, 터치 지원 여부는 구현 시 명시한다. 브라우저 포커스 상실은 입력을 암묵적으로 확정하지 않으며, 입력 모드 유지 또는 명시적 취소 중 하나를 정해 안내한다. 리사이즈는 draft를 버리지 않고 직교 투영과 포인터 변환을 갱신한다.
- `COMMIT`은 선택된 함대 ID·준비 상태·세 인덱스와 경계를 검증해 원자적으로 처리한다. 실패하면 draft에 남고 원인을 표시한다. 기존의 `명령 적용`이 대형 크기와 목적지를 한 번에 쓰므로, 새 입력 커밋과 별도의 대형 크기 적용이 서로 다른 필드를 덮어쓰지 않도록 분리한다. 숫자 필드의 미적용 값과 확정 명령을 혼동하지 않는다.

#### 1.4 뷰포트·직교 투영과 표시

- 원근 `camera`와 `OrbitControls`는 관람용으로 보존한다. 입력용 XZ/YZ 직교 카메라는 별도의 상태로 관리하고, 렌더에 쓰는 `activeCamera`만 단계에 따라 바꾼다. 미니맵의 XY/YZ/XZ 선택과 입력용 주 화면은 독립이다.
- 0단계의 축 표기를 유지한다. XZ는 화면 오른쪽 `+X`, 위 `-Z`; YZ는 오른쪽 `+Z`, 위 `+Y`. 첫 단계 가상 평면은 선택 함대 기준점의 현재 Y를 보여주기 위한 임시 높이로 사용하되 **명령의 Y로 확정하지 않는다**. 두 번째 단계에서는 고정된 X 인덱스의 월드 X를 지나는 YZ 평면을 사용하고 선택된 Z에 세로 안내선을 표시한다.
- 포인터를 실제 주 뷰포트의 CSS 픽셀 영역으로 변환한 뒤 NDC로 바꾸고 직교 카메라의 역투영 광선과 입력 평면의 교점을 계산한다. XZ 교점에서 X/Z만, YZ 교점에서는 **화면의 수직 위치에 대응하는 Y만** 스냅한다. 2단계의 포인터 가로 위치가 잠긴 X/Z를 변경해서는 안 된다.
- 화면마다 현재 단계, 축·방향·격자 눈금, 후보/확정된 좌표, 함대→후보 경로, 취소·뒤로 조작을 표시한다. 뷰에 보이는 격자는 동일한 월드 `origin`과 `spacing`으로 배치한다. 간격이 작거나 확대율이 낮을 때 **표시할 선만 솎아낼 수 있지만** 입력 스냅 간격은 바꾸지 않고 생략을 안내한다.
- 직교 뷰의 중심·표시 범위와 확대/축소 기본값은 임시 설정으로 둔다. 전체 월드를 전부 그리는 대신 뷰에 필요한 범위만 렌더링한다. 캔버스와 사이드 패널·미니맵의 실제 겹침을 고려해 유효 클릭 영역을 정하고, 크기 변경 시 투영과 선택 영역을 재계산한다.
- 완료 후 메인 원근 화면과 현재 선택된 미니맵은 동일한 확정 월드 목표를 투영한다. 세 보조 화면 동시 표시는 필수로 가정하지 않는다. 전체 직교 관측 뷰의 동기화 완성은 단계 7에서 별도로 확인한다.

#### 1.5 MOVE·도착·대기 자세

**초기 설계 선택:** `postureIntent`는 저장된 물리 속도만으로 판단하지 않고 이동 명령과 활성 전술 상태에서 유도한다. 단계 1에는 실제 교전이 없으므로 비전투 MOVE만 연결하되, 이후 `ENGAGING`이 도입될 때 대기 판정을 덮어쓰지 않도록 입력을 분리한다.

```text
RUNNING + 활성 전술 교전          → ENGAGING (후속 전투 단계에서 실제 연결)
RUNNING + MOVE 미도착             → MOVING
RUNNING + MOVE 도착 + 활성 교전 없음 → IDLE
PREPARATION                       → 시뮬레이션 정지; 자세 의도는 보존
```

- 이동 중 목표 방향은 `gridToWorld(destination) - fleetAnchor`로 얻고, 이전 상단 벡터의 연속성을 고려한 3D 자세를 각속도 제한으로 따른다. 유효한 XZ 전방 투영이 있을 때만 `lastValidHorizontalForward`를 갱신한다. 수직에 가까워 유효하지 않으면 마지막 유효 방향을 유지하며 초기 기본 전방 `(0,0,1)`은 함대별 임시값이다.
- 현재 기준점은 속도를 즉시 바꾸고 작은 거리에서 목표로 보정한다. 단계 1에서는 기준점 속도를 명시적으로 관리하고 임시 최대 속도·가속/감속·도착 거리·속도 허용치를 설정한다. **목표 거리와 속도가 모두 허용치 이내**일 때 도착으로 판단한다. 오버슈트·왕복이 생기지 않도록 감속과 도착 처리를 검증하며, 허용치 이내의 보정이 있다면 그 방식과 상한을 기록한다. 이 수치들은 기획 확정값이 아니다.
- `IDLE`에서는 기준점 위치를 유지하고 마지막 수평 전방과 월드 +Y 상단으로 목표 쿼터니언을 구성한다. 각속도 제한으로 연속 회전시키고, 매 틱 바뀐 기준 자세로 월드 슬롯을 다시 계산한다. 함선은 자기 슬롯을 가감속·선회 제한으로 따라간다. 실제 위치나 Y를 즉시 맞추지 않는다.
- 준비로 복귀하면 **기준점·속도·기준 회전·함선 위치·회전·마지막 유효 수평 방향·도착/대기 진행**을 보존하고 정렬도 중단한다. 재개하면 보존 상태에서 이어진다. 준비 중 목적지를 변경했을 때는 현재 물리 상태를 유지하고 새 임무를 시작하며, 이전 대기 회전 결과를 순간 적용하지 않는다.
- 실제 교전 중 정지와 이동 중 조준 회전의 정책은 단계 2 이후에 테스트한다. 단계 1에서 `ENGAGING`이라는 문자열만 만들었다고 활성 교전 예외나 무장 기능이 완성된 것으로 보고하지 않는다.

#### 1.6 편성·슬롯과 현재 구현 보완

- `orderedShipIds[i]`와 결정적인 `slot[i]`의 대응이 UI 순서 변경과 일치해야 한다. 함대 간 이동은 소속과 두 목록을 함께 갱신하며 함선을 복제하거나 잃지 않는다. 실제 함선 위치는 유지하고 새 목표 슬롯으로 이동한다.
- X/Y/Z 크기는 각 축 슬롯 중심의 최대 폭이며, 그 축의 층수가 1이면 해당 크기는 슬롯에 영향을 주지 않는다. UI에서 비활성/미적용을 표시한다. 최소 간격 위반 시 크기·함선 이동을 커밋하지 않는다.
- 현재 `dimensions(n)`은 함선 수 중심으로 층수를 정하고 `grid()`는 필요한 슬롯 수만 앞에서 잘라낸다. 소규모·불완전 격자에서 선택된 슬롯의 중심이 함대 기준점으로부터 치우칠 수 있으므로, **결정적 슬롯 선택·중심 기준·축 크기 비율과 최소 간격**을 함께 검토한다. 실제 크기와 층수의 관계를 UI에 설명하고, 특정 알고리즘이나 완전한 무충돌을 기획 확정으로 보지 않는다.
- 현재 근접 완화는 모든 함선의 즉시 갱신 순서에 영향을 받을 수 있고 정확히 같은 위치일 때 분리 방향이 없다. 동일 틱의 입력 상태를 읽는 방식과 겹침 처리 기준을 검토한다. 범위를 넘어서는 정밀 충돌 회피는 후속 과제로 기록하되 관찰된 겹침·불안정성을 숨기지 않는다.

#### 1.7 구현 단위·순서 제안

기존 `web/index.html`, `web/main.js`, `web/simulation.js`와 미커밋 리깅 도구를 보존한다. 필요 시 책임별 새 모듈은 사용자의 파일 생성 지침과 이후 구현 지시 범위를 확인한 뒤 결정한다. 다음은 파일 이름을 확정하는 것이 아닌 논리 책임이다.

1. **명령 격자 계산·검증:** 좌표 변환과 경계/동률 규칙을 화면과 독립적으로 검증한다.
2. **명령 데이터 전환:** 기본 목적지의 월드 값이 유지되는지 확인하고 모든 MOVE 실행·미니맵 표시가 같은 확정 명령을 읽게 한다.
3. **입력 draft·카메라 어댑터:** XZ/YZ 투영, 포인터 변환, 확정·뒤로·취소, 관람 카메라 복원을 연결한다.
4. **이동·자세 제어:** 감속·도착·수평 복귀와 마지막 유효 수평 방향을 고정 틱에 추가하고 준비 상태 보존을 점검한다.
5. **대형·편성 및 UI 연결:** 슬롯 배정·불완전 격자와 활성 축 검증을 보완하고 입력·관리 창·미니맵을 동기화한다.
6. **통합 회귀:** 자동 계산/상태 검증, 브라우저 입력·리사이즈, 실제 화면 관찰을 분리해 기록한다. UI 구현 완료를 시각 검수 완료로 대체하지 않는다.

### 단계 2 — 데이터·사건 중심 전투와 득점 재설계

- **현행 설계 제안:** [2단계 상세 재설계](phase2-data-oriented-combat-design.md). **이전 상세 설계:** [폐기·보존본](../archive/phase2-combat-design-superseded-2026-11-23.md). 공간 후보·포구 즉시 판정과 데이터 기반 조준 계산 일부를 구현했으나 기존 회전 간섭 근사와 메시 포구 검사가 남아 있으며, 전체 설계가 구현·검증된 것은 아니다.
- 목표: 0~1단계의 조작과 MOVE를 유지하고, 3차원 검색·표적·무장·포구 사선·함선 중심 피격·득점을 데이터와 사건 중심으로 연결한다. 9개 점수 구역과 공간 검색 셀은 별도다.
- 2-A: 기존 동작·동일 시나리오와 비용 기준선 고정, 공격 시간·정확도 조건 확인.
- 2-B: 고정 틱·안정 ID·데이터 소유권과 기존 UI/화면 어댑터, 3차원 공간 인덱스 및 함선 근접 후보 구현.
- 2-C: 공유 후보에 기반한 근사 표적 선택, 리깅 좌표 변환과 포탑 각도·속도, 발사 가능 조건 구현.
- 2-D: 포구 레이와 최초 차단자, 공격 사건, 피격 함선의 피해 확정과 동시 처리. 화면 탄은 독립 판정 객체가 아니다.
- 2-E: 점수·준비/전투 전환, 0~1단계 회귀 및 3단계 증원·경제 연결 검증.
- 2-F: 기능·오차·프레임 시간 및 작업량을 동일 조건으로 비교하고 병목에 따라 최적화. 완료 기준과 테스트는 상세 재설계 10절을 따른다.

발사 틱 즉시 판정은 비교용 시제품 가정이며 탄의 비행 시간·차폐 변화 규칙은 미결이다. 실제 발사 사건 수와 공간 후보 수는 계산량에 영향을 준다. 함수나 라이브러리 변경만으로 성능 개선을 보장하지 않는다.

### 단계 3 — 점수 경제·증원과 기본 적 AI

**목표:** 2단계 전투를 구매와 증원이 가능한 v2.2 게임 반복으로 완성한다. 고급 전술보다 먼저 승리 점수와 소비의 선택을 실현한다.

| 순서 | 작업 | 완료 기준 |
|---|---|---|
| 3-A | 공통 점수·구매·예비 | 현재 점수의 원자적 차감·예비 생성과 중복 방지 |
| 3-B | 기존·신규 함대 배정과 시작 면 투입 | 유효 위치 예약, 실패 시 예비 보존, 기존 함선 상태 유지 |
| 3-C | 동적 모델/무장 등록 및 구매·예비 UI | 실제 FBX 연동·실패 복구, 클릭/드래그 준비 흐름 |
| 3-D | 동일 규칙의 기본 적 AI | 같은 가격·점수·배치 제약, 구역 목표·구매·투입 |
| 3-E | 재기 가능성·결과·교착 | 목표 점수 우선, 전멸과 예비/구매 가능성 및 임시 차단 구별 |
| 3-F | 통합 검증·밸런스 | 전체 전투 반복, 양측 공정성·0~2단계 회귀 및 성능 관찰 |

**검증:** 준비 중 구매는 점수를 감소시키고 득점·전투 시간은 정지한다. 양측 동일 입력에 동일 제약을 적용한다. 비용 차감, 잘못된 스폰과 경계, 예비 전력 및 구매 가능/불가의 전멸, 동시 종료와 재개를 확인한다(Z13~Z19 및 관련 Z 사례). 단계 3 완료는 최소 경제 게임 루프의 완료이며 전체 전술·에셋 검수 완료는 아니다.

#### 3단계 시제품 구현 현황 — 2026-11-24

- 구현: 공통 현재 점수와 임시 가격 30·진영별 함선 한도 32, 구매 요청 중복 방지, OWNED/ASSIGNED/ACTIVE/DESTROYED, 기존/신규 함대 배정과 배정 취소, 양측 시작 면 구형 경계·공간 후보 기반 겹침 검사, 대기/재시도 및 실제 FBX/무장 인스턴스 연결. 적은 준비 단계당 한 번 구역 목표와 구매를 결정하며 같은 비용·투입 경로를 사용한다. 목표 점수와 전멸 시 예비/구매 가능성 판정을 적용했다.
- 확인: 계산 시험에서 점수 90→60·요청 중복·잔액 부족·모델 준비 실패 후 재시도, 시작 면 차단·해제, 기존 함선 위치 보존, 양측 시작 면, AI 중복 구매 방지, 재기 불가 무승부, 구매 함선 격침 후 패배, 모델 불일치 구매 보류 및 동일한 빈 시작 면 배치 실패 3회에 대한 무승부와 모델 오류 시 대기 유지 사례를 확인. Edge 헤드리스에서 점수를 시험 주입해 플레이어 기존/신규 함대 배정과 적 구매 후 19개 FBX/무장 등록을 확인했고, 최종 변경 후 양측 구매·18개 모델 등록·전투 시작/정지, 예비 함선의 함대 탭 드래그 배정을 확인했으며 기존 리깅 안전 검사 10개 그룹이 통과했다. 이는 자연 득점부터 종료까지 전체 경기를 완주한 검증이 아니다.
- 남음: AI 정책·가격/수량의 밸런스, 다양한 장기 교착·배치 변경 사례, 전체 Z13~Z19/Z24 및 비동기 자원 실패의 포괄 검증, 자연 득점→구매→증원→승패까지 장시간 사용자 GPU 관찰. 예비 카드는 기존 함대 탭에 드래그하거나 클릭으로 기존/신규 함대에 배정한다. 현재 모델 등록은 동기 처리이고, 양측 전멸 상태에서 동일 배치 공간 부족이 3회 연속 발생할 때 무승부로 처리하는 임시 한도를 사용한다. 시제품 수치와 화면 확인을 3단계 완료나 전체 밸런스 보증으로 취급하지 않는다.

#### 3.1 상세 설계의 상태·범위

- 상태: **설계 제안 / 미구현·미검증**, 작성 2026-11-24. 상위 규칙은 [v2.2 기획 21절](../spec/game-design-v2.2.md), 전투는 [2단계 상세 재설계](phase2-data-oriented-combat-design.md), UI는 이 문서의 2026-11-24 UI 개선을 따른다. 사용자 지시와 확정 기획이 임시안보다 우선한다.
- 목표: 현재 점수로 양측이 같은 규칙의 구매·편성·시작 면 투입을 거쳐 여러 전투 구간을 진행하고, 점수 목표 또는 재기 불가능 조건으로 종료하는 대표 함선 1종 수직 슬라이스.
- 순찰·추가 교전 대응·실드·환불/매각·다수 함종 완전 검수는 범위 밖이다. 현재 2단계 시제품 검증은 선택된 사례에 한정하며 전체 구현·정밀 충돌·실제 GPU 성능 인증은 아니다.
- 가격·초기 잔액·시작 면 폭·간격·함대 상한·AI 가중치와 대기 한도는 기획 미결. UI에 숫자 입력을 추가하지 않고 테스트 설정의 명시적 임시값으로 시작한다. 무제한 수량·시간이나 즉시 판정을 최종 밸런스로 확정하지 않는다.

#### 3.2 데이터 소유권과 상태

| 데이터 | 필드·권위 | 불변식 |
|---|---|---|
| 전투 상태 | phase, tick, remaining, result, 기존 scores[ALLY/ENEMY], scoreTicks | 기존 scores를 **유일한 현재 잔액**으로 유지. 구매용 별도 화폐나 UI 복사본을 권위로 사용하지 않음. 점수·HP·틱은 준비에서 정지. |
| 함종 설정 | typeId, assetKey/hash, price, collisionRadius, hp, 무장 설정 | 3단계 기본 1종, 양 진영 공유. 가격은 양의 안전 정수; asset 검수 실패는 배치 불가 사유. |
| 예비 함선 | shipId, team, typeId, state, assignment, purchaseId | 구매 시 유일 ID 발급; 하나의 진영과 상태만. 예비는 실제 전장 함선·득점 대상이 아님. |
| 투입 요청 | requestId, shipIds, team, targetFleetId 또는 신규 함대 초안, status/reason | PREPARED/WAITING/DEPLOYED; 예약 중 중복 배정 금지. 구매 취소·환불 없음. 배정 해제/변경은 점수 변동 없음. |
| 전장 함대·함선 | 현재 Fleet/Ship, 안정 ID, 슬롯과 pose, HP, weapons | 활성 전장 객체만 이동·득점·사선에 포함. 동일 함선은 예비와 활성에 동시에 존재하지 않음. 격침은 예비로 복귀하지 않음. |
| 화면 리소스 | shipId→view/rig, 공통 FBX/불변 설정 | 화면은 권위 잔액·생존을 직접 변경하지 않음. 신규 함선마다 개별 무장·안전 상태, 생성 실패는 비활성 유지·이유 표기. |

예비 lifecycle: `OWNED` → 준비 중 배정된 `ASSIGNED` → 재개 시 재검증·모델 준비 성공하면 `ACTIVE` → 격침 시 `DESTROYED`. 배정 취소는 `ASSIGNED→OWNED`; 공간/리소스 문제는 `ASSIGNED`를 유지하며 대기 이유를 기록한다.

현재 `ship()`와 `fleet()`는 초기 편성 생성용이므로 기본 설정과 안전한 신규 생성 경계를 분리해야 한다. 함선·함대 ID는 진영별 단조 증가·충돌 검사, 기존 A/B/E와 구분, 삭제 후 재사용 금지. 모델 에셋 공통 자료는 공유하되 인스턴스 pose·쿨다운·안전 상태는 독립이다. 비동기 리소스 준비 중 중복 클릭·늦은 성공·취소/결과 전환에는 requestId와 버전을 확인하고 잔여 리소스를 정리한다.

#### 3.3 구매와 준비 단계 계약

1. `purchase(team,typeId,requestId)`: PREPARATION, 결과 없음, 유효한 진영·목록·양의 정수 가격·잔액·구매 가능 제한 확인. AI도 같은 진입점 사용.
2. 이미 처리한 requestId는 기존 결과를 반환하고 재차감하지 않는다. 중복 클릭, 예외, 실패에서도 **잔액 차감과 예비 생성은 둘 다 반영 또는 둘 다 미반영**. 점수 목표에 도달해 RESULT가 확정된 뒤에는 어떤 구매도 허용하지 않는다.
3. 구매 성공 후 실제 점수·예비 카드 갱신. 구매 전 UI는 가격과 구매 후 잔액을 **표시**하며 입력란은 만들지 않는다. 가격 부족, 에셋 미준비, 상한 등은 사유를 표시한다. 구매 자체와 배정/투입 성공을 혼동하지 않는다.
4. `assign(shipId,target)`: 준비 중 동일 진영의 예비만 기존 함대 또는 새 함대 초안에 배정. 각 예비 함선은 최대 한 요청만 소유. 배정을 취소하거나 바꿔도 환불·가격 변동 없음. 사용자 명령·기존 생존 함선 pose·HP·무장·재장전은 유지한다.
5. 준비 시간 중 점수·재장전·투사 표현 수명·시뮬레이션 틱은 변하지 않는다. 미리보기는 투입 위치의 제안이며 실제 득점·충돌 객체가 아니다.

#### 3.4 시작 면 투입과 원자적 활성화

기존 시작 방향을 보존해 아군은 +Z 시작 면에서 -Z 방향, 적은 -Z 시작 면에서 +Z 방향으로 진입한다. 반경만큼 면 안쪽으로 이동한 후보 중심을 생성하고, 시작 면 중앙부터 대칭적인 3D 격자 후보를 고정 순서로 탐색한다. 간격·탐색 범위·최대 후보 수는 설정 가능한 임시값이며 실패와 다른 결과를 혼동하지 않는다.

- 각 후보는 전장에 **구 전체가 포함**되어야 하며 기존 생존 함선, 적 함선, 같은 재개 배치에서 앞서 예약한 함선의 보수적 구와 겹치지 않아야 한다. 경계·접촉 허용 여유를 명시하고 양측에 동일하게 적용한다. 공간 셀/AABB는 후보 검색용이고 정확한 구 겹침을 후속 계산한다. 저장 순서에 의존하지 않는 안정 ID/후보 순서를 사용한다.
- 임시로 1척 단위 부분 투입을 허용하고 결과를 함선별로 기록한다. 한 번에 한 척씩 같은 배치 스냅샷에 성공한 위치를 예약해 서로 겹치지 않는다. 실패한 함선은 ASSIGNED 대기로 남고 자동 환불하지 않는다. 추가 시도는 다음 준비→전투 재개 시에만 실행한다.
- 기존 함대에 합류하는 함선도 시작 면에서 실제 생성하고 기존 함대 슬롯을 향해 이동한다. 원래 함대나 기존 함선을 순간이동시키지 않는다. 함선 수 변화로 슬롯 템플릿이 재생성되더라도 기존 사용자 순서와 살아 있는 함선의 물리 상태를 보존한다. 신규 함대는 시작 면에 anchor를 만들고 전장 안쪽을 기본 목적지로 한 기존 MOVE 명령을 부여하며 사용자가 이후 수정할 수 있다.
- 단일 함선의 activation은 **배치 예약 + 모델 복제·무장/안전 준비 + 고유 ID/소속 검증**이 모두 성공한 후 전장 상태와 뷰를 함께 공개한다. 실패하면 예약·부분 뷰/안전 자료를 해제하고 예비와 소속을 유지한다. 전투 시작 도중 함대/함선 ID가 이미 존재하면 오류로 중지하고 중복 생성하지 않는다. 전부 대기여도 정상적인 기존 함대의 전투 시작을 막지 않으며 실패 이유를 UI에 남긴다.
- 재개는 준비 중 **투입 요청 및 AI 행동 확정 → 현재 모델/배치 재검사 → 성공분 활성화 → 재기 판정 → RUNNING** 순서. 준비 단계에서 이미 생성된 전투 객체는 없다. 요청 순서는 양측 동일한 규칙으로 결정하고 예약은 전 진영이 공유한다. 비동기 준비 중 RUNNING을 조기에 켜지 않는다. 재개 중 중복 입력을 잠그고 오류/완료 후 해제한다.

#### 3.5 승패·대기·교착

목표 점수 판정은 현행처럼 같은 고정 틱의 피해·격침 → 9구역 양측 득점 동시 가산 → 현재 잔액 기준 승리 순서다. 양쪽이 같은 틱 목표에 도달하면 잔액이 큰 진영 우선, 동점 무승부는 시제품 권장안이다. RESULT 이후 구매·AI·투입·틱 중지.

재기 판정은 **한 진영의 생존 전장 함선**, 유효한 예비/배정 함선, 유효 가격으로 살 수 있는 잔액을 분리해 계산한다. 생존 0이라도 예비 또는 구매 가능하면 즉시 패배시키지 않는다. 한쪽이 세 조건 모두 없어 영구 재기 불가이고 상대가 생존 또는 재기 가능하면 전자 패배; 양측 모두 영구 불가이면 무승부는 시제품 권장안이다.

배치 장소가 지금 막힌 사실은 영구 불가능의 증거가 아니다. 상대가 이동·격침 등으로 바꿀 수 있으면 대기로 유지한다. 양측 생존 0인데 최소 한쪽이 구매/예비를 보유한 상태는 즉시 전멸 승리로 처리하지 않고 PREPARATION으로 전환해 구매·배정을 허용한다. 양측 생존 0이고 배치 위치가 고정 장애 또는 예약에 의해 지속 불가한 경우는 별도 **교착**으로 표시한다. 3단계 시제품은 동일 상태의 무변화 재개 시도 상한을 설정하고 도달하면 무승부를 제안한다. 가격·보유·배정·점수·장애 또는 성공 투입이 바뀌면 카운터를 재설정한다. 상한은 임시값이며 게임의 최종 교착 규칙이 아니다. 일시적 적군 점유나 에셋 오류만으로 패배·무승부를 강제하지 않는다; 에셋 오류는 복구/대기 상태로 보여준다.

준비 중 수동 정지와 구간 종료는 재개 시 기존 남은 시간 보존/새 구간 설정이라는 2단계 규칙을 유지한다. 재기 판단은 피해·득점 이후 및 구매/성공 투입 후의 확정 상태에서 실행하며, 양측 동시 결과는 한쪽 순서가 아닌 단일 스냅샷으로 결정한다.

#### 3.6 적 AI

AI는 준비 단계 진입 시 1회 결정하고 시뮬레이션 틱마다 구매/전장 전수 검색을 반복하지 않는다. 양측이 동일한 scores·함종 목록·purchase/assign/배치 검증을 사용하며 별도 무료 함선·할인·투입 예외를 두지 않는다. 사용자 구매와 AI 구매는 서로 다른 계좌이지만 각 팀 내 중복 확정과 실행 순서는 결정적이어야 한다.

- 현재 공개된 각 구역의 양측 실제 생존 함선 수·배율과 기존 함대 위치를 스냅샷으로 읽는다. 기본 목표는 도달 가능한 구역 내부 격자점; 간단한 임시 가중치로 득점 잠재력과 거리, 이미 배정된 아군 수를 비교하고 같은 값은 zoneId/fleetId 순으로 정한다. 목표가 없으면 기존 유효 목적지를 유지한다. 구역 선택은 기존 MOVE이며 새 점령 정책을 만들지 않는다.
- 기본 구매 정책은 자금·가격·현재 전장 전력·예비 상태·승리까지 남은 점수를 보고 0 또는 1척을 선택하는 보수적 시제품 안이다. 각 값은 설정·검증 가능한 임시값; 자금/상한이 허용돼도 무조건 구입하거나 자동으로 승리 직전 점수를 소비하지 않도록 한다. 잔액 부족·에셋 불가·배치 실패는 사용자와 같은 결과를 따른다.
- AI 대기/재시도 및 구매 횟수는 제한하고 AI 실패가 플레이어 구매를 되돌리거나 전투 시작을 무한히 막지 않는다. 판단은 준비 스냅샷에 고정되며 플레이어가 시작하기 전 명령을 여러 번 바꿔도 중복 구매하지 않는다. 미래 정보·상대 미공개 정보 사용 여부는 향후 난이도 설계로 남긴다.

#### 3.7 사용자 흐름과 화면

하단 함대 탭·높이별 함선 카드·우측 전투 시작을 유지한다. 항상 현재 양측 점수/목표를 상단 상태에 표시하고, 준비 단계에서만 **함선 구매/예비**를 여는 단일 진입점을 하단 함대 창에 둔다. 기본 함선 카드에 이름·가격·구매 후 잔액을 표시하고 클릭으로 한 척씩 구매한다. 숫자 입력·수량 입력란은 만들지 않는다.

예비 카드는 격침 슬롯과 다르게 명시한다. 예비 카드를 기존 함대 탭 또는 새 함대 생성 선택지에 드래그하거나 카드 선택 후 대상 클릭으로 배정한다. 함대 탭의 예비/대기 표시가 활성 함선 수·구역 득점 수와 혼동되지 않게 한다. 새 함대 초안은 확정 ID와 시작 면을 갖되 성공 투입 전 전장/미니맵에 활성 함대처럼 표시하지 않는다. 시작 면·대기 이유를 보조 정보로 보여준다.

전투 시작 버튼은 단 하나이며 대상은 전체 전투다. 목적지 draft나 리소스 준비 중에는 시작을 막고 이유를 표시한다. 배치 불가 요청이 있더라도 대기를 유지하며 기존 전력으로 시작할 수 있다. 구매 중복 클릭·다른 함대 선택·메뉴 닫기/다시 열기 후 실제 잔액과 예비 상태를 새로 읽는다. 플레이어의 원래 함대 탭/명령과 0~2단계 카메라·미니맵 조작은 유지한다.

#### 3.9 검증 사례와 측정

- **경제:** Z13/14; 정확히 가격 보유·잔액 0, 1점 부족, 무효/0 가격, 잘못된 진영/함종, RESULT/RUNNING 중 구매, requestId 중복·중복 클릭·예외 후 상태 불변, 같은 잔액으로 양측 동일 결과.

- **활성화:** 모델·리깅·해시 검증 실패/비동기 취소, 부분 실패 롤백·ID 중복, 성공 후 view/rig/시뮬레이션/미니맵 1:1, 격침 후 화면 및 득점 제외. 예비는 득점과 사선 후보에 포함되지 않음.
- **AI:** 같은 가격/제약·잔액 차감, 준비 단계 1회, 구역 내부의 유효 목적지, 타깃 동률의 결정성, 공간 부족/에셋 실패에서 무료 생성 없음, 선택하지 않은 기존 플레이어 명령 불변.
- **결과:** Z16~Z19; 양측 목표 동시 도달, 피해·득점·시간 종료 동시, 전멸+예비, 전멸+구매 가능, 일시적 차단, 양측 재기 불가, 교착 카운터 재설정, RESULT 후 입력 불가.
- **브라우저·회귀:** 시작 16척→획득 점수→한 척 구매→배정→시작 면 투입→전투→격침/준비 복귀의 실제 FBX 실행; 세 함대 선택 경로, 드래그/클릭 편성, XZ/YZ 입력·줌·복원, 구매 버튼/상태·오류, 작고 넓은 화면, 장시간 메모리·성능.
- **측정:** 기기·브라우저·GPU·기존/증원 함선·활성 포탑·밀집도·실제 게임 틱·시드·화면 조건을 기록하고 구매/배치 처리 시간과 후보 수, 전투 프레임 p50/p95/p99·틱·GC를 분리한다. 동일 규칙·동일 조건의 반복 전후값만 비교한다. 구매 빈도·승리까지 시간·잔액·AI 구매·투입 성공과 중앙 구역 점유를 관찰해 가격을 조정하며 임시값을 확정으로 표현하지 않는다.

### 단계 4 — 순찰·편성 및 표적 배분 확장

**작업:** 2개 이상의 서로 다른 격자 경유점을 갖는 PATROL, 경로 순환과 인덱스 보존을 구현한다. 기존 클릭·드래그 중심 편성을 유지하고 사격 가능성·표적 유지·이미 배정한 피해에 기반한 2단계 공동 배분을 개선한다. 기본 배분을 이 단계까지 미룬다는 뜻은 아니다.

**검증:** 명령 유지 사격 중 순찰이 유지되고 중간 경유점에서 대기 자세로 복귀하지 않는다(T02, 통합본 G06). 유효하지 않은 경로를 거부하고 준비 복귀·경로 변경·순서/간격 수정 시 무관한 함대의 명령을 보존한다. 과잉 화력 완화와 필요한 집중을 확인한다(T12·T13).

#### 4.1 상세 설계의 상태와 범위

- 상태: **4-A~4-E 시제품 구현 및 대표 시나리오 통합 검증 완료**, 2026-11-24. 아래 검증 기록의 범위만 확인했다. [v2.2 기획](../spec/game-design-v2.2.md)의 순찰·표적 원칙, 이 문서의 하단 UI와 [2단계 전투 재설계](phase2-data-oriented-combat-design.md)를 따른다. 기획 확정, 권장, 시제품 임시 선택을 구분한다.
- 범위: 함대별 MOVE/PATROL, 순찰 경로 편집과 이동 격자 유지, 명령 유지 사격, 함대 공유 후보와 무장별 근사 사격 가능성/표적 유지/예상 피해 배분, 0~3단계 회귀·동일 조건 성능 관찰.
- 단계 5의 조우 중단·복귀, STANDOFF/POINT_DEFENSE, 단계 6의 관통/포위와 순찰 AI 전략은 구현하지 않는다. 보존할 순찰 상태와 확장 경계만 만든다. 3단계는 시제품이며 자연 득점→최종 승패 장시간 검증·밸런스는 별도다.
- 2단계의 즉시 레이 판정, 무장 각도·속도, 자기/아군 사선 안전, 사용자 허용 근사·실드 향후 계획을 변경하지 않는다. 개별 무장 조준이 함대 목표/경로/진형을 직접 변경하지 않는다.

| FleetCandidateSnapshot | fleetId, snapshotTick, 적 후보 IDs·근사 위치/HP | 매 평가 주기의 파생 자료. 기존 3D 공간 인덱스를 사용하고 점수 구역·명령 격자와 분리. |
| ReservedDamage | snapshotTick, team, targetId→누적 예상 피해 | 한 평가 배치 내의 임시 데이터. 실제 HP·발사 사건 아님. 사전 예약 부족·차폐 실패·갱신 사이 사망은 다음 평가에 반영. |

기존 `fleet.destinationIndex/destination`는 UI·AI·이동에서 직접 사용 중이다. 한 번에 제거하지 않고, 이행 단계에서 기존 값을 MOVE 권위 명령으로 복사하고 기존 소비자를 **단일 활성 목표 조회**로 전환한다. 새 상태와 옛 목적지의 양방향 독립 쓰기를 금지한다. 초기 A/B/E, + 빈 함대, 구매·증원 신규 함대는 같은 생성 경로로 유효한 MOVE 기본값을 받는다. 빈 함대 생성/삭제와 예비 상태는 3단계 규칙을 따른다.

AI의 기존 `setDestination` 호출은 **적 함대의 MOVE 목적지를 변경하는 명시적 API**로 이행한다. 플레이어 경로나 다른 함대, 저장된 순찰 경로를 건드리지 않는다. 4단계에서 적 AI는 기본 MOVE만 사용한다. 5단계용 조우 보존 자료는 현재 이행 시 별도 필드 경계만 두고 미구현 동작을 만들지 않는다.

#### 4.3 순찰 확정·이동·시간

1. 준비 단계에서 경로 전체를 검사한다: 각 지점의 안전 정수·유한 변환·전장 포함, **서로 다른 지점이 최소 2개**, 경로 길이 2 이상, 최대 길이 설정 이하. 인접/비인접 중복을 금지하지 않되 같은 지점만 반복하는 경로는 거부한다. 최대 길이는 자원 보호용 설정 가능한 시제품 값이며 UI 숫자 입력은 없다.
2. 성공하면 복사본을 단일 명령으로 확정하고 revision을 증가시킨다. **실제로 수정한 경로**는 시제품 기준 첫 지점 index 0부터 재개한다. 저장 없이 닫기·취소·검증 실패·수정 없는 저장은 기존 경로·revision·index 보존. 다른 함대의 명령과 물리 상태는 건드리지 않는다.
3. 준비→RUNNING에서 활성 정책이 PATROL이면 활성 목표는 `gridToWorld(points[index])`, MOVE이면 movePoint다. 정책 전환 전의 비활성 MOVE/PATROL 설정은 보관한다. PATROL 설정이 유효하지 않으면 선택·전투 시작을 조용히 수행하지 말고 기존 활성 명령과 실패 사유를 유지한다.
4. 각 고정 틱에 순찰 경유점 도착을 기준점 위치와 속도의 명시된 허용값으로 결정한다. 같은 위치/근접 지점은 최대 `points.length`회 확인 후 다음 이동 대상으로 넘어간다. cap 초과나 모든 지점이 실질적으로 도착 판정이면 인덱스와 이유를 기록하고 그 틱의 반복을 끝낸다. 빠르게 접근 중인 함대의 점을 속도만 무시해 조기 통과시키지 않는다. 관통/과속, 선회와 모서리 처리 방식은 기존 MOVE 속도·가속 한계 안에서 시제품으로 검증한다.
5. 중간 지점 처리는 `IDLE`/비전투 수평 복귀를 호출하지 않는다. 다음 목표·대형으로 이동하며 물리 위치·속도·회전을 갑자기 바꾸지 않는다. 기존 MOVE의 최종 도착과 수평 대기는 유지한다.
6. 전투 정지·재개/남은 시간 종료는 현재 index·경로·pose·속도·무장/재장전·scoreTicks를 보존한다. 다른 함대 선택, 슬롯 교환·간격 조정·예비 투입만으로 index 초기화 금지. 명령 유지 사격의 표적·사선·피해는 활성 이동 명령에 쓰지 않는다.
7. 같은 상태·완료 틱에서는 경유점 전환이 렌더 프레임 횟수에 의존하지 않는다. 동일한 좌표만 있는 구경로나 전장 밖 경유점은 저장 전에 오류를 표시하고 기존 경로를 유지한다. 목적지/경유점 전환과 점수·결과 우선순위는 기존 2~3단계 틱 계약을 유지한다.

#### 4.4 경로 편집·표시와 함대 조작

하단 선택 함대의 이동 정책을 **목적지 이동 / 경로 순찰**의 클릭형 선택으로 바꾼다. 순찰 선택 시 같은 영역에 경유점 카드와 추가·저장·취소를 표시하고, 이 기능을 위해 중복된 전역 명령 버튼이나 숫자 입력을 만들지 않는다. 카드 드래그로 순서를 바꾸고 삭제 버튼으로 제거한다. 드래그 대안은 카드 선택 후 대상 카드 클릭이며 같은 목록에서 처리한다. 이전 정책·경로는 편집 완료 전까지 유지된다.

- 경유점 추가/변경은 기존 XZ→YZ UI를 재사용한다. 한 점의 Y 확정은 **경로 초안에만** 반영되고 목록에서 더 추가/수정 가능하다. 기존 MOVE의 2단계 확정은 그대로 즉시 해당 MOVE 명령을 확정한다. 두 경로의 취소 범위를 구분한다.
- 수정 대상·함대 ID·baseRevision을 캡처한다. 2단계 좌표 입력 중 함대 변경·정책 변경·전투 시작은 잠근다. 경로 목록 편집 중에도 저장 또는 취소 전에는 전투 시작과 함대 전환을 막고 이유를 표시한다. XZ↔YZ 이전/취소는 점 입력만 취소하고 경로 편집으로 돌아가며, 전체 경로 취소는 최초 명령을 보존한다.
- 경로의 드래그가 확정 전에 일부만 시뮬레이션에 반영되지 않아야 한다. 최소 두 지점·서로 다른 지점 조건을 만족하기 전 저장 불가 사유를 표시한다. 편집 중 함대 삭제·결과 확정·외부 상태 revision 변경은 commit을 거부하고 초안/이유를 명확히 처리한다.
- 전장에는 선택 함대의 경유점 순서와 마지막→첫 지점 연결을 표시하며 활성 목표를 구별한다. 미니맵은 선택 평면에 같은 확정 경로를 투영한다. 초안은 확정 경로와 시각적으로 구분하고, 숨겨진 축은 목록/호버에서 확인한다. 좌표를 직접 입력하지 않는다.
- 경유점 수가 많을 때 목록은 가로 스크롤하며 함대 탭·전투 버튼을 덮지 않는다. 전투 중 목록은 읽기 전용이고 다음 목표 표시만 갱신한다. 기존 미니맵/전장/함대 탭 세 선택 경로와 높이별 함선 카드·구매/예비 흐름을 보존한다.

#### 4.5 후보 생성·근사 사격 가능성

기존 `battleCombat`은 함대별 3D 셀 후보를 모으고 함선마다 가까운 후보 최대 4개를 선정한 뒤 거리와 무장 배정 수만으로 선택한다. 기존 5Hz 갱신과 45 사거리, 피해 20·재장전 2초는 현 시제품 설정이지 4단계 성능/밸런스 확정값이 아니다.

1. 틱의 단일 이동 후 생존·팀·pose 스냅샷을 사용한다. 기존 인덱스로 함대/근접 범위 후보를 공유하고 안전한 stable ID 순서를 유지한다. 함선별 거리·팀·생존을 확인하고 상위 K 근사 후보를 선택한다. K·탐색 주기·사거리는 설정 가능하며, 가장 가까운 K에만 묶여 모든 무장이 영구적으로 무효 후보만 보지 않도록 다른 셀/후보 확장 또는 교대 평가를 명시적으로 구현·계측한다.
2. 각 무장은 불변 포구/장착 변환과 실제 함선 pose, 회전축/부호·각도·속도에 기반해 **도달 가능한 방향**을 근사 평가한다. 고정포는 선체/포구 방향의 실제 사격 허용 범위만 사용하고, 회전포는 제한 내 접근 가능성을 고려한다. 각 무장의 여러 포구 중 사용 가능한 포구가 있으면 후보로 남긴다. 조준 가능은 당장 발사 가능을 뜻하지 않는다.
3. 도달 가능성 검사는 제한된 샘플/보수 근사로 시작할 수 있다. 오차·부품별 누락과 고정포/회전포의 차이를 기록하고 정밀 메시 검사와 같은 수준이라 주장하지 않는다. 후보가 전부 모호하거나 차단됐을 때 평가 예산을 초과하면 안전하게 발사를 보류하고 나중에 다시 평가한다; 후보 부족을 성공 사격으로 해석하지 않는다.
4. 실제 발사는 기존과 같이 **현재 도달 각도·포구별 자기 구조 검사·첫 아군/적 접촉·쿨다운**을 사용한다. 예측 표적·예상 피해는 실제 사선 확인이나 피해를 대신하지 않는다. 자기 선체·가동 구조·아군을 일괄 무시하지 않는다.

#### 4.6 유지·예상 피해 기반 표적 배분

각 표적의 예정 피해는 **현재 평가 스냅샷의 값**으로 함대별 공유한다. 기획은 함대 공동 배분이므로 기본 집계 범위는 같은 함대다; 다른 함대의 전역 예약은 후속 확장이다. 배분 순서는 fleetId→shipId→weaponId stable 순이며, 평가 시작 시 그 함대의 예약량을 0으로 만든다.

- 후보 기본 점수는 거리/근사 사격 가능성 등을 사용하고, 이전 목표가 여전히 유효하면 유지 보너스, `reservedDamage/현재 HP`가 커지면 포화 페널티를 적용한다. 비교 함수·동률 순서·가중치는 설정 가능한 임시안이다. HP 0/무효 값은 후보에서 제외하고 0 나눗셈을 방지한다.
- 재장전 중에도 조준 표적은 유지할 수 있지만, 피해 예약에는 지정한 짧은 시간 창 안에서 **실제로 준비될 수 있는 무장**의 기대 피해만 포함한다. 포구별 독립 피해를 중복하거나 단일 무장 포구 수를 놓치지 않도록 실제 발사 단위와 일치시킨다. 확인 전 차폐 가능성이 있는 예약은 추정치이며 실 피해를 차감하지 않는다.
- 유효한 후보가 여럿이면 과잉 예약 대상의 점수를 낮춰 다른 대상을 선택할 수 있다. 다른 대상이 범위 밖·고정포 각도 밖·불가라면 유일한 유효 대상에 여러 무장을 배정한다. 따라서 1:1 강제도, 무조건 최근접 1척 집중도 아니다.
- 기본 재평가는 기존 5Hz 조준과 별도 설정하되 시제품은 동일 5Hz로 시작한다. 표적 사망·팀 변경·거리 초과·무장/모델 무효 시 그 무장에 대해 다음 **전투 고정 틱**에 즉시 무효화하고 발사를 보류하며, 새로운 후보 선택은 가장 빠른 다음 배분 갱신에서 수행한다. 고정 틱마다 전체 포구 행렬·정밀 메시를 반복하지 않는다.
- 실제 발사/차폐 실패, 사격 불가 지속 및 회전 제한으로 인한 장기 고착은 진단 카운터와 제한된 재평가로 처리한다. 예상 피해는 한 배분마다 다시 구성하므로 오래된 예약이 영구 유지되지 않는다. 유지 보너스로 무효 표적을 붙잡거나 실제 피해/사선 규칙을 바꾸지 않는다.
- 처리량은 활성 무장 수·후보 수·실제 발사 사건과 공간 밀도에 의존한다. 예측/정밀 검사를 분리하고 기존 포구 행렬·회전 근사의 비용과 할당량을 계측한다. JS/TypedArray/Worker/Wasm 중 무엇이 빠른지는 동일 입력 측정 전 확정하지 않는다.

#### 4.7.1 구현 및 검증 기록 (2026-11-24)

- 구현: 함대별 목적지와 순찰 경로를 분리하고 고정 틱에서 경유점을 순환한다. 순찰 초안은 두 평면 좌표 입력, 추가·삭제·순서 변경·저장·취소를 지원한다. 선택된 경로와 활성 목표를 전장과 미니맵에 표시한다.
- 표적 배분은 함대 공유 후보를 재사용하며 무장 도달 근사, 기존 표적 유지와 예상 피해 예약을 반영한다. 실제 피해와 아군·자함 사선 안전은 기존 포구별 판정을 따른다. 후보 수 제한과 회전식 확장은 근사다.
- 계산 검증: 세 경유점 반복 순환, 중단·재개, 무효 경로의 원자적 거부, 다른 함대와 기존 목적지 보존을 확인했다. 표적 점수의 분산·단일 대상 집중·표적 유지·격침 대상 제외를 확인했다.
- 브라우저 통합 검증: 실제 FBX 16척에서 경유점 두 단계 입력, 저장 전 명령 보존, 0개 경로 거부, 카드 클릭 순서 변경과 취소, 저장 후 순찰 유지, 점수 60 시험 주입 후 구매한 함선의 기존 순찰 함대 증원(17개 모델), 전투 시작·일시 정지, 1280×720에서 900×650으로 리사이즈 후 경로 표시 2개 유지 확인. 페이지 오류 0건. 신규 함대 증원 및 드래그·모든 해상도 조합은 확인하지 않았다.
- 발사 판정의 통제 시험: 고정된 가상 발사 사건으로 아군이 먼저 닿는 경우 피해·발사 0, 자함 안전 검사 실패 시 피해·발사 0, 안전한 적중 시 적 체력 100→80 및 사건 1건을 확인했다. 이는 실제 모델의 모든 포구와 각도에 대한 시각적 검수가 아니다.
- 재현성: 동일 초기 상태에서 고정 틱 600회를 1회씩과 10회씩 묶어 실행한 계산 시험에서 10초 시점의 순찰 인덱스 1, 기준점 (-8, 0, 43.325), 점수 26:30과 모든 함선 HP가 일치했다. 무장 교전이 없는 시험이며 실제 화면 주사율 변화의 전투 재현성은 별도다.
- 추가 UI·증원 검증: 경유점 3개를 드래그하여 순서 변경한 뒤 하나를 삭제·저장했다. 점수 시험 주입으로 구매한 함선을 신규 함대에 투입하고 그 함대의 순찰을 설정했을 때 기존 함대 순찰이 유지됐다. 360/600/900/1280px 폭의 일반 화면에서 미니맵과 함대 창이 겹치지 않았으며 페이지 오류가 없었다. 편집기를 연 상태의 모든 해상도 조합까지 검증한 것은 아니다.
- 표적 확장·무효화: 실제 경순01 중앙 2포구 무장의 회전 범위를 시험용 0도로 좁히고, 사각 밖에 가까운 후보 28개와 방향에 맞는 먼 후보 1개를 배치했다. 첫 갱신에는 후보가 없었고 0.2초 뒤 확장 갱신에서 먼 후보를 선택해 포구별 발사 후보 2개를 생성했다. 대상 제거 시 다음 고정 틱에 표적이 해제됐다. 실제 모든 모델의 모든 각도에 대한 검증이 아니라 통제된 대표 사례다.
- 순찰 중 교전 재현성: 실제 경순01 아군 1척·적 1척으로 고정 틱 240회를 1회 및 10회 단위로 묶어 실행했다. 두 실행에서 4초 동안 공격 3건, 적 HP 40, 순찰 인덱스 1→0, 위치·표적·점수가 일치했고 IDLE 전환 없이 PATROL을 유지했다. 벽시계 프레임 손실과 무관한 고정 틱 입력 비교이며 실제 주사율 변경 시험은 아니다.
- 최종 코드 계측: Edge 헤드리스·SwiftShader, 1280×720, 경순01 FBX 16척, 준비 후 6초 단일 실행. 조우 전은 기본 배치, 조우 후는 아군 기준점 Z=18·적 Z=-18로 이동한 별도 조건이다. 각 시나리오는 재적재했으며 자연 이동으로 같은 전투를 재현한 비교가 아니다.

#### 4.9 계측과 결정해야 할 항목

기존 이슈 #1과 동일한 조우 전/후 16척·6초 기준의 **환경·정확한 실제 시간, 완료 틱/게임 시간, 렌더 콜백/FPS 참고, 프레임 중앙값/p95/최대, battleCombat·회전·포구/segment·update 호출과 누적 시간, 공격 사건·생존 함선**을 수집한다. p99·틱 단계별 시간, 함대 검색/후보 수, 도달 평가, 유지·재배정·사격 보류, 예상/실 피해, 버린 틱 시간 및 할당/GC는 추가 진단이다. 계측 후크·시드·장비/GPU/브라우저·카메라·명령·실제 이벤트와 정확도 차이를 기록한다. 경로가 다른 경우 동일 조우와 동작량을 강제할 수 없으므로 시나리오를 분리해 정직하게 비교하며 서로 중첩된 함수 시간을 합하지 않는다. SW 렌더 결과를 사용자 GPU 성능으로 환산하지 않는다.

시제품의 경로 길이 상한·허용 거리/속도, 후보 K와 확장 주기, 유지 보너스·피해 예측 창, 목표 미도달 보류 시간·진단 예산은 실험 설정이다. 5단계 조우 상태 복귀 시 인덱스 적용, 목표 편집 중 외부 상태 변경, 목표 차폐의 세부 재평가와 다함대 전역 공유는 후속 의사결정이다. 기존 사용자 명령을 무조건 바꾸는 최적화나 보이지 않는 AI 특혜를 도입하지 않는다.

### 단계 5 — 조우 공통 처리·거리 유지·거점 방어

**작업:** 진입/해제 조건, 주 대상 잠금, 기존 이동 임무 보존·복귀를 공통 상태로 만든다. STANDOFF의 접근·이격·유지와 전면 대형, POINT_DEFENSE의 사용자 지정 또는 구분 표시된 자동 거점과 구형 슬롯을 구현한다.

**검증:** 조우 종료 후 MOVE 또는 PATROL의 원래 진행을 복구한다(T03). 대치 경계에서 진동하지 않고 활성 교전의 Pitch/Roll을 일괄 금지하지 않는다(T10). 거점 방어는 적을 추적하지 않으며 도착 전 적이 떠나도 거점 도달을 먼저 완료한다(T07·T08·T25). 준비 중 수정된 교전 명령의 적용 시점은 구현 전에 결정한다.

#### 5.1 범위·현재 기반

- 상태: **5단계 시제품 구현 / 대표 통합 검증 완료, 잔여 시각·성능 검수 있음**, 2026-11-24. [v2.2 기획](../spec/game-design-v2.2.md)의 확정 규칙을 우선하며 아래 수치와 미결 사항 처리 방법은 시제품 선택이다.
- 5단계는 MOVE/PATROL 위에서 OPPORTUNISTIC_FIRE, STANDOFF, POINT_DEFENSE를 실행한다. BREAKTHROUGH/ENCIRCLE, 상시 거점 수비, 전 함종 밸런스는 범위 밖이다. 4단계는 대표 사례 검증이며 전 모델과 실제 GPU 검증은 남아 있다.
- 현 코드는 함대별 movement와 destination, 고정 틱 이동, 함선 공간 인덱스, 5Hz 무장 배분·포구별 사선 판정을 가진다. 조우 상태·교전 대형·전술 선택은 아직 없다. 전술 목표로 destination을 덮어쓰면 순찰 인덱스와 명령 표시가 손상되므로 이동 명령과 실행 목표를 분리한다.

#### 5.2 데이터 소유·틱 순서

| 소유 | 데이터 / 역할 |
|---|---|
| 함대의 사용자 명령 | movement의 MOVE 목표·PATROL 경로/인덱스·revision, 선택 교전 대응, 선택적 사용자 방어 거점. 전술 계산은 이를 덮어쓰지 않음 |
| 함대의 조우 실행 | MOVEMENT/ACTIVE, 잠긴 적 함대 ID, 정책, 이탈 누적 시간, 1틱 재진입 제한, 방어 거점 스냅샷·출처·도착 여부, 임시 전술 목표와 대형 상태 |
| 함대의 물리 실행 | 실제 기준점·속도·회전, 해당 틱 실행 목표, 자세 MOVING/ENGAGING/IDLE, 슬롯. 보간은 렌더용이며 판정에 사용하지 않음 |
| 무장·피격 | 기존 함대 공유 후보, 무장별 표적·포구 안전·첫 피격. 조우의 대상 함대 ID가 모든 무장의 표적 ID를 덮어쓰지 않음 |

고정 틱: ① 살아 있는 함선의 위치 스냅샷 및 공간 인덱스 ② 함대 경계와 조우 관계 갱신 ③ 정책별 실행 목표·대형 결정 ④ 기존 가속/회전 제한을 적용해 기준점과 슬롯 추종 ⑤ 기존 전투·피해·득점 ⑥ 다음 틱에 소멸 결과 반영. 준비 상태에서는 전체 틱을 실행하지 않는다. 대상이 같은 틱에 격침되면 그 틱의 사격은 기존 동시 피해 규칙을 따르고 다음 틱에 조우 대상을 무효화한다.

조우 탐색은 함선마다 모든 적 함선을 검사하지 않는다. 살아 있는 함선 스냅샷에서 함대별 AABB·중심·경계 반경을 한 번 만들고 함대별 후보를 공유한다. 함대 경계 구의 AABB를 별도 공간 인덱스에 등록하고 진입 범위로 확장한 AABB를 질의해 적 함대 후보를 얻는다. 함대 중심 거리에서 양쪽 경계 반경을 뺀 거리(최소 0)로 근사 평가한다. 잠긴 대상은 ID로 직접 재검사한다. 후보 탐색 주기는 시작 시 5Hz, 잠금 대상의 소멸 및 정책 변경 확인은 매 고정 틱으로 제안한다. 큰 함대의 경계 구 과대 판정은 허용 가능한 근사인지 관찰한다. 후보가 없거나 함대가 비면 안전하게 해제한다. 동점은 함대 ID 순서로 정한다.

#### 5.3 조우 상태·명령 변경

1. MOVEMENT에서 OPPORTUNISTIC_FIRE는 조우 상태 없이 현재 이동과 사격을 유지한다. 나머지 정책은 최근접 유효 적 함대가 진입 거리 이내이면 잠그고 ACTIVE에 진입한다. 적 함대 잠금은 개별 적 함선 사격을 강제하지 않는다.
2. 진입 시 movement는 그대로 보존하고, 전술 대형·목표와 거점 방어의 고정 거점을 초기화한다. ACTIVE 동안 순찰 인덱스는 전진하지 않는다. 전술 이동은 연속 월드 좌표로 처리한다.
3. STANDOFF는 대상 소멸 또는 해제 거리 밖의 연속 유예 충족 시 종료한다. POINT_DEFENSE는 대상 소멸/유예가 먼저 발생해도 기록만 하고 거점 도착 후 종료한다. 유예 중 다시 범위 안으로 들어오면 타이머를 0으로 되돌린다.
4. 종료 시 전술 목표와 잠금을 제거하고 이동 격자 및 보존된 현재 사용자 명령으로 복귀한다. 물리 위치·속도·회전은 초기화하지 않는다. 그 틱에는 새 조우에 진입하지 않고 다음 틱부터 후보를 평가한다. 대형 전환은 슬롯 목표를 바꾸고 기존 속도·가속 한계로 추종하며 순간이동하지 않는다.
5. 사용자가 준비 단계에서 명령을 변경하면 시뮬레이션은 정지된 채 사용자 명령만 즉시 갱신하고, 재개 첫 고정 틱에 반영한다. 이동 목표/경로 변경은 현재 교전을 유지하면서 복귀할 최신 명령을 바꾼다. 경로를 실제 수정하면 4단계 규칙대로 인덱스 0, 변경이 없으면 기존 인덱스를 보존한다. 교전 대응을 다른 정책으로 바꾸면 명시적 사용자 변경을 우선해 현재 조우를 종료하고 다음 틱에 새 정책으로 진입 여부를 판단한다. POINT_DEFENSE의 도착 우선은 자동 해제에 적용하며 명시적 정책 변경을 막지 않는다. 같은 정책의 사용자 방어 거점 변경은 재개 첫 틱에 기존 거점 스냅샷을 새 지정점으로 교체하고 도착 여부를 초기화한다. 편집 취소는 어떤 명령도 바꾸지 않는다.
6. 하나의 조우 대상이 격침되면 5단계 시제품은 종료 후 다음 틱에 다른 적을 다시 탐색한다. 대상 잠금을 유효 기간 중 매번 더 가까운 적으로 교체하지 않는다. 재진입 쿨다운, 동시 변경 충돌은 추가 관찰 대상이다.

#### 5.4 대치와 대형

- 시제품 설정 제안: 조우 진입 38, 해제 48, 이탈 유예 2초, 대치 거리대 24~32 월드 단위. 기존 무장 사거리 45와 별개 설정이며 밸런스 확정값이 아니다. 경계 기반 조우 거리와 대치 기준점 간 거리는 정의가 다르므로 경계 반경이 큰 편성에서도 실제 접근·해제가 가능한지 시험한다.
- 적 중심을 향하는 정규화 벡터를 전면 법선으로 한다. 현재 거리 >32면 대상 방향으로 접근, <24면 반대 방향으로 이격, 그 사이는 기준점 정지 목표를 사용한다. 목표는 전장 경계로 제한하며 접근·이격 속도와 가속은 기존 기준점 제한을 따른다. 정지 시 속도를 강제로 0으로 만들지 않고 감속한다. 임계점 교대는 거리대와 별도 전환 여유 또는 최소 유지 시간으로 억제하고 시험으로 수치를 정한다.
- FRONT_PLANE은 법선에 직교하는 두 축에 함선 수와 간격에 맞는 2D 격자 슬롯을 배치한다. 수직 방향 등 외적이 퇴화할 때 이전 유효 축 또는 다른 기준 축을 사용한다. 슬롯과 함선 ID의 매핑은 안정적으로 유지한다. 함선 손실·증원 시 재배치하되 순간이동하지 않는다.
- ACTIVE에서 기준점 속도 0이어도 ENGAGING이다. 적 방향으로 함대 자세를 갱신하되 Pitch/Roll을 일괄 0으로 제한하지 않는다. 사격은 기존 포탑 각도·포구별 자기/아군 차폐 검사를 통과해야 한다.

#### 5.5 거점 방어와 구형 슬롯

- 조우 진입 시 사용자 지정 3D 격자 거점이 있으면 그것을 고정한다. 없으면 MOVE 목적지 또는 현재 PATROL 경유점을 사용하고, 유효 목표가 없는 예외에서는 조우 시 기준점을 사용한다. 사용자 지정/자동/현재 위치의 출처와 적용 좌표를 표시한다. 자동 거점은 이번 조우 동안 고정하며 적 이동에 따라 움직이지 않는다.
- 방어 기준점은 기존 속도·가속 제한으로 거점에 이동한다. 기준점이 도착 거리와 속도 조건을 모두 만족하면 도착으로 판정한다. 적이 사라져도 도착 전에는 진행한다. 도착 후 이탈 유예 또는 대상 소멸이면 복귀한다. 방어 중에도 유효 포구는 기존 규칙으로 사격한다.
- SPHERE는 우선 안정된 ID 순서의 구면 슬롯을 사용한다. 1척은 중심, 2척 이상은 균일한 방향 표본과 설정 반경을 사용하고 기존 간격 단계로 반경 하한을 정한다. 경계 부근에서는 전술 슬롯 집합 전체를 전장 안쪽으로 평행 이동해 간격을 보존한다. 이때 함대 기준점·방어 거점은 변하지 않지만 슬롯의 기하학적 중심은 거점에서 이동할 수 있다. 대형 자체가 전장보다 클 때는 추가 제한이 적용되며 간격 보장은 별도다. 모든 수와 좁은 경계에서 충돌 없는 배치를 보장한다고 가정하지 않는다. 함선의 실제 위치는 슬롯을 연속 추종하며 개별 무장의 유효 사격각을 유지한다.

#### 5.6 UI·작업 순서

선택 함대의 기존 명령 영역에 명령 유지 사격/거리 유지 교전/거점 방어 버튼을 추가한다. 거점 방어를 선택하면 별도 위치 지정 및 자동 거점 상태를 표시하고, 기존 XZ→YZ 입력과 취소·카메라 복원을 재사용한다. 선택 중 함대 전환·전투 시작을 잠그고 좌표를 숫자로 입력받지 않는다. 전장·미니맵의 거점 표시와 현재 조우 상태는 선택 함대에만 명확히 표시한다. 기타 설명은 기존 도움말에 둔다. 지정된 거점을 자동으로 되돌리는 클릭 경로도 제공한다.

구현은 5-A 조우 데이터/정지·명령 반영, 5-B 탐색·잠금·해제와 MOVE/PATROL 복귀, 5-C FRONT_PLANE·거리 유지, 5-D 거점 입력·SPHERE·도착 우선, 5-E UI·기존 경제/전투 회귀 및 측정 순서다. 각 단계에서 실행 증거를 기록하고 일괄 미검증 완료로 표시하지 않는다.

- 2026-11-24 추가 실제 FBX 교전: 아군·적 각각 1척, 적 HP를 시험상 20으로 설정하고 기존 무장·안전 판정으로 전투했다. 거리 유지와 거점 방어 각각 아군 공격 3건으로 적 격침, 교전 종료 및 순찰 복귀를 확인했고 조우 중 경유점 인덱스는 유지됐다. 거점 사례는 복귀 시 원래 경유점에 이미 도착해 같은 틱에 다음 인덱스로 정상 진행했다. 점수 주입으로 구매한 함선을 기존 함대에 투입해 실제 FBX 17개와 ACTIVE 상태를 확인했다.
- 실제 아군 피격·구매 함선 격침: 1대1, 아군 HP 20의 한 배치에서는 900틱 동안 아군 피격이 발생하지 않았다. 별도의 16척 근거리 배치에서 아군 HP를 20으로 설정해 적 E-6의 사격으로 B-2·B-3 격침을 확인했다. 구매·배정한 실제 모델 ALLY-R1은 시험상 근거리 전장으로 재배치하고 HP를 20으로 설정했을 때 241틱에 E-1의 사격으로 격침됐으며 예비 기록이 DESTROYED로 갱신됐다. 자연 배치에서 구매 함선이 교전까지 접근하는 전체 흐름을 확인한 것은 아니다.
- 대형 경계 회귀: 전면/구형, 1·2·4·8·16·32척, 전장 중심과 모서리를 비교했다. 종전 개별 점 제한으로 8척 이상에서 슬롯 중복이 발생해 대형 전체 평행 이동으로 수정했다. 수정 후 시험한 모서리 32척의 최소 슬롯 간격은 전면 8, 구형 12.35 월드 단위였고 모든 슬롯은 유효 전장 안에 있었다. 이는 모든 회전·간격 조합의 충돌 방지를 뜻하지 않는다.
- 득점 회귀: 1대1 함선을 각각 구역 안과 바깥에 고정한 계산 시험에서 점수 주입 없이 7200 고정 틱(게임 120초), 준비 단계 재개 3회를 거쳐 120:0 아군 승리를 확인했다. 실제 무장 교전·AI 구매가 포함된 완전한 경기 검증은 아니다.
- 조우 처리 추가 계측: 경계 수정 후 Edge 헤드리스·SwiftShader, 1280×720, 16척, 6초 일회 실행. 조우 전 실제 6200ms/게임 4400ms, 처리 264회 37.2ms, 공간 질의 22회 및 반환 후보 누적 44개. 근거리 실제 6164.6ms/게임 4800ms, 처리 288회 10.8ms, 질의 1회 및 후보 3개, 공격 46건·생존 14척. 후보는 자기 함대를 포함한 질의 반환값이고 정밀 통과 수가 아니다. 시간에는 경계 산출과 인덱스 생성이 포함되며 계측 오버헤드와 SW 렌더 영향이 있다. 서로 다른 조우 상태·부하에서 얻은 단일 관찰이므로 비교 개선율이나 실제 GPU 성능을 뜻하지 않는다.
- 대표 통합 검증 범위는 마쳤으나 위 1대1 배치의 적 사격 부재 원인, 구매 함선이 자연 이동으로 교전에 진입하는 흐름, 모든 대형 회전과 경계 조합, 실제 GPU 성능·사용자 화면 시각 검수 및 자연 교전/AI 구매가 포함된 경기 전체는 남는다. 5.7의 모든 조합을 통과했다고 판정하지 않는다.

### 단계 6 — 진형 관통과 4분할 포위

**작업:** BREAKTHROUGH의 적 3D 배치 영역, 진입·출구, 쐐기 슬롯, 완료와 재발동 억제를 구현한다. ENCIRCLE의 네 분견대 배분·3D 목표·슬롯과 원래 소속을 보존하고 종료 후 재집결한다.

**검증:** 관통 경로 계획과 실제 진입·통과·출구를 구분하고 같은 조우의 즉시 재관통을 막는다(T04·T05). 포위는 4척 미만의 불가능 사유를 표시하고, 8척의 네 그룹과 손실 시 재편성을 확인한다(T06·T18). 도달한 그룹은 나머지를 기다리지 않고 유효 무장으로 사격할 수 있다.

### 단계 7 — 전체 UI·모델 연동과 관람

**작업:** 준비 화면에서 두 이동 명령과 다섯 교전 대응, 구매·증원, 편성과 목표 입력을 기능별 완료 상태에 맞춰 제공한다. 숫자 입력 없이 클릭·드래그와 선택 단계로 조작한다. 점수·구역 현황·체력·차단 사유와 관람 카메라를 제공한다. 사용 대상 모델의 축·포구·형상·접합 예외를 개별 검수해 공통 무장 계층에 연결한다.

**검증:** 2×5 조합별 정책 의미와 자동 대형, 입력·취소·카메라·미니맵·준비/전투 상태를 확인한다(T19~T24). 사용 모델마다 접합·회전 경로·포구 방향·차폐를 확인하고 실패/미검수 모델을 구분한다. 10종 전체의 안전을 일괄 보증하지 않는다. 실제 사용자 관찰 전 사용성 달성을 주장하지 않는다.

### 단계 8 — 통합 검증·성능 및 제출

**작업:** v2.2의 T·Z 사례와 통합본 및 공간 보강 명세의 G 사례를 각각 식별해 실행한다. 같은 시나리오의 함선·무장·발사체 수, 구역·장면, 기기/브라우저, 시간과 성능 지표를 기록한다. CG 직접 구현의 원리와 기여를 실제 구현과 과제 원문에 대조하고 실행·라이선스·보고서·영상 자료를 정리한다.

**검증:** 계산 및 상태 테스트, 브라우저 조작, 실제 모델 시각 검수, 성능 실측을 분리한다. 최적화 전후 조건과 정확도를 비교하고 측정하지 않은 확장성은 보장하지 않는다. 실패·미실행·남은 미결을 기록한다. 과제 원문은 [프로젝트 자료](../../../W11L1-Project3-3D%20작품%20만들기.pdf)를 확인한다.

### 단계별 의존 관계와 통과 방식

`0~1 기존 기반 확인 → 2 전장·안전한 기본 전투·득점 → 3 경제·증원·양측 AI → 4 순찰 → 5 조우·대치·거점 방어 → 6 관통·포위 → 7 UI·모델 확장 → 8 통합·성능 검증`을 기본 순서로 한다. UI와 진단, 성능 측정은 각 기능 개발 때 함께 시작한다. 4~6은 3의 경제 데이터와 독립적으로 설계할 수 있으나 게임 완료 판정에는 모든 범위를 합친다.

각 단계의 완료는 해당 범위의 실제 구현과 통과 증거에 한정한다. 미구현 기능은 선택 불가 또는 명확히 표시하며 계획과 테스트 목록을 실행 결과로 간주하지 않는다.

### 데이터 지향 구조와 최적화 적용

현재 환경은 Unity가 아닌 웹과 three.js다. DOTS는 **상태를 데이터 중심으로 분리하고 같은 종류의 작업을 일괄 처리하는 설계 원칙**으로 참고하며 Unity ECS/Burst 또는 자동 병렬화를 도입했다고 표현하지 않는다.

- 안정적인 함선·무장·탄 ID와 팀·생존·소유 관계를 기준으로 시뮬레이션과 렌더를 분리한다. 초기에는 기존 객체 배열과 단순 순회를 유지하고 틱별 스냅샷을 읽어 결과를 따로 확정해 갱신 순서 의존을 줄인다. TypedArray 등은 병목 측정 후 적용한다.
- 표적 탐색, 무장, 사선과 함선 피격을 각각 일괄 처리한다. 9개 득점 구역과 공간 검색 셀은 별개다. 3D 공간 인덱스의 안전 후보를 전수 검사와 비교한다.
- 정적 자기 형상과 인접 함선은 단순 경계체를 활용하고, 가동 부품의 처리 정확도와 갱신 주기는 성능·누락을 함께 검증한다. 공격 사건과 화면 효과를 분리하며 효과 풀링은 피해를 바꾸지 않는다.
- 고정 틱 `1/60`은 임시 설정이다. 부하 제한으로 누적 시간을 버리면 실제 실행한 틱만 게임 시간을 진행한다. FPS 검증은 같은 벽시계 시간이 아니라 **같은 완료 틱 수**의 결과를 비교하고 초과 부하에서의 시간 손실도 기록한다.

## 6. UI와 정책의 단계별 노출

- 첫 수직 슬라이스는 목적지 입력과 명령 유지 사격만 작동시킨다. 화면에서 아직 없는 정책을 선택해도 같은 동작을 하는 식으로 표시하지 않는다.
- 각 정책의 UI 이름과 실제 행동이 일치해야 한다. 거점 방어는 조우 전 상시 이동 명령이 아니다. 명령 유지 사격은 적을 추격하지 않는다.
- 준비 중 편집은 선택 함대에만 적용하고, 나머지 함대의 명령과 런타임은 유지한다. 입력 확정/취소 및 오류는 UI에 명확히 나타낸다.
- 순찰 경유점의 시작 인덱스는 경로 수정 시 첫 경유점부터 시작하는 안을 임시 제안한다. 바뀐 경로를 조우 중 적용하는 시점은 별도 결정한다.
- 정규 목표 입력은 XZ→YZ/XY 2단계 직교 화면이다. 첫 클릭은 X/Z만 임시로 정하고 두 번째 클릭은 Y만 정해 확정한다. 현재 입력 코드가 이 절차를 구현한 범위와 카메라 복원은 실제 조작 및 회귀 테스트로 확인한다.
- 회귀 ID는 문서마다 의미가 다르므로 **통합본 G01~G14**와 **보강 명세 G01~G18**로 문서명을 함께 표기한다. 예를 들어 통합본 G10은 대기 수평 복귀, 보강 명세 G10은 다른 높이 교전이다. 번호만으로 결과를 합치지 않는다.

## 8. 우선 확인할 위험과 대응

1. **좌표·리깅 불일치:** 모델 보정 전후로 선체 전방, 포구 +Z와 회전축을 대표 모델에서 확인하고 무장별 예외를 기록한다. 노드 존재만으로 포구 위치가 정확하다고 보지 않는다.
2. **시뮬레이션과 화면 불일치:** 고정 틱의 실제 자세에서 발사 변환을 계산하며 보간된 렌더 자세와 구분한다. 준비 중 발사체·재장전·조우 시계가 변하지 않는 회귀를 둔다.
3. **대형 붕괴와 회전 불연속:** 함대 기준점과 함선 속도를 별도로 제한하고, 진행 방향이 수직에 가까울 때의 상단 벡터 연속성과 좁은 슬롯 전환을 검증한다.
4. **정책 의미 혼동:** 명령 유지 사격과 거점 방어, 대치와 포위를 같은 상황에서 비교한다. 관통은 경로 계획과 실제 통과를 별도로 기록한다.
5. **형상 검사 비용과 정확도:** 열린 메시·접합 후보·1° 표본의 한계를 보존한다. 최적화나 단순화 전에 대표 상황의 오류와 비용을 측정하고, 실제 게임에서 적용한 범위를 공개한다.
6. **과제 기여의 근거 부족:** 대형 좌표 변환·3D 입력 등 게임에 필요한 계산을 직접 구현할 후보로 검토하되, 라이브러리 호출만으로 CG 직접 구현 충족을 주장하지 않는다. 어떤 기법이 강의 범위에 해당하는지는 원문과 구현 후 검증한다.
7. **외부 에셋 의존:** 로컬 실행과 제출물에서 에셋 경로·라이선스·배포 가능 범위를 확인한다. 저장소 밖 파일이 누락된 경우 사용자에게 원인을 표시한다.

## 9. 구현 착수 시 변경 제안

- 기존 `web/` 프로토타입의 입력·카메라·편성·이동을 회귀 확인한 뒤 단계 2의 상태·전장·무장·안전·득점부터 연결한다. 구체적인 파일 분할은 실제 구현 범위와 기존 의존성 확인 후 결정한다.
- `rigging-test/`는 독립 도구로 유지한다. 변경 중인 공통 모듈을 게임이 직접 참조할지, 검증 후 공유 위치로 옮길지는 기존 작업의 소유와 변경 위험을 확인한 뒤 정한다. 무단 복사·이동이나 현재 미커밋 변경 덮어쓰기는 하지 않는다.
- README에는 실제 구현과 실행 방법이 바뀐 시점에 상태를 갱신한다. 이 설계 문서의 갱신은 v2.1 기능의 구현·검증 완료를 의미하지 않는다.
