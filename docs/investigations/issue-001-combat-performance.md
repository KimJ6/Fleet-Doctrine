## 문제와 범위

적이 사거리 안에 들어와 포탑 조준이 시작되면 화면이 심하게 느려지고 고정 틱 진행이 지연된다. 현재 게임의 전투 계산은 `web/main.js`·`web/simulation.js`의 JavaScript에서 실행한다. `python/`은 별도 스타터 데모이고 로컬 Python HTTP 서버는 파일 제공 역할이다. 따라서 Python 교체만으로 이 교전 병목이 해소되는 구조는 아니다.

현재 리깅 안전 검사기는 실제 메시의 BVH, 부품 경계와 회전 중간 자세를 검사한다. 게임 조준은 각 함선의 여러 무장 후보를 만든 뒤 동시 이동 안전 검사를 요청한다. 적 조우로 이 경로가 빈번해지는 점이 관찰된 병목 후보이며, 세부 비용의 분해 측정은 아직 필요하다. 검사기가 가진 열린 메시·표본 사이 간섭·접합 후보의 기존 한계는 성능과 별도로 남는다.

## 작업 내역

1. 2단계 시제품에서 포탑·포구 검사와 전투 시뮬레이션을 연결했다. 실제 리깅 모델 두 척을 근접 배치한 브라우저 시험에서 포탑 회전 후 발사 2회, 적 체력 100→60을 관찰했다. 이는 모든 포구·배치의 안전이나 다수 함선 성능 검증은 아니다.
2. 조우 후 무장 안전 검사가 한 시점에 몰리는 것을 완화하기 위해 함선별 검사 시점을 나누고, 변경 없는 요청 및 동일 모델·자세의 검사 결과를 제한적으로 재사용했다.
3. 한 차례 검사에서 최대 1°만 이동하도록 임시 제한했다. 현재 기본 편성 16척에서는 각 함선의 검사 주기가 64 고정 틱이므로, `1/60초` 기준 약 1.07 시뮬레이션 초당 최대 1°, 즉 약 **0.94°/시뮬레이션 초**다. 기존 35°/초 목표보다 현저히 느리며 최종 성능 해결이 아니다. 실제 초당 속도는 틱이 밀리면 더 낮아진다.
4. 이슈에 단순 충돌 형상, 후보 축소, 데이터 공유, Worker 및 C++/WebAssembly 비교 방안을 기록했다. 이를 도입하거나 유효성을 검증한 상태는 아니다.

**해석:** 이번 초기 조우 한 사례에서는 `moveBatch` 누적 3.95초 중 `pairCollision` 누적이 약 3.93초여서 부품 쌍의 정밀 검사 경로가 우선 조사 대상이다. 이는 계측 오버헤드가 있는 관찰이며 `pairCollision` 내부의 BVH·삼각형·내부 포함 판정의 개별 비용이나 원인을 아직 분리하지 않았다. `update`의 계측 시간은 이 사례에서 상대적으로 작아 보이지만, 이를 일반적인 모든 장면의 결론으로 확대하지 않는다. 원거리에서도 SwiftShader의 렌더 콜백이 낮아 실제 사용자 GPU 환경의 FPS로 해석할 수 없다. 측정 횟수 1회, 짧은 구간 및 캐시 초기 상태의 한계가 있다.

**다음 기준:** 기존 전수 쌍 비교와 보수적 사전 후보 목록을 같은 고정 틱·같은 입력 자세로 비교하고, 누락·과차단 및 정밀 검사 호출 수를 기록한다. 실제 사용자 브라우저/GPU에서도 반복 측정하고, 조준 속도를 제한하기 전과 복구한 상태를 별도로 비교한다.

## 2026-11-23 함선 내부 검사 개선 및 재측정

### 변경

- 게임의 `GameRigSafety`는 생성 시 같은 강체 쌍을 제외하고 고정 구조/가동 부품 쌍을 미리 분류한다. 같은 자세에서 현재 활성 부품과 관계없는 쌍 및 AABB가 겹치지 않는 쌍을 걸러 낸 뒤 기존 `pairCollision`을 호출한다.
- 고정 구조와 가동 부품 검사를 위한 재귀 호출을 없애 같은 중간 자세에서 `update()`를 한 번 수행한다. 검사 순서는 고정 구조 후 가동 부품 순서를 유지한다.
- 기존 `rigging-test/rig-safety.js`와 사전 분석 해시는 변경하지 않았다. 게임 쪽 전용 확장이므로 리깅 테스트 도구의 검증 결과를 게임 구현 자체의 자동 통과로 간주하지 않는다.
- 이 변경은 **회전 가능 영역을 이용한 사전 공간 후보 생성이 아니다.** 모든 유효 쌍의 분류와 현 자세의 AABB 필터를 이용하며, 겹치는 후보의 메시 정밀 검사는 여전히 남는다. 포탑 회전량에 적용된 기존 임시 제한도 그대로다.

### 검증

- Node 실행 중 외부 FBX를 로드해 기존 검사기와 게임 개선 검사기를 비교했다. 경순양함 01의 검사 옵션 4종과 동시 회전 경로 4개에서 차단 여부·사유 유형·안전 이동 비율·각 무장 최종 각도가 일치했다. 단일 모델과 선택한 4개 경로에 대한 비교다.
- 실제 브라우저 초기 조우의 동일 자세 20개를 기존 검사 후 개선 검사 순서로 비교했다. 결과 유형과 첫 부품 이름의 불일치가 0건이었다. **20개 모두 차단 없는 자세**였으므로 충돌·정상 접합 예외의 포괄 검증이 아니다. 기존 방식 누적 1,662.6ms, 개선 방식 1,510.5ms였으나 각 경우 시간이 크게 흔들리고 순서가 고정된 1회 실험이므로 일반적인 개선율로 사용하지 않는다.
- 기존 `node rigging-test/rig-safety.test.mjs`의 10개 그룹은 통과했다. 이 테스트는 원본 검사기를 대상으로 한다.

- 좌우·후방 포신 박스는 일부 자세·포구에서 차단 여부가 일치하고 Node 중앙값이 다소 낮았으나, 고정 자세 120개 모두 기준 검사가 통과했고 가려진 형상과 이동 경로 검수가 남아 있다. 따라서 게임의 기본 판정으로 교체하거나 16척 성능 향상을 확정하지 않는다.
- 정확도 절충은 검수 가능한 범위에서 설계할 수 있다. 우선 느린 부품·포신을 검증된 단순 형상으로 교체하고, 포탑 간 아주 작은 관통이나 간섭의 허용 범위를 별도로 정한다. **자기 선체·아군 발사 차단 및 포구별 판정은 별도 정책**으로 남기며, 작은 시각적 오차 허용을 사선 검사 제거로 확대하지 않는다.
- 다음 검수는 포탑 간 실제 차단 자세, 시작·종료는 안전하나 중간에 충돌하는 경로, 정면·후면·측면 및 포구 폭을 포함해야 한다. 원본 검사와 불일치한 경우 시각 확인으로 과차단과 누락을 구분한다. 적합한 근사와 검사 주기를 선택한 뒤 정상 목표 회전 속도의 16척 브라우저 시나리오로 성능과 결과를 측정한다.

## 2026-11-23 포탑 회전 근사 판정 시험 적용

### 변경과 의도적 정확도 절충

사용자의 정확도 절충 검토 요청에 따라 게임 프로토타입의 포탑 이동에 AABB 기반 근사 방식을 적용했다. 12 고정 틱마다 함선의 무장 후보 자세를 함께 적용하며, `35°/초 × 0.2초 = 최대 7°` 후보 증분을 사용한다. 이전의 16척에서 1.07초당 최대 1° 제한은 제거했다. 각 무장의 기존 축·범위 및 `applyPose`의 조건부 제한은 유지한다. 투사체 이동은 고정 틱마다 진행한다.

각 함선의 활성 무장과 관계있는 고정·가동 부품 쌍에 대해 현재/후보 AABB 겹침 부피를 작은 쪽 상자 부피로 나눈 값을 계산한다. 후보에서 겹침 비율이 0.65를 넘고 현재 대비 0.20보다 많이 증가하면 해당 함선의 후보 무장 전체를 이전 자세로 복구한다. 기존 접촉에 의한 과차단을 줄이기 위한 **임시 경험적 기준**이며 튜닝·형상별 검증 전이다. 검사 오류 시 자세를 복구하고 해당 함선의 사격 처리를 중단한다.

이 방식은 **도착 자세만 검사**한다. 포탑 회전 경로, 얇은/부피가 거의 없는 부품, 이미 깊게 겹친 상태, AABB의 빈 공간 및 정상 접합의 정확한 구분을 보장하지 않는다. 따라서 7° 중간 관통이나 비교적 큰 간섭도 놓칠 수 있다. 화면에서 일부 관통 가능성을 안내한다. 별도 리깅 테스트 도구의 기존 정밀 검사기는 변경하지 않았다.

포구별 자기 구조의 실제 메시 검사, 아군 사선 검사, 발사 후 자기 선체의 경로 검사는 기존 코드를 유지한다. 이는 아군의 모든 미래 이동이나 회전 중 형상을 완전 보장한다는 뜻은 아니다. 이 근사 방식은 게임에 시험 적용한 것이며, 아직 최종 채택·안전 승인이 아니다.
