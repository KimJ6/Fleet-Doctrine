# 함선 리깅 및 회전 제어 절차

[프로젝트 안내로 돌아가기](../../README.md)

Blender 리깅은 **형상과 움직임의 구조**를 정의하고, 실행 스크립트는 **회전 방향과 허용 범위**를 제어한다. 모델과 스크립트가 같은 규칙을 각각 중복 적용하지 않는다. 아래 범위는 현재 프로젝트의 정책이며, 적용·검증 상태는 별도로 표시한다.

## 탐색과 판정 정책

### 기본 원칙

- 메시 조각의 정점 수, 원통형 모양, 길이, 좌표 또는 대칭성만으로 포신·포탑·엔진을 확정하지 않는다. 이런 값은 **후보 탐색**에만 사용한다. 모델별 형상과 연결 관계를 검토하지 않은 일괄 분류를 완성된 리깅으로 취급하지 않는다.
- 각 함선의 전방·후방과 중립 자세를 먼저 확인하고, 전체와 상·하·좌·우·후면 및 필요한 부위를 확대해 살핀다. 원본 외형과 별도 메시 조각을 비교하며, 가려진 부분은 뷰를 회전하거나 와이어프레임·분리 미리보기로 확인한다.
- 사용자가 확인한 부품의 역할·개수·회전 방식은 우선 적용한다. 추정이 사용자 확인 내용과 충돌하면 추정을 고친다.

### 포신과 포탑

1. 포구처럼 보이는 후보마다 포신의 양 끝, 축, 주변 외장과 연결부를 살핀다. 실제 포신과 포구가 어디인지 판단하고, 빔·장식·센서·엔진 원통과 구분한다.
2. **모든 포신 후보에 대해** 뿌리에서 주변을 따라가 포탑 외장·회전받침·선체 중 무엇에 결합하는지 확인한다. 메시 연결 성분뿐 아니라 접촉, 삽입, 외형상의 연속성도 살핀다. 같은 메시여도 분리 부품일 수 있고, 떨어진 성분이어도 하나의 포탑일 수 있다. 단순 근접성이나 토폴로지만으로 결합을 확정하지 않는다.
3. 포신이 포탑에 결합하면 외장과 함께 도는 판넬·큐브·기타 부속을 식별하고 포탑 피벗 아래로 분리한다. 포신과 함께 움직여야 하는 큐브 등은 포신의 일부로 취급하고 그 끝을 기준으로 포신 피벗을 둔다. 연장포의 각 포신과 각 포구를 빠짐없이 연결한다.
4. 선체에 고정된 무장이라면 고정 포로 분류해 포구 기준점만 선체 하위에 둔다. 포탑 외장은 고정하고 포신만 포탑 중심을 기준으로 선회하는 등 사용자가 지정한 특수 구조는 별도로 적용한다.
5. 분리 전후 외형을 비교하고, 포탑을 회전할 때 본체·부속·포신이 함께 움직이는지, 포신만 회전할 때 지정된 구성품과 포구가 함께 움직이는지 살핀다. 정상 접합부를 분리 메시·표면 교차만으로 제거하거나 임의로 벌리지 않는다.

### 엔진과 결과 확인

1. 선체 후방을 확대해 노즐의 개수, 위치, 출구 면과 분사 방향을 확인한다. 좌우·상하 대칭은 누락 점검에 활용하되, 원뿔·원통 등 형상만으로 엔진을 판정하지 않는다. 노즐과 장식·무장·선체의 구별이 불확실하면 확정하지 않는다.
2. 확인된 노즐마다 출구에 기준점을 두고 방향을 검사한다. 사용자가 지정한 개수와 실제 배치가 다른 경우에는 차이를 확인하며, 추정으로 개수를 맞추지 않는다.
3. 각 모델에서 포탑·포신·고정 포·포구·엔진의 식별 결과와 검증 상태를 기록한다. 확정할 근거가 부족한 부위는 후보로 명시하고, 필요하면 사용자에게 해당 부위를 보여 확인받는다. 포탑 본체 분리, 부속 동반 회전, 엔진 위치 또는 FBX 재가져오기 검증이 빠졌다면 완료로 보고하지 않는다.

**구축함 02의 확인 사항:** 사용자가 엔진은 후방 원통 6개라고 확인했다. 기존 초안의 엔진 후보는 잘못되어 사용자 검수에 따라 수정했다. 수정된 부품과 포신별 결합 관계의 전 범위 검증 여부는 별도로 확인한다.

## 모델별 작업 순서와 통과 기준

한 번에 한 함선을 대상으로 아래 순서를 수행한다. 각 단계에서 확인한 결과를 바탕으로 다음 단계에 진행하며, 후보 분류나 파일 생성만으로 리깅 완료를 선언하지 않는다.

### 1. 원본 조사와 부품 목록

1. 기존 사용자 장면과 구분되는 작업 영역에서 원본을 확인한다. 함선의 전후·좌우·중립 자세를 파악한 다음 상·하·좌·우·전·후면을 살핀다. 가려진 부위는 확대, 와이어프레임 또는 분리 미리보기로 확인한다.
2. 포신·포탑·고정포·엔진 후보를 위치별로 빠짐없이 나열하고 각 후보를 **확인 / 형상상 추정 / 미확인**으로 구분한다. 정점 수·원통형·좌표·대칭은 후보를 찾는 단서이며 역할 판정의 근거로 단독 사용하지 않는다.
3. 사용자가 특정한 역할·개수·회전 방식은 우선 적용한다. 확인된 내용과 자동 추정이 충돌하면 추정을 바로잡는다.

**통과 기준:** 상부뿐 아니라 선체 하부·측면·함수·함미의 후보를 살폈고, 확정할 수 없는 항목이 분명히 표시돼 있어야 한다.

### 2. 각 포신의 결합 관계 추적

1. 포구 후보에서 포신을 따라 반대편 끝과 결합부를 확인한다. 그 포신이 포탑 외장, 회전받침 또는 선체 중 어디에 결합되는지 추적하고 장식·센서·엔진과 구별한다.
2. 포탑과 함께 움직이는 외장·판넬·11자 판넬·작은 부속을 **전체** 식별한다. 포신에 붙어 함께 움직이는 큐브 등은 포신 구성품으로 분류한다. 메시가 연결됐다는 것만으로 하나의 가동 부품이라거나 분리됐다는 것만으로 별개의 부품이라고 판단하지 않는다.
3. 각 무장을 회전 포탑, 고정 외장에 가동 포신, 완전 고정포 중 실제 구조와 사용자 지시에 맞게 분류한다. 연장포는 포신마다 포구와 움직임을 확인한다.

**통과 기준:** 각 포신의 결합 대상, 포탑과 함께 움직일 부품, 포신과 함께 움직일 부품을 설명할 수 있어야 한다. 근거가 부족하면 임의로 완성 처리하지 않고 확인 대상으로 남긴다.

### 3. 피벗과 계층 구성

- 포탑이 실린더로 선체에 연결되면 실린더의 **중심선**을 회전축으로 둔다. 포탑의 경계 상자 중심이나 최저점만으로 대신하지 않는다. 축 방향은 연결 형상과 실제 요구 동작을 따른다.
- 포신 피벗은 원통만이 아니라 함께 회전하는 큐브 등 **전체 포신 구성품의 포구 반대편 끝단**에 둔다. 포구는 실제 출구 면 중심에 두고 로컬 +Z를 발사 방향으로 맞춘다.
- 포탑 본체·부속과 포신 구성품을 각각 적절한 피벗에 연결한다. 고정포는 회전 피벗 없이 선체에 연결한다. Blender에서 각도 제한을 걸지 않는다.
- 포신이 접합부에 삽입되는 정상 형상은 허용한다. 표면 교차 수치만을 근거로 포신을 잘라 포탑에서 떨어뜨리지 않는다. 포탑이 회전할 때 열린 접합면이 드러나면 형상·재질·UV를 보존하며 면 보완을 검토한다.

### 4. 엔진 출구 판정

- 선체 후방을 확대해 각 후보의 실제 노즐 출구, 중심, 분사 방향을 확인한다. 대칭성은 누락 점검에 쓰되 원통·원뿔이라는 형상만으로 엔진을 확정하지 않는다.
- 확인된 출구마다 기준점을 출구 면 중심에 놓고 로컬 +Z를 분사 방향으로 맞춘다. 이펙트 크기는 외장 전체가 아닌 **출구 둘레의 반지름**을 기준으로 하며, 대상 툴의 단위·스케일 변환을 반영한다.
- 확인된 개수와 배치가 사용자 지시와 다르면 원인을 다시 조사한다. 불확실한 노즐은 확정했다고 보고하지 않는다.

### 5. 시각·동작·내보내기 검증

1. 중립 자세의 원본과 결과를 비교해 실루엣과 부품 위치를 확인한다. 좌·우 각각 포탑만 회전시켜 본체·모든 판넬·포신·포구가 함께 움직이고 선체에 남은 부속이 없는지 본다.
2. 포신만 회전시켜 원통·큐브·포구가 함께 움직이고 포탑 외장은 별도로 유지되는지 확인한다. 고정포는 독립 회전하지 않아야 한다.
3. 허용 범위의 중립·중간·경계 자세와 포탑·포신 회전 조합을 확인한다. 접합부 삽입과 외장·선체 밖으로 뚫고 나오는 관통을 구분하고, 포탑 회전 시 빈 접합면이 보이는지 살핀다.
4. 내보낸 FBX를 다시 가져와 이름·계층·피벗·포구·엔진 위치와 방향, 재질을 확인한다. 웹 또는 대상 툴에서는 실제 회전축·부호, 동기화, 엔진 이펙트 크기를 별도 검증한다.
5. 각 모델의 확인된 포탑·포신·고정포·포구·엔진 수, 검증한 자세, 미확인 부위와 검사 경고를 보고한다. 표본 검사는 전 구간 무충돌 보증이 아니다. 포탑 본체·부속이나 엔진 출구 판정 및 재가져오기 검증이 빠진 경우 **미완료 또는 검수 필요**로 보고한다.

### 확인된 모델별 사례

- 구축함 01 Pod는 고정포다. 좌우 양끝의 원뿔 4개는 엔진이 아니다. Hull 포신에는 뒤쪽 큐브가 포함되며, 포탑 접합면이 노출되지 않도록 보완한 사례다. Broadside 좌우 3문씩의 좌우 회전은 웹 스크립트에서 각각 동기화한다.
- 구축함 02는 전방 고정포 4문과 하단 포탑이 있다. Aft의 세워진 연결 실린더는 포탑 상하 회전축이며, 포신은 좌우로 회전한다. 11자 판넬은 포탑과, 포신에 붙은 큐브는 포신과 함께 움직인다. 엔진은 후방 원통 6개이며 양끝 2개는 위쪽 원통이다. 중앙 4개는 각 출구 크기와 중심을 확인한다.
- 사례에서 확인된 구조와 개수를 다른 모델에 무작정 적용하지 않는다. 사용자 확인과 각 모델의 실제 형상을 함께 기준으로 한다.

## Blender 리깅 절차: 구조와 기준점

### 6.5단계 포 식별 이름 기준 — 2026-11-24

상태: **FBX 10척 명칭 변경 및 계층 재가져오기·대표 게임 검증 완료. 각 모델의 모든 회전 자세 시각 검증은 남음.** 관련 설계: [6.5단계](../design/implementation-plan.md#phase-6-5-balance-data). 이 표의 W 번호는 확정한 식별자로 취급하며 추후 재정렬·유형 변경 시 재할당하지 않는다. 함선 ID는 구축함 `D01`~`D05`, 경순양함 `LC01`~`LC05`다.

| 부품 | 새 이름 | 예시 |
|---|---|---|
| 회전 포탑 피벗 | `PIVOT_Turret_<함선ID>_<포ID>` | `PIVOT_Turret_LC01_W03` |
| 포신 피벗 | `PIVOT_Barrel_<함선ID>_<포ID>_<포신ID>` | `PIVOT_Barrel_LC01_W03_B01` |
| 포구 | `FX_Muzzle_<함선ID>_<포ID>_<포신ID>` | `FX_Muzzle_LC01_W03_B01` |
| 고정 포구 | 동일한 포구 이름; 포탑·포신 피벗을 새로 만들지 않음 | `FX_Muzzle_D02_W01_B01` |

`W01`은 함선 내 재사용 시간을 공유하는 무장 하나, `B01`은 그 무장 안의 포신/포구 하나를 뜻한다. 같은 포탑의 연장포는 하나의 W와 여러 B를 사용한다. 고정 포구는 현 런타임 동작과 구축함 02의 확인된 전방 고정포 4문을 보존해 일단 각각 독립 W와 B01을 부여한다. 향후 고정 포구의 공동 발사가 명시적으로 결정되면 재사용 그룹을 데이터에서 별도 지정하며 기존 W를 무단 합치지 않는다. 이름에는 피해·유형·회전축을 넣지 않는다. 포 유형은 사용자가 CSV에서 각 W에 지정하고, 모델별 회전축·각도·부호는 별도 리깅 설정에서 기존 설정을 이관한다.

최초 번호는 Blender 5.3에서 FBX를 기본 설정으로 불러온 중립 자세의 Blender 월드 좌표 기준으로 전방→후방(X 오름차순), 같은 X에서 좌측→우측(Y 내림차순), 같은 위치에서 위→아래(Z 내림차순), 마지막으로 기존 이름 순으로 부여했다. 좌표는 0.001 단위로 반올림해 비교했다. 이 순서는 **아래 표를 만드는 최초 기준**이며, FBX 재수출 후 좌표로 W를 재계산하지 않는다. B 번호는 같은 포탑의 포신에 대해 기본 가져오기 상태의 Blender 월드 좌표 Y 내림차순, Z 내림차순, X 오름차순, 기존 이름 순으로 부여하고 그 포신의 포구에 같은 번호를 부여한다. 현재 조사한 회전 포탑 하위 포구는 모두 포신 피벗을 경유하며, 포신당 복수 포구가 발견되면 한 B에 여러 포구를 억지 배정하지 않고 별도 확장 규칙을 정한다.

**적용 기록:** FBX의 노드 이름 문자열만 교체했으며 재내보내기로 메시·재질·변환을 재구성하지 않았다. 변경 전 무변경 읽기/쓰기 결과가 10개 파일 모두 바이트 단위로 동일함을 확인했다. 변경 후 Blender 5.3 재가져오기에서 10개 파일의 전체 객체 이름 매핑·부모·월드 변환·메시 정점 수를 변경 전과 대조해 일치했다. 포구 방향은 포구와 조상의 월드 변환이 일치하는 것으로 확인했으며 별도 전 각도 시각 검증은 아니다. D01 Hull 부호·조건부 pitch 등 기존 키 의존 회전 설정은 새 ID→기존 키 매핑으로 연결했고, 포구 데이터 계산도 D01_W01의 좌우 부호를 반영했다. 고정 포구는 새 W ID로 탐색한다. `rig-analysis.json`을 새 에셋·제어 코드로 재분석했다.

기존 안전 시험 10개 그룹 통과. 실제 게임의 LC01 16척, Z=±18, Edge 헤드리스·SwiftShader 시험은 게임 5.9초, 공격 30건, 안전 실패·페이지 오류 0건이었다. D01/LC01 외의 중립 상태 충돌은 기존 분석과 같이 엄격 차단 대상이며, 이 결과를 모든 회전 범위의 안전이나 실제 GPU 화면 검수 통과로 해석하지 않는다. FBX 원본 자산은 상위 `ship assets/rigged`에 있어 프로젝트 저장소의 `git status`에 표시되지 않으므로 별도 버전 관리 상태도 확인해야 한다.

1. 원본 모델링은 보존하고 지정된 리깅 작업 파일에서 수정한다. 별도 결과물을 만들지 않고 작업 파일을 덮어쓰라는 지시가 있으면 그에 따른다.
2. 원본의 중립 자세를 기준 자세(0°)로 정한다. 함선의 기준 방향, 단위와 좌표축을 확인하고, 형상과 부품의 상대 위치를 유지한다.
3. 포탑 외장 및 함께 도는 부속품을 선체에서 분리하고, 선체에 연결되는 실제 회전 중심에 포탑 피벗을 둔다. 각 가동 포신은 별도로 분리하고 **포구 반대편 끝면 중심**에 포신 피벗을 둔다. 포신 길이 중간에 회전축을 두지 않는다.
4. 기본 계층은 `함선 → 포탑 피벗 → 포신 피벗 → 포구 기준점`이다. 포탑 외장과 부속품은 포탑 피벗에, 포신 형상은 해당 포신 피벗에 연결한다. 연장포는 각 포신·포구를 각각 연결한다. 고정 포는 함선 아래에 포구 기준점을 둘 수 있다.
5. 웹 탐색 이름은 `PIVOT_Turret_*`, `PIVOT_Barrel_*`, `FX_Muzzle_*`, `FX_Engine_*`를 사용한다. 포구·엔진 기준점의 로컬 **+Z**를 각각 발사·분사 방향으로 둔다. 이름과 부모 관계를 모델 안에서 중복 없이 정한다.
6. 포탑과 포신은 Blender에서 독립적으로 자유 회전하도록 구성한다. Blender의 회전 제한 조건으로 게임 허용 각도를 고정하지 않는다. 포신이 포탑 접합부 안에 삽입된 상태는 허용한다. 표면이 교차한다는 이유만으로 접합부를 벌리지 않는다.
7. 중립 자세와 피벗·부모 관계를 확인하고 FBX로 내보낸 뒤, 다시 가져와 위치, 축, 계층, 기준점 방향과 재질을 확인한다. 포탑·포신 및 포구가 함께 움직이는지 검사한다. Blender에서 설정한 제약조건이 다른 툴에서 동작한다고 가정하지 않는다.

## 회전·발사 제한 정책

### 목적과 책임

제한의 목적은 다음 두 가지다. 여기서 **함선 구조는 선체·함교뿐 아니라 자기 포탑, 다른 포탑과 모든 포신 및 동반 부속을 포함**한다.

1. 포탑·포신이 움직이는 과정과 도착 자세에서 정상 결합부 밖의 충돌·관통을 방지한다.
2. 실제 포구에서 발생하는 공격 이펙트나 투사체가 자기 함선 구조를 통과하거나 자기 함선을 피격하는 발사를 방지한다.

회전 가능 여부와 발사 가능 여부는 별도로 판정한다. 형상상 안전한 조준은 허용하되 발사 경로가 막힌 포구의 발사를 차단한다. 고정포도 발사 경로 검사를 수행한다. 포탑·포신 각도와 다른 무장의 자세가 바뀌면 안전 여부도 달라진다.

Blender는 중립 형상, 피벗, 부품 계층과 기준점을 제공한다. 실행 스크립트는 기본 범위, 현재 자세에서의 이동 허용 여부와 발사 허용 여부를 결정한다. 사전 계산과 검사 도구는 그 결정을 지원한다. Blender 제약조건을 게임 제한의 실행 수단으로 삼지 않는다.

### 기본 범위·사전 계산·런타임 검사의 조합

| 수단 | 담당하는 범위 | 한계와 적용 원칙 |
|---|---|---|
| 명시적 기본 규칙 | 가동 포신의 선체 바깥쪽 0~45°, 기계적 한계, 사용자 지정 예외, 동기화 | 범위 안의 모든 자세가 안전하다는 뜻이 아니다. 고정포는 독립 회전하지 않는다. |
| 고정 형상 사전 계산 | 선체·함교 등 함선 좌표계에서 움직이지 않는 구조에 대한 포탑·포신 자세 조합 | 표본 결과를 연속 구간 전체의 안전 증명으로 취급하지 않는다. 경계와 이동 경로를 보완 검사한다. |
| 런타임 이동 검사 | 현재 자세에서 다음 자세까지의 이동, 다른 포탑·포신과 동시 이동 | 최종 자세만 검사하지 않는다. 실제 반영할 이동 구간을 검사한다. |
| 런타임 발사 검사 | 현재 포구 위치·방향과 공격 크기·경로에 따른 포구별 발사 가능 여부 | 이전 조준 검사나 사전 계산 결과만으로 발사를 허용하지 않는다. |

적용 우선순위는 **사용자 지정 구조·예외 → 공통 기본 범위 → 현재 형상과 경로에 따른 추가 제한**이다. 예외는 정상 접합부와 같은 명시된 허용 관계 외의 충돌을 무시하는 권한이 아니다. 충돌 검사는 기본 범위 밖으로 각도를 확대하지 않는다.

포탑 360° 회전은 구조상 허용되는 무장에만 적용한다. -180°와 180°의 표현 경계에서 회전이 튀거나 금지 구간을 건너뛰지 않도록 실제 이동 방향과 경로를 유지한다. 좌우현 부호, 수직 장착, 구체형 포탑, 고정 외장에 가동 포신 등은 실제 피벗과 계층을 기준으로 처리한다. 이름은 부품 식별에 사용하며 이름만으로 축이나 안전 범위를 확정하지 않는다.

### 정상 결합부와 잘못된 관통의 구별

- 포구 반대편 포신과 큐브·실린더가 자기 포탑 안에 삽입되거나 접해 있는 것은 정상 결합일 수 있다. 표면 교차나 접촉만으로 이동을 차단하지 않는다.
- 무장별로 **허용 부품 쌍, 접합 영역, 허용하는 접촉·삽입 관계**를 정한다. 영역은 실제 접합부를 기준으로 하며 회전 중의 정상 움직임도 포함한다.
- 허용은 지정 부품 쌍이 지정 영역에서 정상 결합하는 경우에만 적용한다. 포신과 자기 포탑 전체를 충돌 검사에서 제외하거나, 그 영역 안의 다른 포탑·선체까지 제외하지 않는다.
- 중립 자세의 모든 겹침을 자동으로 허용하지 않는다. 중립 오류가 예외로 굳어질 수 있다. 회전 후 포신이 접합부 반대쪽 외장을 뚫고 나오는 경우도 차단해야 한다.
- 사용자가 정상이라고 직접 확인한 구축함 01·경순양함 01의 **모든 포탑·포신이 0°인 자세**는 유효한 형상 기준이다. 판정기가 이 자세를 형상 충돌로 차단하면 기준·접합 판정을 수정한다. 이 확인은 다른 함선이나 0° 밖의 움직임까지 자동 승인하지 않는다.
- 구현 초안은 확인된 두 FBX의 중립 교차에서 접합 후보 부품 쌍과 피벗 주변의 측정 영역을 기록하고, 회전 중 그 쌍의 제한된 영역에서 이어지는 접촉을 허용한다. 이는 근사 규칙으로, 다른 각도의 무관통을 사용자 확인으로 간주하지 않는다. 영역 밖·다른 부품 쌍의 접촉과 발사 경로는 별도 검사한다. FBX가 변경되면 다시 확인한다.
- 정상인 0° 자세에서도 포구 앞 발사 경로가 자기 함선 구조에 막힌다면 자세 자체를 금지하지 않고 해당 포구의 사격을 제한한다. 이동 중 형상 간섭과 발사 경로 차단은 별도로 판정한다.
- 결합 영역을 과도하게 키워 관통을 숨기거나 충돌을 없애려고 포신을 포탑에서 벌리지 않는다. 판단이 불확실한 영역은 근거와 검수 대상으로 남긴다.
- 형상 결합 예외를 발사 경로 전체의 예외로 재사용하지 않는다. 포구가 자기 포탑 외장을 향하거나 포구가 구조물 안에 들어간 경우도 검사한다. 자기 무장 전체 무시나 임의의 검사 시작점 전진으로 막힌 발사를 통과시키지 않는다.

### 이동 판정과 동시 회전

1. 중립 자세와 원래 로컬 회전을 보존한 상태에서 조준 입력을 기본 범위로 제한한다. FBX 로더의 축·단위 변환을 반영하며 초기 회전을 덮어써 중립 형상을 바꾸지 않는다.
2. 현재 자세에서 다음 반영 자세까지 포탑과 포신의 **조합 경로**를 검사한다. 시작·도착만 안전한 경우를 허용 근거로 삼지 않는다.
3. 고정 구조의 사전 계산 결과로 후보를 줄이고, 움직이는 다른 포탑·포신과 실제 이동 구간을 검사한다. 접합부 예외는 해당 접촉에만 적용한다.
4. 연속 충돌 검사 또는 이동량에 맞춘 세분 검사와 경계 정밀 검사를 사용한다. 큰 시간 간격·빠른 회전·얇은 부품을 건너뛰지 않도록 분할 기준과 오차 여유를 정의한다. 검사 정밀도가 부족한 구간을 안전으로 확정하지 않는다.
5. 차단되면 현재 자세에서 연속적으로 도달 가능한 안전 위치까지만 이동한다. 안전 구간이 여러 개라면 차단 구간 너머의 다른 안전 구간으로 건너뛰지 않는다.
6. 여러 무장의 다음 자세를 같은 갱신 단계에서 예측하고 상호 이동을 검사한다. 각각을 오래된 상대 자세와 비교한 뒤 동시에 반영하는 방식으로 충돌을 놓치지 않는다. 충돌 시 이동 우선순위 또는 정지 규칙을 결정적으로 적용한다.
7. 동기화된 포탑도 모든 구성원의 경로를 검사한다. 그룹 동기화를 유지해야 하면 한 구성원의 차단을 그룹의 이동 한계에 반영한다. 검사를 위해 개별 포탑만 몰래 분리 움직이지 않는다.

### 발사 경로 판정

1. 이동 판정과 자세 반영 후 월드 변환을 갱신하고, **발사 순간의 실제 포구**에서 로컬 +Z를 변환해 발사 방향을 구한다.
2. 공격 종류는 스크립트에서 포구에 연결한다. 광선, 굵은 빔, 크기가 있는 투사체를 구별하고 이펙트·충돌체의 폭, 생성 위치와 검사 거리·수명을 일치시킨다. 굵기가 있는 공격을 중심선 한 줄로만 검사하지 않는다.
3. 자기 포탑, 다른 포탑·포신, 선체·함교를 포함한 구조와 발사 경로를 검사한다. 연장포는 포구별 판정을 기본으로 하며 동시 발사 요구가 있을 때 그룹 규칙을 추가한다.
4. 막힌 포구는 공격 이펙트·투사체 생성 전에 차단한다. 시각 이펙트만 선체를 통과하고 피해 처리만 무시하는 방식으로 목적을 충족했다고 보고하지 않는다.
5. 곡선 탄도는 직선 검사 하나로 대신하지 않고 해당 궤적과 크기로 검사한다. 지속 빔은 유지 중 구조물의 움직임을 재검사한다. 발사 후 움직이는 자기 함선·다른 포탑과 만날 수 있는 투사체도 수명 동안 충돌·시각 처리를 유지한다. 발사 직전 검사를 비행 전 구간의 안전 보증으로 취급하지 않는다.

## Codex의 제한 구현 작업 절차

### 1. 현재 상태와 작업 범위 확인

- 현재 브랜치·변경 파일과 기존 정책·스크립트를 읽고 사용자 작업을 보존한다. 현재 FBX를 입력으로 사용하며 과거 작업 장면이나 이전 파일과 혼동하지 않는다.
- 먼저 경순양함 01·구축함 01을 기준 사례로 구현·검증하고, 같은 절차를 나머지 함선에 적용한다. 특정 무장 이름마다 조건문을 계속 추가하는 방식 대신 구조·무장 설정과 공통 판정기를 분리한다.
- 문서 작성, 구현, 형상 검증과 실행 검증 상태를 구분한다. 새 파일·검사 결과물은 사용자가 요청한 범위에서 생성한다. 불확실성은 추정·미검증으로 남기고 진행 가능한 작업을 계속하며, 불확실하다는 이유만으로 매 함선 뒤에 작업을 종료하지 않는다.

### 2. FBX 구조와 제어 정보 조사

- 대상 로더로 실제 FBX를 읽어 포탑·포신·고정포·포구의 수, 계층, 중립 자세, 단위와 실제 로컬 축을 확인한다. Blender와 대상 로더의 결과를 동일하다고 가정하지 않는다.
- 무장별 피벗 역할, 장착 방향, 바깥 방향·부호, 기본 범위·사용자 예외, 그룹 동기화와 동반 회전 부품을 대응시킨다. 필요한 구조 정보가 없으면 형상을 확인하고 근거를 기록한다.
- 포구 표식의 좌표만 검사하지 않고 실제 포신 메시와 부속의 움직임도 검사한다. 축·부품 연결 오류는 제한 로직으로 숨기지 않고 리깅 오류로 분류한다.

**통과 기준:** 각 입력이 어떤 부품을 어느 축으로 움직이는지, 각 포구가 어느 무장에 속하는지 설명하고 대상 로더에서 재현할 수 있다.

### 3. 충돌 형상과 정상 결합 관계 준비

- 고정 구조와 가동 부품을 나누고, 검사에 포함할 원본 형상 또는 단순 충돌 형상을 준비한다. 판넬·큐브·실린더 등 회전하는 부속도 포함한다.
- 접합 영역과 허용 부품 쌍을 실제 형상에서 지정·검수한다. 자동 후보 추정은 가능하지만 최초 겹침이나 근접성만으로 정상 결합을 확정하지 않는다.
- 단순 충돌 형상이 정상 회전을 과도하게 막거나 얇은 부속의 관통을 놓치는지 원본과 비교한다. 단위와 형상 크기에 맞는 오차 여유를 정하고 근거를 기록한다.
- 기존 스케일·열린 메시·분리 메시 등의 경고가 판정에 미치는 영향을 확인한다. 경고만으로 형상을 임의 삭제하거나 모두 정상 처리하지 않는다.

**통과 기준:** 정상 삽입은 허용하고, 같은 부품이 접합 영역 밖 외장을 관통하거나 다른 부품에 닿는 경우는 구별해 검출한다.

### 4. 기본 규칙과 고정 형상 사전 계산

- 기본 범위·예외를 적용한 후보 영역에서 포탑·포신의 자세 조합을 검사한다. 연장포의 독립 제어·구체형 포탑의 동반 회전 등 실제 자유도를 반영한다.
- 안전·차단 영역, 경계, 사용한 형상과 각도 간격, 정밀 검사 기준·오차를 기록한다. 차단 영역이 복잡하면 단일 최소·최대 각도로 무리하게 합치지 않는다.
- 형상·계층·피벗·스케일·접합 예외·판정 규칙이 바뀌면 사전 계산과 캐시를 무효화한다. 생성 결과가 어떤 입력에서 계산됐는지 추적할 수 있게 한다.
- 사전 계산만으로 실행 안전성을 확정하지 않고 런타임 경로 검사에 연결한다.

**통과 기준:** 경순양함 01 함교 방향과 구축함 01 Hull 조건부 범위를 재현하고, 기존 설정과 차이가 생기면 근거를 확인한다.

### 5. 런타임 이동과 발사 판정 구현

- 같은 시점의 현재 자세와 제안된 다음 자세로 이동 경로를 검사하고 승인된 자세만 반영한다. 동시 이동과 동기화 그룹을 일관되게 처리한다.
- 승인 자세에서 포구별 발사 경로를 별도로 검사한다. 회전 차단과 발사 차단을 각각 반환하고, 차단 부품·원인과 안전 위치를 추적 가능하게 한다.
- 갱신 순서는 **입력·조준 → 이동 후보 검사 → 승인 자세 반영 → 월드 변환 갱신 → 발사 검사 → 허용 포구 생성**으로 유지한다.
- 한 무장이 이동하거나 공격 형태·크기가 바뀌면 관련 이동·발사 검사 결과를 갱신한다. 오래된 안전 결과를 그대로 재사용하지 않는다.

### 6. 웹 테스트와 회귀 검증

- 경순양함 01·구축함 01의 기존 범위·부호·조건부 제한·고정포·동기화가 보존되는지 확인한다.
- 중립·중간·경계, 여러 축의 조합, 도착은 안전하나 중간이 막힌 이동, ±180° 경계 통과, 큰 시간 간격을 검사한다.
- 정상 접합부 삽입, 자기 포탑 외장 관통, 다른 포탑·포신과의 간섭, 동시에 가까워지는 무장을 각각 검사한다.
- 포구가 막힌 고정포, 연장포 일부만 막힌 경우, 폭이 있는 공격, 지속 빔과 발사 후 이동 구조물의 경로 차단을 검사한다.
- 테스트 화면에서 실제 회전 부품·검사 형상·접합 영역·발사 경로와 차단 원인을 확인할 수 있게 한다. 최종 게임 화면에 검사 구현 세부사항을 그대로 노출할 필요는 없다.
- 수학적·자동 검사와 실제 웹 화면 확인을 구분한다. 로더나 표식 검사만 통과한 결과를 브라우저에서 실제 형상 동작까지 확인했다고 보고하지 않는다. 사용자에게 오류 여부를 재검수시키기 전에 현재 파일과 실제 제어 경로를 직접 재현한다.

**통과 기준:** 각 차단이 재현 가능하고, 정상 결합과 안전한 움직임·발사를 불필요하게 막지 않으며, 수행한 검사 범위와 미검증 범위를 명시한다.

### 7. 성능 측정과 최적화

정확성 기준을 통과한 뒤 함선·가동 무장 수, 동시 회전·발사 수와 시간 간격을 고정해 검사 시간·후보 수·캐시 적중과 오차를 측정한다.

- 공간 분할과 경계 상자로 충돌 후보를 먼저 줄이고 필요한 쌍만 정밀 검사한다.
- 고정 형상 사전 계산과 결과 캐시를 사용하되, 가동 구조와 최신 발사 경로 검사를 생략하지 않는다.
- 원본과 비교 검증한 단순 충돌 형상을 사용하고, 경계 근처에서 검사 정밀도를 높인다.
- 멀리 떨어진 무장의 관련 없는 변경은 재계산을 줄일 수 있다. 관련 부품의 변경을 누락하거나 단순히 검사 주기를 늦춰 관통을 허용하지 않는다.
- 최적화 전후에 같은 회귀 사례를 비교한다. 비용과 안전 오차의 허용 기준은 측정 후 명시하며, 근거 없는 성능 수치를 약속하지 않는다.

### 8. 결과 보고와 Blender 사용 시점

함선별 기본 규칙·예외·접합 영역, 사전 계산 입력과 검사 정밀도, 검증 사례·차단 원인, 남은 경고와 미검증 범위를 보고한다. 사용자 검수용 초안과 검사 통과 결과를 구분한다.

Blender 상시 실행은 필요하지 않다. FBX 조사, 사전 계산과 런타임 제어 구현은 별도 도구와 웹 테스트로 수행할 수 있다. 접합부 시각 확인, 피벗·부모 관계 수정, 검사 형상 조정이 필요할 때 Blender를 사용한다. 리깅을 수정했다면 FBX 재가져오기와 대상 로더 검증, 관련 사전 계산·회귀 검사를 다시 수행한다.

## 현재 구현 상태

2026-11-23 기준 [리깅 테스트](../../rigging-test/README.md)에 10종 FBX 선택, 공통 제어, 기본 범위·조건부 제한, 고정 형상 자세 표본 분석, 가동 부품의 이동 구간 검사, 포구별 직선 구형 공격 경로·비행 검사와 접합 후보 검수 UI를 구현했다. 기존 경순01·구축함01 예외는 [공통 제어 모듈](../../rigging-test/rig-control.js)에 유지한다. 일반 포신 범위는 0~45°이며 바깥 방향 부호의 자동 추정은 검수 대상이다.

[10종 분석 결과](../../rigging-test/rig-analysis.md)와 JSON은 FBX·코드 해시를 포함한다. 확인된 두 기준 함선은 중립 접촉을 기준으로 하며, 나머지 8종은 분석 해시 일치 시 추정 접합 후보를 검수용 초안으로 기본 적용한다. 후보 적용은 개별 승인이나 안전 확정과 구분한다. 불일치 모델의 엄격 모드는 정상 접합까지 차단할 수 있다. 승인 상태는 현재 로드에서만 유지된다.

1° 이동 표본, 열린 메시의 내부 판정, 순수 동일 평면 중첩, 검사 형상과 접합 영역의 최종 검수, 지속 빔·곡선 탄도 및 대규모 함대 성능은 추가 작업이 필요하다. 따라서 구현된 검사 초안과 10종 분석을 안전 각도의 최종 확정이나 전 구간 무관통 보증으로 취급하지 않는다. 세부 실행 방법과 한계는 리깅 테스트 문서를 따른다.
