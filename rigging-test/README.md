# 함선 리깅·이동·발사 검사 도구

[프로젝트](../README.md) · [정책](../docs/ship-rigging-policy.md) · [10종 분석 결과](rig-analysis.md)

작업 폴더의 리깅 FBX 10종을 읽어 공통 제어와 형상 검사를 수행한다. 모델 파일은 변경하지 않는다. FBX와 텍스처는 프로젝트의 자산 라이선스 방침에 따라 별도로 관리하며, 분석 JSON에는 모델 메시를 복제하지 않는다.

## 사용

상위 작업 폴더를 제공하는 로컬 서버에서 `Fleet Doctrine/rigging-test/`를 연다. 함선 선택 목록에서 10종을 선택하거나 FBX를 직접 불러올 수 있다.

- 기본 모드는 미승인 접합부의 겹침도 차단한다. 사용자가 확인한 경순01·구축함01의 전체 0° 접합은 해당 FBX 해시가 일치할 때 기준으로 기록한다. 회전 중에는 확인된 부품 쌍과 그 접합점으로 측정한 제한 영역 안의 접촉만 후보로 허용한다. 이 휴리스틱은 다른 각도 전체의 무관통 보증이 아니다. 다른 함선과 그 밖의 부품 쌍에는 적용하지 않는다. 발사 경로는 중립에서도 별도 검사한다.
- **추정 접합부 허용**은 피벗 주변의 제한된 구 영역과 해당 부품 쌍만 허용하는 검수용 초안이다. FBX와 코드의 분석 해시가 일치하는 나머지 8종에는 이 초안이 기본 적용된다. 안전이 확정된 모드가 아니다. 분석 자료가 없거나 일치하지 않으면 자동 적용하지 않는다.
- 접합부 후보 검수에서 부품 쌍을 선택하고 분홍 구를 표시한다. 실제 접합부를 덮되 다른 외장 관통까지 숨기지 않는지 확인한 경우에만 개별 승인한다. 승인은 현재 로드에서만 유지되며 사전 계산 자료의 사용을 중단한다.
- 이동과 발사는 별도로 차단하며 상태 표시에서 원인 부품을 확인한다. 연장포의 발사 판정은 포구별이다. 기본 공격은 반경 0.075, 속도 12, 수명 3초인 직선 구형 투사체다. 포구의 실제 출구부터 중심선을 검사하고, 구의 중심을 반경만큼 앞으로 생성해 구의 후면이 출구에 접하게 한다. 비행 중에도 구의 이동 구간을 검사한다.
- 전체 초기화도 현재 자세부터의 이동 검사를 거친다. 차단 구간 너머로 순간 이동하지 않는다.

## 구현과 사전 계산

`rig-control.js`는 경순01·구축함01의 기존 범위·조건부 제한·부호를 유지하고 중립 쿼터니언 기준으로 회전한다. 일반 무장은 포신 0~45°를 사용하며, 장착 위치와 1° 시험 회전으로 바깥 방향의 부호를 추정한다. 이 추정은 분석 자료에 기록되며 검수가 필요하다. 수직 장착 등의 기존 구조별 설정도 유지한다.

`rig-safety.js`는 실제 삼각형의 BVH, 부품 경계 상자와 연결 성분별 내부 검사 표본을 사용한다. 같은 강체의 부품끼리는 검사하지 않는다. 접합부 예외는 피벗·부품 쌍·구 영역으로 제한한다. 이동 후보는 같은 시점에 함께 적용해 동기화 그룹과 다른 가동 무장의 간섭을 검사한다. 조건부 범위의 경계에서는 필요한 중간 자세를 추가한다.

`analyze-rigs.mjs`는 동일 로더와 판정기로 10종을 조사한다. 고정 형상에 대해 포탑 30° 간격 및 중립·경계, 포신 중립·중간·경계의 총 1,950개 조합을 검사했다. 엄격 모드와 추정 접합 허용 결과를 구분한다. 동적 무장은 다른 무장이 중립인 상태의 구조 조사 및 별도 런타임 검사 대상이다. 모든 무장의 전 자세 조합을 사전 인증한 자료가 아니다.

웹은 FBX SHA-256과 두 제어·검사 모듈의 SHA-256이 모두 일치할 때만 사전 결과를 재사용한다. 설정과 각도가 정확히 일치하는 고정 형상 표본만 조회하고, 표본 사이를 안전 구간으로 보간하지 않는다. 그 외 자세와 가동 부품은 실제 검사한다. 고정 부품 변환이나 접합 승인 상태가 바뀌면 사전 자료 사용을 중단한다. 형상·피벗·예외를 바꿨다면 재분석이 필요하다.

## 실행과 검증

Node.js와 네트워크 접근이 필요하다. 브라우저와 헤드리스 분석은 동일한 Three.js 0.170.0 및 three-mesh-bvh 0.9.1을 사용한다. 분석 스크립트는 고정 버전의 모듈을 메모리로 읽으며 자산을 외부에 전송하지 않는다.

```powershell
node rigging-test/analyze-rigs.mjs
node rigging-test/rig-safety.test.mjs
npm exec --yes --package=playwright -- node rigging-test/browser-smoke.mjs
```

마지막 명령은 로컬 서버와 설치된 Microsoft Edge가 필요하다. npm이 테스트 도구를 캐시에 설치할 수 있다. 10종의 로딩·분석 해시 일치·이동·발사 이벤트·검수 모드를 검사하며, 모든 자세의 시각적 무관통 검수와는 구분한다.

단위 회귀 검사는 정상 출구와 안쪽 발사, 굵은 공격의 스침, 내부 생성, 끝점은 안전하지만 중간이 막힌 회전, 접합 허용 범위, 동시 회전 충돌, 구축함01 조건부 범위 경계 및 경순01 기본값을 포함한다.

## 남은 검증과 한계

- 접합 영역은 현재 전부 **후보**다. 중립 자세의 겹침만으로 정상 접합으로 확정하지 않았다. 개별 형상 검수와 승인 기록의 영속화가 필요하다.
- 1° 이하로 나눠 검사하는 이동은 연속 충돌 검사의 대체 인증이 아니다. 매우 얇은 구조나 고속 회전에서 표본 사이의 간섭을 놓칠 수 있다. 허용 해상도 예산을 넘으면 이동을 차단한다.
- 열린 메시와 비다양체가 있는 메시 전체에는 내부 포함 판정을 확정하지 않는다. 표면 교차 검사는 수행하지만 완전히 내부에 들어간 물체를 놓칠 수 있다. 10종 모두 해당 형상이 있어 닫힌 검사 형상 준비 또는 연결 성분별 보완이 필요하다.
- 순수한 접촉·동일 평면의 면은 관통으로 확정하지 않는다. 얇은 판의 동일 평면 중첩도 추가 검수 대상이다.
- 비균일 스케일은 공격 반경을 보수적으로 확대하므로 과도하게 차단할 수 있다. 곡선 탄도·지속 빔의 수명 제어는 현재 UI에 구현하지 않았다. 해당 공격을 추가할 때 실제 궤적·폭·시간별 검사를 연결해야 한다.
- 분석 소요 시간은 해당 실행의 관측값이다. 대규모 함대에서의 프레임 예산 충족은 아직 측정하지 않았다.

위 한계 때문에 현재 결과는 **10종을 대상으로 동작하는 검사·검수 초안**이며 전 함선의 안전 각도 확정 결과가 아니다.
