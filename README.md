# Fleet Doctrine

완전한 3차원 우주 전장에서 함대를 편성하고, 이동 명령과 적 조우 시 교전 대응을 정한 뒤 자동 전투의 결과를 관찰·수정하는 게임 프로젝트입니다. 컴퓨터그래픽스 Project 3를 위해 기획하고 있습니다.

## 기획 개요

플레이어는 함선을 함대로 편성하고 전투 준비 단계에서 목적지, 명령, 대형의 크기와 함선 순서를 정합니다. 자동 전투 중에는 함대가 명령에 따라 움직이고 각 함선이 무장을 운용합니다. 일정 시간 뒤 또는 전투 결과에 따라 상황을 살펴보고 명령을 수정하는 흐름을 목표로 합니다. 개별 함선이나 포탑을 직접 실시간 조작하는 게임은 아닙니다.

기획의 플레이 흐름은 **함대 편성 → 전투 준비 → 제한 시간 자동 전투 → 결과 확인 및 명령 수정**입니다. 화력 차이는 임의의 대형 보너스보다 무장의 사거리·방향, 배치, 거리와 접근 방향 등에서 발생하도록 설계합니다.

| 플레이어의 선택 | 기획된 항목 |
|---|---|
| 이동 명령 | 목적지 이동, 경로 순찰 |
| 교전 대응 | 명령 유지 사격, 거리 유지 교전, 진형 관통, 분할 포위, 거점 방어 |
| 대형 | 이동 명령과 교전 대응에 맞는 대형의 크기와 함선 순서 조정 |

상세 규칙과 확정·권장·미결 구분은 [기획 및 구현 기준 명세서](fleet_auto_battle_design_spec.md)를 따릅니다.

## 현재 상태

| 구성 | 확인된 상태 |
|---|---|
| 웹 함선 리깅 테스트 | `rigging-test/`는 FBX 함선, 포탑·포신 회전, 포구 발사 표시와 엔진 표시를 점검하는 도구입니다. 실제 자동 전투 게임 화면은 아닙니다. |
| 함선 리깅 | 경순양함 01의 포탑·포신·포구·엔진 기준점을 작업했습니다. 회전 범위는 테스트용이며 모델·자세별 형상 간섭을 추가 검증해야 합니다. |
| Python 코드 | `python/`은 캐릭터·강아지와 마을을 사용하는 스타터 데모 코드입니다. 함대 오토배틀 구현으로 간주하지 않습니다. |
| 함대 게임 | 명령·대형·표적 배분·자동 전투는 기획 문서의 목표입니다. 현재 확인한 웹과 Python 진입점에서 완성된 게임으로 검증되지 않았습니다. |

## 웹 리깅 테스트 실행

Python 3와 브라우저가 필요하며, three.js를 CDN에서 불러오므로 네트워크 연결이 필요합니다. 이 저장소와 `ship assets` 폴더가 같은 상위 폴더에 있는 배치에서, **상위 폴더**를 작업 디렉터리로 열고 실행합니다.

```powershell
python -m http.server 8000
```

브라우저에서 [함선 리깅 테스트](http://127.0.0.1:8000/Fleet%20Doctrine/rigging-test/)를 엽니다. 포트가 이미 사용 중이면 기존 서버의 루트가 해당 상위 폴더인지 확인합니다. 현재 기본 모델 경로는 상위 폴더의 `ship assets/rigged/Light_cruiser_01_rigged.fbx`입니다. 해당 파일이 없으면 페이지에서 FBX 하나와 필요한 텍스처를 직접 선택할 수 있습니다.

- `무장 선택`에서 탐지된 포탑이나 고정 포를 선택하고 포탑·포신 회전과 발사 표시를 확인합니다.
- `회전 축과 범위 설정`은 선택한 무장에 적용됩니다. 화면에서 바꾼 설정은 페이지를 유지하는 동안만 유효합니다.
- 자동 탐색은 피벗·기준점의 이름과 부모 계층을 사용합니다. 리깅되지 않은 모델은 보이더라도 무장 조작 항목이 없을 수 있습니다.
- 각도 제한은 Blender가 아니라 웹 스크립트에서 관리합니다. 현재 알 수 없는 포탑의 임시 포신 범위는 -45~45°이므로 모델별 설정을 확인해야 합니다.

리깅 구조, 이름 규칙, 포신 피벗, 각도 제어 및 검증 절차는 [함선 리깅 및 회전 제어 절차](docs/ship-rigging-policy.md)를 따릅니다.

### 함선 모델과 라이선스

현재 사용 중인 함선은 CraftPix의 무료 에셋 [Battle SpaceShip Free 3D Low Poly Models](https://craftpix.net/freebies/battle-spaceship-free-3d-low-poly-models/)입니다. 무료 다운로드 에셋이지만 자유 재배포를 허용하는 공개 라이선스나 CC0로 간주하지 않으며, [CraftPix 파일 라이선스](https://craftpix.net/file-licenses/)의 무료 에셋 조건을 따릅니다. 원본에 포함된 `License.txt`도 해당 라이선스 페이지를 안내합니다.

**저장소에는 이 함선 에셋의 원본과 이를 수정한 리깅 파일을 올리지 않습니다.** 프로젝트에서 사용하는 리깅본은 CraftPix 원본을 바탕으로 별도로 수정한 작업 파일입니다. CraftPix에서 원본을 내려받는 것만으로는 이 프로젝트의 포탑·포신 리깅과 기준점을 얻을 수 없습니다. CraftPix는 무료 에셋의 프로젝트 사용과 수정을 허용하지만, 다른 사람이 에셋 자체를 사용할 수 있도록 원본이나 수정본을 재배포하는 데 제한을 둡니다. 이 저장소의 비공개 방침은 이를 고려한 프로젝트 운영 방침이며, 게임 완성물의 모든 배포가 금지된다는 뜻은 아닙니다.

현재 함선 원본 및 리깅 파일은 저장소 밖 상위 폴더의 `ship assets/`에 있습니다. GitHub에서 저장소만 내려받으면 이 프로젝트의 리깅 모델이 포함되지 않으므로 기본 모델을 이용한 리깅 테스트를 바로 실행할 수 없습니다. [ASSETS.md](ASSETS.md)는 스타터 팩 에셋 목록이며 CraftPix 함선에 적용되는 라이선스 목록이 아닙니다.

## 개발 방향

기획 명세서는 전투 한 판이 완결되는 수직 슬라이스를 우선하고, 이후 교전 대응을 단계적으로 추가할 것을 권장합니다. 전투 규칙과 과제 요구사항의 구현 여부는 기획 채택, 코드 구현, 실제 검증을 구분해 관리합니다. 리깅 테스트에서 모델이 움직이는 것만으로 함대 AI나 자동 전투 기능이 완성된 것은 아닙니다.
