# Fleet Doctrine

3차원 우주 전장에서 함대를 편성하고 이동 명령을 내린 뒤 자동 전투를 관찰하는 컴퓨터그래픽스 프로젝트입니다. 현재 웹 프로토타입에서 함대 이동과 시험 전투를 실행할 수 있습니다.

## 게임 실행

브라우저와 Node.js 또는 uv 및 Python 3.12가 필요합니다. three.js 등 라이브러리를 CDN에서 불러오므로 인터넷 연결이 필요합니다. 저장소와 별도 함선 에셋은 다음과 같이 같은 상위 폴더에 있어야 합니다.

```text
텀프3/
├─ Fleet Doctrine/                 # 이 저장소
└─ ship assets/rigged/
   ├─ Light_cruiser_01_rigged.fbx
   └─ Texture/
```

Windows에서는 저장소의 [게임 실행.cmd](게임%20실행.cmd)를 더블클릭하면 로컬 서버가 시작되고 기본 브라우저에서 게임이 열립니다. 서버 창은 게임을 하는 동안 열어 두고, 종료하려면 해당 창을 닫습니다. 8001 포트가 이미 사용 중이면 실행 창의 안내를 확인하세요. Node.js가 있으면 Node.js로 실행하며, Node.js가 없으면 uv와 Python 3.12를 사용합니다.

직접 실행하려면 PowerShell에서 **저장소의 상위 폴더**를 연 뒤 다음 명령을 실행하고 창을 열어 둡니다. `uv`가 설치되어 있어야 하며, 해당 포트에서 이미 올바른 서버가 실행 중이면 다시 실행할 필요가 없습니다.

```powershell
uv run --no-project --python 3.12 python -m http.server 8001 --bind 127.0.0.1
```

- [게임 프로토타입 열기](http://127.0.0.1:8001/Fleet%20Doctrine/web/)
- [함선 리깅 테스트 열기](http://127.0.0.1:8001/Fleet%20Doctrine/rigging-test/)

페이지가 열리지 않거나 모델이 나오지 않으면 서버가 실행 중인지, 서버의 작업 폴더가 위의 `텀프3`처럼 저장소와 `ship assets`를 모두 포함하는지 확인합니다. 다른 프로그램이 8001 포트를 사용한다면 빈 포트로 바꾸고 주소의 포트도 함께 바꿉니다. 연결이 거부되면 서버가 종료된 상태이므로 위 명령을 다시 실행합니다. 게임은 제공된 FBX의 리깅 분석 해시가 일치하지 않으면 안전을 위해 사격을 보류합니다.

## 조작 방법

1. 왼쪽 함대 목록, 전장 또는 미니맵에서 아군 함대를 선택합니다. 왼쪽에서 **이동 → 교전 → 간격**을 조합합니다. 좁은 화면에서는 상단 **함대**로 작업창을 엽니다.
2. 목적지는 **위치 변경**, 순찰은 **경로 편집**에서 XZ 수평 위치를 클릭한 뒤 높이를 선택합니다. 입력 중 WASD·드래그로 화면 이동, 휠로 확대·축소, Esc로 취소합니다. 순찰은 서로 다른 두 점 이상을 저장해야 적용됩니다. 거점 방어의 거점 지정도 같은 입력을 사용합니다.
3. 함선 카드를 클릭하면 정보를 봅니다. 카드를 드래그하거나 선택 후 **배치 변경**으로 슬롯을 교환합니다. 다른 함대로 드래그하거나 **함대 이동** 후 대상 함대 항목을 선택해 옮깁니다. +로 빈 함대를 만들 수 있으며 마지막 함선이 옮겨진 기존 빈 함대는 삭제됩니다.
4. 상단 **증원**에서 점수로 구매하고 대상 함대 또는 새 함대에 배정합니다. 구매는 승리 점수를 소비하며, 미배정 함선은 투입되지 않습니다. 상단의 **전투 시작 / 전투 재개 / 다음 전투**로 배정된 함선의 투입을 시도하고 전투를 진행합니다. **전투 일시정지** 후 명령을 수정할 수 있습니다.
5. 카메라는 WASD·R/F 이동, 드래그 회전, 휠 확대입니다. 전장 오른쪽 위 **카메라**의 평면 선택과 오른쪽 아래 미니맵의 평면 선택은 독립적입니다. **정보**에서 개발용 줌과 좌표를 확인하고 경로·목표 표시를 켜고 끕니다.

## 현재 구현 상태

- 아군은 파란 텍스처를 사용하며 시작 함대는 진영별로 평행하게 전장 중앙선을 바라봅니다. 기본 편성은 양측 각각 4척 함대 두 개이며, 3차원 이동·대형 유지와 함선 근접 완화가 동작합니다. 현재 함선 체력·실드와 포구 피해량은 data/balance의 CSV에서 읽습니다. 근접 완화는 완전한 무충돌을 보장하지 않습니다.
- 전술은 **단종진·일자진·어린진·원형진** 네 가지입니다. 단종진은 종렬 이동과 경로 우회, 일자진은 적 방향 전개와 대치, 어린진은 진형 준비 후 돌파, 원형진은 조우 시 지정 거점 구축을 수행합니다. 분할 포위와 돌파 후 재관통은 폐기됐습니다.
- 양측 함선이 표적을 선택하고 포탑·포신을 움직여 자동 사격합니다. 함대 단위로 표적 후보를 공유하고 공간 셀로 주변 함선과 사선 후보를 찾습니다.
- 시험 전투는 포구 레이의 최초 접촉을 **발사 틱에 즉시 판정**합니다. 자기 함선·아군이 앞을 가로막으면 발사를 보류하며, 구형 근사 피격 범위와 짧은 선형 효과를 사용합니다. 탄이 비행하는 동안 차폐가 바뀌는 상황은 아직 반영하지 않습니다.
- 생존 함선으로 9개 구역을 집계하며 현재 점수로 함선을 구매하거나 승리 목표인 1,000점을 모을 수 있습니다. 기본 적 AI도 같은 가격으로 구매하고 시작 면에 투입합니다. 구매 가격과 AI 정책은 시험값입니다. 네 전술의 대표 계산 시나리오는 검증했지만 실제 교전에서 어린진·원형진의 장시간 전개와 64척 부하는 추가 검증 및 개선이 필요합니다.
- 포탑 회전 간섭은 AABB 근사, 자기 함선 포구 안전은 메시 검사를 사용합니다. 피격 형상의 오차와 모델별 회전·사선은 추가 시각 검수가 필요합니다. 이동·무장·득점 수치는 시험용입니다.

전투 기반은 [2단계 상세 재설계](docs/design/phase2-data-oriented-combat-design.md)를, 현재 전술은 [조우 정책 재설계](docs/design/Fleet-Doctrine-Encounter-Policy-Redesign.md)를 따릅니다. 이전 전술과 단계별 구현 이력은 [구현 계획](docs/design/implementation-plan.md)에 보존합니다. 교전 성능 측정과 비교 한계는 [이슈 #1 조사 기록](docs/investigations/issue-001-combat-performance.md)을 참고합니다.

## 개발 검증

밸런스 데이터 검증은 `node web/balance.test.mjs`, 게임 규칙 회귀는 `node web/simulation.test.mjs`, 광선 주기는 `node web/weapon-combat.test.mjs`, 효과 수명은 `node web/effects.test.mjs`, 리깅 안전 검증은 `node rigging-test/rig-safety.test.mjs`로 실행합니다. 게임 규칙·리깅 검증은 고정된 three.js 모듈을 인터넷에서 불러옵니다. `node web/combat-benchmark.mjs`는 실제 렌더링을 제외한 고정 입력에서 A0와 A1을 비교합니다. 실제 게임에서 주소에 `?profile=1`을 붙인 뒤 정보 메뉴를 열면 전투 구간 프레임 간격의 p50/p95/p99, 경과시간 상한으로 제외된 시간, 고정 틱 상한으로 버린 시간과 처리별 누적 계측값을 볼 수 있습니다. 프레임 분포는 최근 최대 10,000개 표본을 60프레임마다 갱신하며, 렌더 제출 시간은 GPU 완료 시간이 아닙니다. 계측은 새로고침 전까지 전투 구간 사이에서 누적됩니다.

개발용 64척 부하 장면은 게임 주소 뒤에 `?profile=1&stress=64`를 붙여 실행합니다. 양 진영 각 32척의 일자진을 실제 모델과 무장으로 불러오며, 일반 게임 시작 편성에는 영향을 주지 않습니다.

`?profile=1`의 정보창은 선택된 어린진의 준비도·정렬각·슬롯 오차·경과시간과 원형진의 거점 거리·정체시간·슬롯 오차도 표시합니다. 이는 지연 원인 분석을 위한 관측값이며 충돌 원인을 자동 판정하지 않습니다.

선체 전방 중심 이동과 단종진의 차단 시 제동·대기·재개는 `?maneuver=experimental`에서 시험 중입니다. 기본 게임에는 기존 단종진 우회가 남아 있습니다. 대표 전술 조합과 실제 64척 화면을 확인했지만, 선회 경로·제동 예측과 64척 단종진의 검증이 남아 있어 기본 전환을 보류했습니다. 구현 범위와 결과는 [조우 정책 문서](docs/design/Fleet-Doctrine-Encounter-Policy-Redesign.md#124-함대함선-이동-제어-통합-상세-설계--구현-전)에 기록합니다.

## 함선 리깅 테스트

리깅 테스트는 게임과 별도로 FBX의 포탑·포신 회전, 포구와 엔진 기준점을 살펴보는 도구입니다. 기본 모델을 불러오거나 테스트 화면에서 FBX와 텍스처를 직접 선택할 수 있습니다. 무장 선택과 회전 축·범위 설정은 테스트 화면에서 조작하며, 설정 변경은 페이지를 유지하는 동안만 유효합니다. 리깅되지 않은 모델에는 무장 조작 항목이 없을 수 있습니다.

이름 규칙, 각도 제어, 검증 절차는 [함선 리깅 정책](docs/policies/ship-rigging.md)과 [리깅 테스트 안내](rigging-test/README.md)를 따릅니다.

### 함선 모델과 라이선스

현재 사용 중인 함선은 CraftPix의 무료 에셋 [Battle SpaceShip Free 3D Low Poly Models](https://craftpix.net/freebies/battle-spaceship-free-3d-low-poly-models/)입니다. 무료 다운로드 에셋이지만 자유 재배포를 허용하는 공개 라이선스나 CC0로 간주하지 않으며, [CraftPix 파일 라이선스](https://craftpix.net/file-licenses/)의 무료 에셋 조건을 따릅니다. 원본에 포함된 `License.txt`도 해당 라이선스 페이지를 안내합니다.

**저장소에는 이 함선 에셋의 원본과 이를 수정한 리깅 파일을 올리지 않습니다.** 프로젝트에서 사용하는 리깅본은 CraftPix 원본을 바탕으로 별도로 수정한 작업 파일입니다. CraftPix에서 원본을 내려받는 것만으로는 이 프로젝트의 포탑·포신 리깅과 기준점을 얻을 수 없습니다. CraftPix는 무료 에셋의 프로젝트 사용과 수정을 허용하지만, 다른 사람이 에셋 자체를 사용할 수 있도록 원본이나 수정본을 재배포하는 데 제한을 둡니다. 이 저장소의 비공개 방침은 이를 고려한 프로젝트 운영 방침이며, 게임 완성물의 모든 배포가 금지된다는 뜻은 아닙니다.

현재 함선 원본 및 리깅 파일은 저장소 밖 상위 폴더의 `ship assets/`에 있습니다. GitHub에서 저장소만 내려받으면 이 프로젝트의 리깅 모델이 포함되지 않으므로 기본 모델을 이용한 게임 및 리깅 테스트를 바로 실행할 수 없습니다. [ASSETS.md](ASSETS.md)는 스타터 팩 에셋 목록이며 CraftPix 함선에 적용되는 라이선스 목록이 아닙니다.
